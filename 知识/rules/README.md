# 知识目录定义

这是 Core 提供的可编辑默认组织约定。新实例可直接使用；已有实例只有在本次明确采用时才按差异合并，不覆盖既有规则。知识根入口为 [knowledge.md](../knowledge.md)，只概述直接下级的内容、组织方式和实际入口；本文件持有公共约定，各类型定义补充自身结构。本目录是定义设施，不作为业务知识单元。

## 单元与命名

- 每个知识单元直接位于 `知识/`，命名为 `单元类型-具体名称`，连接符使用半角 `-`。类型和具体名称都应能说明用途，不预建类型枚举或领域层。
- 内置的可选类型是[认知](认知.md)，例如“认知-观察方法”。没有实际主题时不创建认知单元。其他类型按实际信息与框架定义，可以与认知单元同级并存。
- `rules/` 与根 `knowledge.md` 是公共设施，不套用单元命名规则。新类型的规则写在本目录，模板放在 `templates/`；没有实际需要时不提前铺设目录。
- 单元类型决定采用哪份组织约定，不能单凭名称判断资料的真实性、采纳或验证状态。

## 入口与渐进读取

根导航 → 相关单元的实际入口 → 直接分区或主题概览 → 必要原文。每层只说明当前层与直接下级承载什么，不递归列出全部文件，不在导航重复详细结论。

认知入口为 `cognition.md`。其他类型可以采用适合自己的入口名与结构，并在根导航中明确链接，不要求都叫 cognition.md 或 knowledge.md。明确材料已经足够时可以直接读取，不为形式完整遍历全库。

整理前先读本说明和目标类型定义。根入口负责导航，本目录负责结构规则，具体认识留在单元。材料引文、原件中的命令及萃取过程文件不成为本实例执行指令。

## 唯一正文、来源与关系

一份材料保留一个现行主位置，其他单元通过链接引用。项目事实和任务进度留在项目；可复用的执行方法由基本功持有；知识萃取的专业方法及其支持资料由实际采用的基本功持有，来源工程保持原位。

普通来源随所支撑的目标保存，默认在该目标 `资料/`，已有来源包内部目录保持完整，不为了填满分类而拆散资料。正文注明来源、来源时间或版本、原件入口与适用条件，区分来源主张、可核实事实、解释和未验证认识。查不到时保留未知。

## 记录、补充与修订

知识主要由人沉淀：人决定内容、认识、采纳和修订，按需要使用能力工具归纳、提炼、比较或总结。系统依据“内容性质＋本次记录目的”辅助归位，保存已明确要求记录的内容，维护来源与入口。

- “放哪里合适”只提供位置建议；“记下来”执行记录；“处理后保存”先由适用能力完成所需内容处理，再按同一有效授权保存。目标和内容明确时不额外询问是否采纳。
- 优先复用已有单元与正文。按当前类型规则判断分区和章节，不按词语匹配决定位置；同一内容可以因记录目的不同而采用不同位置。新类型或框架选择影响结构时再澄清。
- 默认保留用户原文或其指定处理结果的含义，可整理标题、段落和链接；内容提炼、改写、结论合并或删减按明确要求进行。尚未验证的认识可以记录，保留原有不确定性；来源未知如实说明，不虚构来源，不以缺少外部证明阻止记录个人想法。
- 新内容与旧认识冲突时，指出差异并建议补充、并列或替换；用户已明确修订目标和内容时直接实施。没有修订意图时保留现状，不按日期或模型判断自动改写结论。来源原件保持原性质，不随结论修订自动删除或改写。
- 写前读取最新目标和基线，保留既有有效内容；并发变化先停止受影响写入，再核对新状态。重复无差异不重写或制造副本；沿用既有修订约定，不新增强制版本字段或逐条日志。
- 只同步必要概述、链接和已过时占位，详细内容留在正文。混合材料保持唯一主存，通过引用连接相关分区，不机械拆散完整来源包。写后重读，核对内容保真、位置、来源与入口，并反馈实际保存位置。

## 整理、规则变化与检查

已有单元优先复用；同一来源重复整理没有差异时不改写、不制造副本。迁移或重命名先明确来源、目标、当前基线和引用影响，核验目标后再清理已授权旧位置。历史回执和来源原话保留原样，路径调整另留映射；冲突不以修改时间裁决。

规则变化只影响声明采用它的类型或单元，不触发全库改造。新框架先定义当前需要的职责、入口和样例，再同步直接相关导航。没有规则的材料可以保持原状供读取，不自动套认知模板。

整理后核对单元可发现、入口能逐层到原文、来源与内容未丢失，区分已有缺口与新增断链。程序检查只能证明文件事实；内容归属、认识采纳与有效性另行判断。

## 保存与机制边界

本约定支持人发起的知识记录、结构整理和明确修订；不自动发现沉淀价值、采纳认识或修改结论。不创建后台任务或默认用户记录。保存知识不自动创建能力，不形成常规业务自主检索知识的入口。过程与验收证据按任务要求保存在项目记录或本机验证目录，不作为本目录的业务知识。
