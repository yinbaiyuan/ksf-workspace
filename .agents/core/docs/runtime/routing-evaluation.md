# 自然语言三路由评测机制

用户原话 → 正常KSF入口的独立Agent → 实际材料读取和最小交付 → 可观察证据 → 程序断言与独立评审。这是对[routing](routing.md)的行为评测，不是另一个生产路由器。

## 什么算正确

项目归属及引用范围合理；能力符合明确要求/有效原安排/项目预设/全局工作流/搭档/通用Agent的顺序和适用性；知识回到相关原文，核对范围与冲突；后续动作真实采用方法和事实；目标与授权保持。无项目、无需业务知识、通用Agent与必要澄清均可为正确结果。角色名、文件名和检索数量不是效果证据。

每个案例明确用户原话、材料、必要前文、多轮消息和变更、可接受行为、禁止事项、最小产物与证据要求。评分答案不进入被测上下文；新会话不继承本次开发对话。真实项目与知识案例来自当前工作树副本，边界分支使用虚构样例。路径仅做物理重绑定，不给原话增加语义提示。被冻结的材料版本与模型配置随报告保留。

## 首版案例

公共Core只保存虚构样例与两条真实案例的绑定接口；真实原话、项目/知识路径及验收事实保存在当前实例私有的 `.agents/user-data/eval-routing.json`。该文件和评分预期不进入被测快照，正式贡献不携带私有案例。

| 组别 | 场景 |
| --- | --- |
| 项目P01–P04 | 无项目、真实隐含归属、多候选、指定不存在 |
| 能力A01–A04 | 预设优先、明确指定、全局替代、通用处理 |
| 知识K01–K04 | 输入充分、真实知识采用、无导航检索、来源冲突 |
| 缺口D01–D04 | 精确预设失效、必要依赖缺失、发现不完整、工具不可用 |
| 延续T01–T04 | 继续、纠正、旁问返回、暂停及独立恢复 |
| 协调C01–C04 | 来源歧义、新证据局部重判断、部分交付、外部结果未知 |

calibration：P01/P02/P03/A01/K02/D02。其中P02与K02使用实例副本，另四例虚构。core：24个场景，P02/P03/A01/A03/K02/D02/T04/C02各3次，共40例次；相同初始材料与用户输入，不混入同义表达变化。另保留8条未运行表达；本轮结果不代表它们已通过，后续采用时须显式版本化，不能把已用于调试的表达称为盲测。

核心表达包含口语、省略、间接指代和“晨光方按”等错别字。来源歧义夹具使用同ID的1.0.0与2.0.0，不能按最高版本猜来源。新证据夹具先有固件2.3下已实测的无需网关结论，再明确当前方案升级2.4且实测必须配G7，检查真正撤回受影响承诺并保留仍有效事实，避免用“未知变为已知”冒充前提被推翻。

套件1.1.0的A01保持原自然语言输入，但两条适用路线不再汇合到同一编辑方法：预设编辑读客户表达约定，以“客厅灯”描述；全局交付使用另一编辑和设备台账，按内部设备代号写说明。两者均只需交付一句话、不保存或发布；以必要资料、方法和产物共同核对选择，称呼本身或角色自报不能单独证明采用。不把同一输入的新夹具结果与1.0.1视为完全相同的实验。

## 证据与判分

程序记录工具事件、实际输出、session ID、用户消息、文件内容摘要及变化。原始事件保留于测试侧；过滤reasoning，不请求隐藏思维链。新会话与继续会话分开核对。发现、正文读取、实际采用及最终完成分别记录；不要求所有任务加载三种业务上下文，启动完整读取 USER/BOT/MEMORY 也不计为无关业务知识；只读场景三文件与检查点均不得写入。

程序断言核对完整记录、实际原文读取、允许文件变化和外部动作尝试。独立评审只收到已冻结验收条件、原文、工具证据、实际回答和产物；引用必须对应存在的事件。语义取舍由模型对照证据判断，仍有人工复核入口。缺证据、格式错误、分歧或装置异常不能算通过；确定违规始终为失败。

能力评审分开判断正文核对顺序、实际选择、异常说明，另由adoption维度判断方法使用。摘要可提前发现；已明确且需要项目预设时，根卡和逐项检查先于预设正文，适用预设不能因全局存在工作流而被跳过。已证明的顺序违规记失败，不能被正确文案抵消；读取全局正文仍不足以证明采用全局。如果实际选择的可观察证据不能区分，保留该子项无法判定，不反向猜测。预设失效后的替代须在采用前告知，中途消息满足说明义务，工具错误不算用户沟通。以成对评审挑战验证相同关键行为的判定一致性。

校准分程序自检、真实运行装置有效性、独立模型评分器挑战三层。制造的评分器负例不计真实Agent行为。明确的路由失败可以证明装置正确发现问题；它仍是不通过，不能通过改答案、生产规则或只展示成功案例消除。校准装置有效且结果无未决项后才扩量。

汇总显示全部计划、已运行、未运行、有效/基础设施/装置异常、五维度与总体结果；重复结果按场景保留，不把多次执行当作更多独立语义场景。宿主提供的用量原样记录；无法取得价格或实际后端身份时保持未知，不推算费用。一个模型的独立评审仍可能有共同偏差，不等于人工签收；正式改规则前应回看争议与失败原证据。

## 使用与后续

每个空白会话还检查固定runtime、ability-route的实际读取；仅需要新选能力的案例检查实际能力发现，不把按需路由改成简单问答或恢复有效安排也强制全库发现。答案正确但绕过KSF固定入口不视为机制通过；继续同一会话不要求机械重复启动。测试代码及私有案例也有独立摘要，校准后修改测试装置同样使原门槛失效。

执行入口、写入范围、校准门槛与输出契约见[eval CLI](../cli/eval.md)。普通[test](task-regression.md)继续验证确定性契约，不隐式调用模型。首版没有自动修规则、自动长期记录用户输入、桌面UI或跨宿主一致性验收。项目检查点只保存稳定状态和证据入口，完整原始日志留runtime-data。

Codex适配依据本机CLI帮助与[官方非交互运行说明](https://learn.chatgpt.com/docs/non-interactive-mode)核对；具体支持以本次本机实际运行记录为准。

新版CLI使用[原生权限配置](https://learn.chatgpt.com/docs/permissions)同时控制本地工具读写和网络，不与旧sandbox_mode混用。Codex宿主的认证与模型连接保持独立；工具不能读取认证目录或原实例。全局记忆和其他会话不继承，宿主自带通用能力的可用性仍属于本次宿主配置，不能声称物理隔离了所有宿主内部代码。
