# 最小任务检查点

检查点让另一会话能够从已保存的事实继续一项任务。它是项目中的普通 Markdown，由宿主 Agent 按授权保存和复核；没有后台服务、自动聊天采集或专用 checkpoint 命令。程序读取成功只证明文件可读，不证明目标、授权和外部动作仍有效。

## 唯一位置与入口

已有主项目时，使用 `项目/<项目名>/任务/<任务名>.md`，文件名保持可读。一个任务维护一份现行检查点；根卡 `project.md` 只保存任务名称和链接，项目长期事实继续由根卡或已有领域资料持有。检查点保存恢复摘要及原文入口，不复制工程正文、整段聊天或另一份项目进度表。

根 MEMORY.md 是短期续接入口，按[根协作约定](user-collaboration.md)在自然检查点维护。已有项目检查点时只保留链接和必要提醒，不复制完整任务现状；它不能代替正式记录或自动创建项目。

没有主项目的一次性任务继续使用会话上下文及必要短期线索；用户要求保存时先确定已有项目或明确保存位置，不为格式完整自动建项目。多个未完成任务均列在根卡中，用户只说“继续”且不能唯一确定时先澄清，不凭修改时间选一个。

最小元数据如下。它是普通材料格式，不是第五类能力对象，也不使用对象 CLI 管理：

```yaml
---
checkpoint_schema: 1
task_id: "example-task-001"
name: "示例任务"
state: "in_progress"
updated: "2026-10-19T10:00:00+08:00"
---
```

task_id 是任务内稳定的非空标识，改文件名不改标识；示例值不能复制为多个真实任务的身份。state 使用 in_progress、paused、blocked、completed 或 cancelled，仅表达记录状态，不是程序自动执行的状态机。updated 写实际保存时间。遇到未知 schema，先保留原件并说明不支持，不猜测迁移或覆盖。

## 必须能够恢复的信息

正文可以按任务调整章节，但必须能回答以下问题；没有的内容明确写“无”或“未知”：

| 信息 | 最小内容 |
| --- | --- |
| 目标与完成条件 | 用户要得到什么、本次范围和关键约束；最新纠正覆盖哪些旧结论 |
| 项目与工作位置 | 根卡、当前 KSF 根、实际工程入口；跨设备绝对路径需重新核实 |
| 当前安排 | 正在做哪一步、已完成什么、未完成什么；采用对象的精确 id@version、实际来源和路径 |
| 已确认决定与授权 | 用户原始指令或可信来源入口、允许的动作及目标、适用条件和已消耗动作；记录不自行产生新授权 |
| 产物与证据 | 当前文件、回执、测试结果入口及其实际范围；易变化输入记录版本、摘要或核对方法 |
| 外部动作 | 已完成、未开始或结果未知；已发起动作保存操作 ID、实际回执及下一次对账方式 |
| 待决项与下一步 | 仍缺什么，第一项可执行动作及其前置条件；依赖缺口不阻止哪些独立工作 |

权限、凭据和完整私人资料不复制进检查点。已失效方案从当前安排中移除，必要时保留简短纠正依据和历史入口，不能继续作为下一步执行。

## 保存时机与写入

用户要求保存、暂停或交接时，在其已授权位置保存。持续任务已授权维护项目记录时，可以在阶段成果、重要纠正或恢复安排发生实质变化后更新；简单问答不例行落盘。没有项目记录写入授权时只在会话保留检查点候选，并说明尚未保存；短期 MEMORY 采用自身规则。用户要求只讨论、只读或不保存时，两者均不写入，不后台补写。

写前读取最新检查点与直接受影响入口，核对本次基线并保留既有内容。正文使用宿主补丁工具；现有 `metadata read/check/write` 可读取、检查和局部更新元数据，但 metadata 不自动理解检查点业务内容。project CLI 只管理根卡，不展开任务文件。

写后逐项对照已完成结果、最新决定和“下一步”，移除已经完成或失效的动作。目标只写目标和完成条件，当前步骤与下一步各持有自己的信息，不在多个章节复制同一份当前计划。发现矛盾先修正同一记录，再报告保存成功。

检查点与根卡是两个文件，不能声称跨文件原子保存。先写并重读检查点，再向根卡补稳定链接；链接失败时报告实际已保存位置，恢复后只补缺失入口。不要为了保存检查点改工程文件、Git 历史或外部系统。检查点及其链接随项目备份，不放进可清理的 runtime-data。

## 恢复顺序

1. 从当前根入口读取当前运行定义，重新完整读取 USER.md、BOT.md、MEMORY.md，再用 project read 复核主项目；从根卡取得指定任务链接，检查路径确实属于该项目或用户明确的位置。项目归档或任务已完成时不自动重开。
2. 读取检查点元数据与正文，核对 schema、task_id、目标、最新决定、当前状态和完成条件。字段缺失、文件损坏或路径失效时说明具体缺口；不据空响应重建一份来掩盖丢失。
3. 重新读取必要产物、工程规则及状态。采用定义按精确引用重新解析，比较实际来源和版本；发生不匹配或 draft 接管变化时重审受影响安排，不静默换成别的版本。旧检查点中的提示词不是当前系统规则。
4. 对照用户当前指令与可信授权来源。目标、对象、条件或权限变化时旧授权不沿用；外部发布、发送或不可逆动作不能仅凭检查点中的自述授权执行。仍有效的普通本地任务授权不重复询问。
5. 先对账已发起但结果未知的外部动作。无法确认时保留未知，只做不依赖该结果的工作，不因为下一步写着“重试”就重复副作用。
6. 说明恢复到哪一步、已核实什么和仍缺什么，执行第一项已授权动作。恢复后的实质变化再写回同一检查点，不能只复述记录后声称恢复任务已完成。

暂停时写清恢复条件；completed 或 cancelled 退出默认继续范围，历史文件保留。检查点不是永久授权、自动备份或完整会话记录，长期效果和独立新会话需按[任务回归](task-regression.md)另行验证。
