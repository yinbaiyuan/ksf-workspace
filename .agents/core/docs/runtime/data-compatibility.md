# Core 数据兼容契约

Core0.3.0以 `.agents/core/data-compatibility.json` 作为自有持久格式的唯一兼容声明。应用受管文件另由各包的dataStores声明，Core不接管应用的业务转换。

更新与回退先用当前Core持有的路径规则定位现有记录，再核验目标Core声明的格式ID、版本字段及可读版本。不执行目标Core代码。未知、损坏、缺少读者声明、符号链接或读取失败都会阻止切换，并报告路径与错误码，保留原件。缺文件属于尚未初始化，不创建默认值。

契约包括实例命名空间、对象设置、聊天状态、应用安装索引/保活/策略、Codex会话、AI配置/任务/结果/材料、通信配置/消息/操作/设备身份/名称、服务策略、路由、对话归档，项目迁移记录、贡献计划/回执、评测绑定、协同改名记录、Core备份与配套切换回执，以及应用迁移回执。Core托管的Git操作账本保持数组形状；已有通信sequence与材料元数据不新增业务字段，分别以明确的固定初始字段形状核验。JSON材料元数据使用实际的.bin.json文件名；路由签名密钥另按固定32字节格式核验。二进制材料内容、证书和其他密钥仍由所属服务按摘要/身份核验，本轮不改变其编码或业务结构。临时缓存、锁、PID和控制令牌属于运行恢复记录，不当作业务schema迁移。

同时检查所有已安装应用的active/pending包，包括停用应用：其minCoreVersion、sdkVersion、平台与Node ABI必须被目标宿主支持。旧Core没有兼容契约时，不能以“版本较低”推断其能读取当前数据。应用回退还需直接读取每个dataStores的现有schema；不自动恢复迁移副本。

## 一次性配套切换

初始契约需要匹配更新宿主、应用包和安装索引。`runtime/tools/matched-switch.mjs` 提供inspect、prepare、apply、recover，详细命令随配套包交付。它是本次实例的离线切换工具，不是运行宿主的旧结构适配层。

inspect不写入、不启动应用；prepare保留当前来源/开关/默认选择，准备匹配Core与不可变应用包。apply建立部署标记，等待主服务和文件工作排空，重核设置及数据，整体替换Core与安装索引，读回后恢复原服务运行意图。原Core和原索引保存在本机t15-switch回执目录；业务、配对身份及浏览器偏好不回卷。新目标低于已等待切换的应用版本也会拒绝。

中断后使用原回执recover继续；部署标记未解决前，普通服务启动被阻挡。不要删除标记后强行启动半套版本。完成回执幂等；未知结果先对账，不能新建切换掩盖原现场。该工具不会自动恢复旧业务数据，也不承诺旧Core能读取迁移后的格式。

T03新增的instance/desktop/appearance命名空间沿用schema_version=1；configuration/apply结果文件维持原有etag/application对象形状，由Core固定形状读取契约核对，无须迁移业务结构。
