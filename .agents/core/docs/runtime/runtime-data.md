# 运行数据与源码保留

`.agents/core` 是当前实例的正式系统源码；独立应用在其正式工程开发。Core 的 CLI、服务和应用宿主从正式 Core 执行，前端和应用包还会包含构建产物。`runtime-data` 中的历史 Core、PR 克隆和验收副本不因存在源码就成为开发主工程。

## 分别处理的内容

| 内容 | 保留方式 |
| --- | --- |
| 当前随包 Node、身份与配对、任务游标、运行配置、应用及 AI 的业务状态 | 按各领域管理，不能当成缓存清空 |
| 最近可用的配套切换及正式升级回退材料 | 两种机制分别保留最近可用一份；未完成事务或服务恢复保留现场 |
| 唯一源码、未提交修复、独立 Git 历史和重要原件 | 先归入正式工程或项目维护资料，核验恢复能力后再退役临时副本 |
| 可重建依赖、旧候选、重复源快照、下载副本 | 在任务结束并核对来源、使用情况和恢复需求后释放 |
| 测试日志及可复用成功结果 | 按数量和容量限制保留，不按版本无限积累 |

目录被 Git 忽略不代表里面没有重要内容。父仓库忽略 `repositories` 时，子工程依靠自己的 Git；嵌套目录也可能只是共享同一仓库的 worktree。清理前应核对实际 Git 根、公共对象目录、全部引用、未提交文件和本地可用对象，不能只看目录名或 `status`。

## 受管清理

`ksf system cleanup --json` 默认只预览；`--apply` 才实际清理。它只识别受管备份、切换准备和统一测试材料，未知目录与损坏记录保留并报告，拒绝穿越符号链接和文件系统边界。

成功安装会尝试同一保留策略。清理旧 Core 前，还必须确认文件内容在同一正式路径，或在本实例 HEAD 可达且本地可读的 Git 历史同一路径中有依据。仅在其他路径找到相同内容不足以保护未提交的文件名。发现唯一文件或独立 Git 元数据，返回 `source-not-preserved` 并保留整个材料；不会因为版本旧就自动删除。没有 Git 或缺少对象也不会被当作已备份。唯一内容归档后的人工退役需另行核对，宿主不会自动扫描个人项目资料来证明已保全。

测试历史通常保留最近十次及额外五次失败／取消记录，成功缓存最多 256 项、64 MiB。正在运行和不可识别的记录不按预算猜测删除。测试结果仅是证据，不是源码备份。

## 开发任务结束时

正式源码和可复用工具进入正式维护位置；暂存修复或历史实验可保存为附有来源、文件清单及还原方法的去重材料，避免按版本复制整份实例。历史验收日志继续说明当时结果；退役载荷后不承诺旧候选仍可直接运行。唯一保存内容应能被相应 Git 纳管；“未忽略、等待提交”与“已经提交并推送备份”必须分别报告。

业务数据、迁移原件和恢复副本由各自领域决定寿命。本命令不承担业务数据归档、自动数据降级，也不清理独立工程或其他设备。
