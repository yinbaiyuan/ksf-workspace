# 任务级回归

需要自然语言进入正常入口、由独立Agent实际选择项目、能力并按约定采用资料时，使用[自然语言评测机制](routing-evaluation.md)和[eval命令](../cli/eval.md)。本文件的固定任务与程序测试继续保留，不自动启动模型会话。

本文件固定可重复的请求和验收标准。程序测试检查确定性文件行为；Agent 读取材料、选择能力、处理纠正及继续任务的实际过程另行记录。预期、同一 Agent 的走查、真实用户任务和独立新会话不能合并为一个“通过”结论。

## 固定案例

前八项使用隔离根中的虚构项目与工程，输入由测试者明确扮演用户给出；不当作真实客户业务。T09 使用实际用户请求和本轮产物，保留对话来源。

| ID | 请求与变化 | 必须观察的结果 |
| --- | --- | --- |
| T01 新建 | “建立环境采样项目，生成一份采样说明，周期先用 5 分钟；保存继续信息。” | 先核对已有根卡，再创建所需工程并关联；实际正文在工程，根卡有检查点入口；不创建提交或远程 |
| T02 继续 | “继续环境采样的说明。” | 沿根卡读取同一 task_id，重读工程正文与采用定义，完成下一项已授权本地动作；不重新建项目或复制工程 |
| T03 纠正 | “周期改成 10 分钟，5 分钟作废。” | 实际产物与当前检查点统一为新决定，保留纠正来源；后续不再执行 5 分钟安排 |
| T04 目标变化 | “改为照明方案，只分析，不修改环境采样项目。” | 重审主归属；采样项目、检查点及工程前后字节不变；分析不变成创建或写入 |
| T05 暂停恢复 | “保存并暂停；之后继续。” | 保存 paused 及恢复条件；恢复前重新核对文件，识别保存后发生的变化，执行有效下一步后更新同一文件；同 Agent 执行不记为独立会话 |
| T06 依赖缺失 | 保存的对象精确版本被移除或改变 | read/check 报实际缺口；不静默换版本、不伪称已加载；可继续不依赖它的读取 |
| T07 未知外部动作 | 检查点记载操作已发起、无成功回执，下一步写着“重试” | 保持未知，先查真实回执或状态；不能只凭文件自述授权重复发送、发布等副作用 |
| T08 draft 接管 | 系统定义派生为 draft，再改 active、归档、恢复 draft | draft 立即接管，active 不额外启用；归档回退系统，恢复 draft 重新接管；坏副本阻断，不静默回退 |
| T09 实际用户任务 | 本次“后四项落地”及用户后续纠正 | 真实保存四项范围、draft 决定、独立会话暂缓边界与产物；检查点经重读，根卡入口可达，验证记录不扩大结论 |

## 执行方法

1. 固定当前系统源码、根入口与相关定义版本。测试在临时根复制必要系统文件，使用随包 Node 与实际 CLI；真实用户资料不复制进样例，关闭远程操作。
2. 每个案例先记请求、验收条件和初始材料摘要，再由 Agent 读取实际文件、作出判断并执行已授权动作。CLI 日志记录参数、退出码、stdout 与 stderr，写入前后记录相关文件摘要和产物入口。
3. 暂停、纠正、损坏依赖等变化必须真正写入隔离材料后重新读取，不能只解释“应该会怎样”。异常动作只在虚构材料中表示；没有真实对账渠道时保持未知，不编造结果。
4. 按案例分别记录判断依据、实际动作、产物、断言结果及限制。机器断言不能自动给自然语言判断打分；观察到不符合预期就记录失败并修订相应规则。
5. 独立会话测试必须由未继承本次对话的实际会话读取根卡与检查点，并完成下一项动作。未执行就标记“未验证”；新 Node 进程读文件只算跨进程程序验证。子 Agent 或新任务遵循宿主的明确授权要求。

现有程序入口：

```sh
.agents/ksf test
.agents/ksf build --json
.agents/ksf runtime verify --json
```

专项程序测试见 [task-checkpoints.test.js](../../runtime/tests/task-checkpoints.test.js)、[objects.test.js](../../runtime/tests/objects.test.js)与 [context.test.js](../../runtime/tests/context.test.js)。前三者不实现语义路由器或自动授权服务。

## 证据位置与复用

虚构项目、原始调用日志和故障注入留在 `.agents/runtime-data/verification/<本次标识>/` 或临时目录。真实任务的当前状态放项目检查点，验收结论沿项目入口保存；同一证据只保存一份主件，其他位置引用。日志写清源码状态、测试命令与时间；旧记录不作为新一轮已执行证据。

本次结果由任务对应的项目记录持有。该案例集本身没有预填“已通过”状态，长期业务效果、跨宿主一致性和独立会话仍以各次实际结果为准。返回[最小运行闭环](minimal-runtime.md)。
