# 路由上报约定

由当前宿主 Agent 按实际任务安排调用 [route CLI](../cli/route.md)，KSF 保存声明和可核对的来源。本页描述未接入任务归档的旧 v1 写入流程。Codex 接入后的逐轮原文与路由改用[任务归档](task-capture.md)，由 Hooks/Web/CLI 补采，原件成为路由查询投影的事实源。没有宿主运行心跳，KSFAssistant 本轮不改。

## 每轮最小流程

1. 先遵守用户和宿主的写入边界。明确要求“只讨论、只读、不保存”、规划模式禁止写入，或已知关闭 routing.enabled 时，不调用 start/write。不能为声明停报再写一条记录。旧记录仍只是最近上报，无法代表被禁止保存的当前轮次。
2. 本轮允许记录且身份可用时，用 `route read --json` 取得当前 revision；新用户消息只调用一次 start，传入唯一 eventId、最小任务简述、preparing 状态及实际已知安排。归属尚未确定时为 unresolved，已确定无归属时为 none。start 返回 KSF roundId；在当前会话底稿保留它及最新 revision。
3. 路由确定或改变、补充实际采用的基本功/数据包时，用 write 提交完整快照。原生会话身份不能用目录、项目、摘要或自造 ID 代替；非 Codex 身份经 stdin 明确提供。会话上下文遗失 roundId 时先查询核对，不重建伪造旧轮次。
4. 采用对象前仍按能力规则读取正文与 user-data。对象 read 的 definition_digest 用于路由核对；直接读取的固定入口可再通过对应对象 read 核对摘要，但摘要不产生采用授权。候选只记 selected，实际加载才记 read，实际承接或用于本次方法才记 adopted；发现列表、references 和读过的资料不自动等于采用。
5. 完成、暂停、取消、等待澄清或遇到阻碍时，按实际状态上报完整快照。阶段继续复用仍有效的安排，不每个工具调用上报，不制造心跳或百分比进度。若已采用定义发生变化，先重读核对后再报告，不把新摘要套到旧读取事实。

start/write 的 report 包含 summary、status、ownership、relatedTargets 和 abilities（旧 project/references 输入兼容，不能混用）；write 顶层另带 roundId。详细字段、输入示例、开关与版本规则由 CLI 文档持有，不在这里复制第二份。

## 内容与失败边界

任务简述只写最小必要描述，不复制完整输入、聊天、正文、凭据或个人隐私。主归属按明确主要目的选择项目、知识、能力或档案；项目依 project-route 的实际结论，知识核对 `知识/knowledge.md` 导航和精确入口，能力核对对象与实际来源，档案核对实例规则及明确文件或目录。被建设能力不等于本轮采用能力，已归档项目仍是项目。只讨论、尚未保存资产也可归属；目标明确但资产未建立时可使用待创建目标的稳定身份，创建后以版本检查显式绑定，具体目标未确定时保持待确定。其他对象只作 relatedTargets，不建立聊天归属。无归属是正常状态，不因阅读材料、顺带补文件、自动归档对话或 cwd 改换目标。

实际采用的四类能力和固定入口可同时报告，由程序识别固定对象；能力 stage 与 status 均为 Agent 声明。程序核对的是定义可用性、精确来源和摘要，不证明推理质量、工具执行或业务成功。项目检查点、短期记忆和路由运行记录分属各自位置，不能互相代替。

上报失败不阻断原任务，不写回伪造成功。版本或轮次冲突后先读当前状态；旧轮次不得改用新 revision 覆盖。可纠正的输入/来源缺口解决后重试；存储、容量或身份缺口保留原件，在确实影响查看时简短说明。单次事件重试复用 eventId；新变化必须用新 ID。宿主和用户已禁止写入时立即停报。

本版不迁移旧 verified-route-projection-v6 或 KSFAssistant 数据，不把旧分类/岗位映射为新四类对象。后续消费者采用版本化查询响应，不重新解析 Markdown 或直接读内部去重账本。
