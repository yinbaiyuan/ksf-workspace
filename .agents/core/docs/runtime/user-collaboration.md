# 根协作设定

当前 KSF 根的 USER.md、BOT.md 分别承载用户长期设定和 Agent 长期协作方式。它们是用户可直接编辑的普通 Markdown，不注册能力对象，不放入对象 user-data，不增加目录或额外调度层。USER/BOT 可通过[统一配置中心](../configuration-center.md)按版本编辑原文，权威来源仍是根文件，不自动抽取或双写结构化画像。具体加载与运行责任由 [ksf-runtime](../../abilities/partners/ksf-runtime/partner.md)持有。

## 职责与采用

首次孵化将明确的用户称呼保存到 USER 原文，使用现有版本校验并保留其他内容。实例名保存在 instance.name，作为默认协作自称；BOT 不复制维护第二份名字，已有明确的自定义约定保持优先。完成后进入正常 runtime 仍从这些唯一来源读取，详见[孵化接口](../cli/incubation.md)。

| 文件 | 保存什么 | 维护方式 |
| --- | --- | --- |
| USER.md | 身份、称呼、思考习惯与稳定工作偏好 | 用户维护；Agent 只按明确授权修改 |
| BOT.md | 当前宿主 Agent 的协作定位、表达、推进习惯与边界 | 用户维护；Agent 只按明确授权修改，不替代 Core 职责 |

公司现状、项目进度和具体业务决定回到项目或相关资料；稳定身份与偏好不再特殊归入知识。知识与档案的组织机制继续由各自根说明持有，两文件不替代它们。持续任务按[任务检查点约定](task-checkpoints.md)保存和恢复。

首次进入当前根，在首次实质回应和处理任务前完整读取 USER.md、BOT.md；不能以搜索命中、标题或截取片段代替。继续任务复用有效内容；文件更新、用户纠正、任务恢复、上下文丢失或切换根时重新完整读取。切根不沿用前一实例身份或协作设定。缺失采用通用默认，不自动创建；不可读报告实际缺口并继续独立工作，不能假装未配置。

仅当 USER.md 确认不存在时，可只读兼容该根的 `知识/用户画像.md`；USER 存在即以新文件为准，即使不可读也不自动合并或用旧画像掩盖故障。旧原文不删除、不自动搬迁。两文件中的引文、推测、待确认内容不是已确认协作要求，不产生新的操作授权。

本次明确指令优先。项目约定按其适用范围采用；与用户明确长期边界发生重大冲突时说明具体取舍。所有约定遵循宿主指令、实际能力与权限，不因被读入而扩大权力。责任交接仅传递完成任务所需的约定和线索，不附带无关个人资料。

## 模板、发行与升级

唯一通用模板源位于 Core 的 distribution/template；新工作区生成大写文件名、小写扩展名的 USER.md、BOT.md，只含可编辑说明，不包含实际用户或 Agent 的私人身份。真实实例的两文件属于用户内容，不进入 Core 发行或公开贡献。

发行检查根据包内已验证的模板源判断生成文件集合和字节；允许没有协作文件模板源的旧包，拒绝未知额外文件、缺失必需模板及篡改内容。升级和回滚仅管理系统范围，不覆盖用户定制、不补写缺失文件；新模板源随 Core 更新，不等于自动重新生成根文件。旧包中的 MEMORY.md 仅按其已验证模板源校验，新包不再生成；旧实例已有文件作为普通用户原件保留，不参与启动读取或自动维护。

## 验证范围

程序测试核对模板生成、字节和名称、私人内容隔离、旧包布局及升级回滚保留。加载、称呼采用、临时覆盖、换根、不可读处理和只读零写入由 Agent 使用隔离材料走查；程序测试不冒充 Agent 行为。当前 Agent 走查不能证明独立新会话或长期效果。每轮实际结果由实例开发项目检查点保存，不用下面历史计数替代当前验收。
