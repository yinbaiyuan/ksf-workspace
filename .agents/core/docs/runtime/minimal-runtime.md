# 最小运行闭环

本版让当前 Agent 从 KSF 根入口完成必要的项目筛选、知识读取、任务推进和已授权资产维护。方法定义已有，实际处理仍由宿主 Agent 执行，不能把 CLI 返回成功当作任务已完成。

## 入口与责任

根 AGENTS.md 进入 [ksf-assistant](../../abilities/partners/ksf-assistant/partner.md)。入口搭档保持目标、组织执行、处理纠偏并复核交付，按下表读取定义：

| 需要解决的问题 | 主要定义 |
| --- | --- |
| 本轮与已有任务的关系、能力发现与承接安排 | [task-route](../../abilities/competencies/task-route/competency.md) |
| 项目归属、必要项目事实、工程关联 | [project-route](../../abilities/competencies/project-route/competency.md) |
| 必要知识、来源范围、时效与冲突 | [knowledge-route](../../abilities/competencies/knowledge-route/competency.md) |
| 保存价值、唯一落点、授权、写入与验证回退 | [asset-maintenance](../../abilities/competencies/asset-maintenance/competency.md) |

入口先按 ksf-assistant 的启动约定取得已配置的用户短卡，再识别本轮关系；理解目标需要项目事实时先补事实，再完成能力选择。按工作流优先、搭档兜底的现行规则推进，无匹配时判断通用 Agent 承接。背景知识与维护均按需发生，空库和简单任务不强制经过全部基本功。对象的专业设计仍由[对象设计师](../../abilities/partners/ksf-object-designer/partner.md)及其三项设计基本功承接。

三项新增基本功使用固定系统定义、0.1.0 和 active，含义是参与使用；质量与验证范围另外记录。保护身份、路径与用户接管规则只由[对象元数据规范](../对象元数据规范.md)及程序实现持有，不在这里另定。

## 内容与程序边界

- 项目稳定入口为 `项目/<项目名>/project.md`，以普通 Markdown 保存当前事实与来源。[project CLI](../cli/project.md) 提供 list/read/write/remove/check；发现只返回根卡摘要，read 不展开资源。已有领域入口按需下钻，本版不实现自动拆分或跨文件原子迁移。
- 知识保留普通 Markdown；`知识/用户画像.md` 为可选配置的短卡，首次进入时读取已配置内容，系统包不预填私人信息。用户可明确授权写入自己的身份与协作偏好；通用协作、证据规则仍由系统定义持有，见[用户协作约定](user-collaboration.md)。项目和知识不套用能力对象必填字段。
- 用户能力通过现有四类对象 CLI 维护；项目根卡可用 project CLI 创建与更新，局部正文、资料和知识可由宿主文件工具编辑，元数据也可用现有 metadata CLI。固定系统开发必须有明确任务授权，日常对象 CLI 仍拒绝其写入和删除。
- 能力发现实时读取文件，不生成第二份能力索引。维护只同步直接受影响入口与链接。
- 原始工程、代码和工程文档留在真实工作区；项目只保存项目认知和稳定入口。跨工程分别检查规则、改动基线与授权。
- 用户目录可为空。首次需要项目或知识时按明确任务创建或读取，不从另一知识库补齐内容或加载其运行规则。

当前已有项目基础命令；没有专用知识管理命令、持久化路由接口、全库语义索引或完整宿主事件记录。运行诊断及专项链路审计不在本轮；一般异常由入口搭档处理。外部任务上报和版本包升级暂缓。当前系统的明确开发修改仍按工程规则测试、构建和验证。

## 旧规则的必要性筛选

历史文档只用于设计时查漏，不作为当前执行依赖；没有逐文件原样搬迁。

| 来源主题 | 本轮处理 |
| --- | --- |
| 运行模型 | 沿用新版四对象及公共契约，旧分类、岗位与执行对象制度不迁移 |
| 执行身份说明 | 目标、推进、纠偏、授权与交付已由入口搭档覆盖，不另建身份对象 |
| 协作可观测性 | 沿用入口对依据与实际结果的表达，区分读取、执行和结果；不搬固定回执和例行治理报告 |
| 读库规则 | 能力读取复用 task-route，只补项目与知识发现、渐进读取和来源检查 |
| 知识库索引 | 复用实时能力发现；按新目录读取必要入口，不导入旧项目或知识清单 |
| 归类与维护 | 仅补唯一正文、八目录责任、链接范围和文件操作边界 |
| 独立工程协作 | 补工程身份核实、事实原位、规则读取、Git 隔离与稳定事实写回边界 |
| 系统更新 | 补保存价值、归属与授权、基线复核、实际验证和窄范围回退；不搬旧阶段、证据晋级或待治理状态机 |
| 用户画像 | 初始迁移只定义可选入口，不批量导入个人内容；后续用户明确授权的身份与偏好按用户协作约定单独维护 |

一般工程与宿主已经提供的规则直接使用。发现新的冲突时先核对当前用户决定，未裁决的重大冲突交回用户，不以迁移完整性为由扩大范围。

## 验证入口

程序回归使用 `ksf test`，随后 `ksf build --json` 与 `ksf runtime verify --json`。自动化检查覆盖真实定义图、固定保护、精确依赖、四类对象服务以及项目基础命令；项目/知识的语义选择、授权判断与来源核对由当前 Agent 在隔离材料中走查，二者不能冒充彼此。

实际结果和限制见[验证记录](minimal-runtime-validation.md)。测试材料放临时目录或本机运行数据，正式项目、知识、能力、收件箱、源档与归档目录不加入演示内容。修改不自动获得 Git 暂存、提交或发布授权。
