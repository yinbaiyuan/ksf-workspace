# 能力源协议 v2

能力源（Ability Source）是遵循本协议的独立 Git 仓库，用于分享协同、搭档、基本功和数据包。可以私有或公开，可由个人、团队或组织维护，也可以只分享一个对象。KSF 直接关联仓库当前工作树，不安装、不锁定提交、不生成正文副本或能力快照。

系统内置能力负责入口、路由、对象设计与管理、能力源管理、系统生命周期等系统支持；个人区承载个人创建与定制，专业、行业和业务能力默认由个人区或能力源维护。对象 ID 与源身份分开，不要求源专属命名空间，不改变固定入口保护。

## 声明和结构

仓库根必须有普通 UTF-8 YAML 文件 ksf-source.yaml：

```yaml
kind: ksf-ability-source
schema_version: 2
id: team-methods
name: 团队方法库
description: 共同维护的协同、搭档和基本功。
```

kind、schema_version、id、name 必需，description 可选。id 为小写字母开头、最长 64 字符的小写字母/数字/连字符字符串，排除 system/user/effective/all；在一个 KSF 中唯一，不作全局注册。name 是非空显示名称。schema_version 管理协议格式与语义，与 Core 和对象版本分别管理。未知字段、版本、YAML 多文档、重复键、锚点、别名和自定义标签均报错并保留原件。

固定能力根为 能力/，类型子目录为 协同/、搭档/、基本功/、数据包/；无对象的类型可以省略。一个对象一个目录，可以用中文显示名称或完整对象 ID 命名，入口分别为 cooperation.md、partner.md、competency.md、datapackage.md。对象身份由入口元数据中的完整 ID 确定；目录名本身是有效对象 ID 时，仍须与元数据 ID 一致。同源重复 ID、入口类型错误、符号链接和固定对象保护继续按原规则校验。资源属于对象目录，不作为嵌套对象扫描。复用[公共对象规范](对象元数据规范.md)，发布对象不含 user_revision/upstream 和 .upstream/，修订历史由源 Git 管理。正文非空，状态仍为 draft/active/archived，前两者参与默认发现。

建议根目录包含 README.md 和 AGENTS.md。init 默认生成；已有文件保留。源的 AGENTS.md 是普通仓库协作规则，不是 KSF 工作区的固定入口，也不作为协同载入。仓库不需要 Core、启动器或单独运行时。

## 关联、读取和权限

通过 source init/link/read/check 管理，命令见 [source](cli/source.md)。关联要求路径自身为独立 Git 工作树根，允许独立仓库的 Git worktree；不得关联 KSF 自身或与其共用历史存储的工作树。默认位于 repositories 的直接子目录，整个容器由外层 KSF Git 忽略；外部已有仓库可原位关联。普通目录和资源不跟随符号链接。

关联保存在系统级 user-data 的 sources 命名空间，values 为 `{"entries":[{"id":"team-methods","path":"repositories/team-methods"}]}`。内部路径相对 KSF 根，外部路径为绝对路径；显示名每次读声明取得。注册数据无凭据、正文、版本锁或副本。目录移动需显式解除旧关联再关联；源声明 ID 变化报错，不把旧关联静默指向新身份。

可读即允许使用，不增加组织、成员、白名单或远程鉴权。离线使用本地工作树；clone/pull/push/PR/merge 按正常 Git 认证、权限与用户请求执行。权限撤销不远程清除已有本地文件。

直接读取当前工作树，包括未提交修改；切分支、拉取和编辑后下一次读取反映变化。关联后整个源参与发现，正文和资源渐进加载。没有额外安装清单、持久化对象索引或安装快照。读取失败保留来源与 complete=false，不把损坏/失联当空源。

## 多源身份与依赖

默认读取按个人 → 匹配的能力源 → 系统，精确版本沿用相同顺序。归档退出默认选择，坏的高优先级副本不静默回退。多个源同时匹配同 ID（精确请求时同时匹配该版本）返回 SOURCE_AMBIGUOUS 与候选，不按源顺序或最高版本猜测。显式对象 --source <源ID> 只读该源；context --source <源ID> 则发现个人、该源和系统的有效集合。

源对象的 references 保持 id@version 格式，只由同源和 Core 的精确版本满足，返回实际 source/path。个人覆盖不改变源内依赖绑定，其他源也不能隐式补齐它。个人与系统对象仍走默认有效解析。固定入口始终采用其系统定义。

关联/检查/导出验证源内依赖，Core 更新和回退预览及实际切换也核对已关联源的精确依赖。不兼容时保留当前 Core。普通 Git 拉取后出现不兼容时保留 Git 现场，检查并据用户要求通过 Git 修正，KSF 不自动恢复旧工作树。

## 贡献与分发边界

source export 将选定个人对象及必要个人依赖写入指定源，保留 ID 和个人原稿。已有对象沿用其当前目录（包括中文目录），新对象默认使用完整 ID 目录；移动现有目录不改变对象身份与精确引用。移除个人修订字段与派生基线，复制完整选定资源并重算所选对象之间的相对链接。相对本机外部资源须先显式包装，其他源内容不自动复制。已有发布对象内容变更需要递增对象版本及有效精确引用；export 的 --versions 映射可单独设置贡献版本并同步包内引用，不更改个人派生来源版本；支持预览与无变化结果，列出移除资源；已有目标对象有 Git 差异时停止覆盖，写入前检查并发，使用源仓库临时锁协调本机写入。

export 只准备本地贡献文件。维护搭档按[能力源管理](../abilities/competencies/source-management/competency.md)组织具体 Git 分支、定向提交、推送和草稿 PR；更新、合并与回退遵循普通 Git。源内容与个人历史不进入 Core 发行、模板或公共系统贡献。系统发布仅按原系统白名单收集文件，构建校验不读取维护者的能力源配置。
