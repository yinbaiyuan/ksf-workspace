# 每日工作回顾、证据审查与对话归档

KSF飞轮（原“对话工作台”，应用0.2.19起采用新名称）按工作事项整理当前实例已采集的工作，形成报告、可复用能力候选及已有资产的改进建议。对话是证据来源，工作事项可以跨聊天；归并展示不改变原文和主归属。最低 Core 0.3.1、应用 0.2.10。

## 启用和生成

1. 打开KSF飞轮，在“回顾设置”选择系统已有的 API/CLI 执行配置，或显式选择 Codex Desktop 及对话所属项目，勾选每日自动生成并保存。
2. 默认时区 Asia/Shanghai，每天 06:00 整理前一自然日；自动范围从首次启用当天开始。今日或更早日期可以手动生成。
3. 在“工作回顾”查看今日活动、后台批次进度、历史与补充报告。打开页面和刷新不会发起新的模型任务。
4. 按四部分审阅：工作与结果、证据与问题、复用与改进、后续与收尾。点击证据定位原始轮次；文件核验只表示核验时可读取，不证明历史版本或测试通过。

聊天数和轮次数表示活动量，工作事项另行统计。完成声明保留“对话中报告”的性质；缺失、冲突、时间不确定及未上报归属明确展示。跨午夜按消息时间分段，前文作为上下文。图片等未进入文字审查的附件明确列为缺口，相关轮次不视为已覆盖；原件仍可点击回源人工核对。单处来源变化或读取失败保留缺口，其他可核对事项继续生成。

## 建议及审阅归档

“待处理建议”跨日期保留能力候选、现有资产改进、工作质量改进，包含来源、目标、修改理由、具体建议和验证方向。能力候选补充场景、输入、步骤、输出及限制。优先完善已有能力；同一问题沿用稳定标识，合并新增证据并保留忽略、稍后处理等选择。

建议支持打开修改位置、复制处理指令，以及待处理／稍后处理／已忽略／用户标记已处理。标记处理不等于独立验证。应用不创建正式能力，不修改项目、知识、USER、BOT，不替用户发送处理指令。

报告中的“确认审阅并归档 N 个对话”是用户动作。归档要求聊天工作已结束、必要轮次已覆盖、没有未交付或结果未知事项，且确认时来源版本未变化。用户可以取消候选；变化的聊天跳过并返回原因。未完成建议不阻止对话归档。

“采集完整”“已回顾”“已归档”分别表达正文采集、已审阅来源版本、默认列表可见性。归档仅影响本应用；原件、统计、项目查询和 Codex 原聊天不变。对话可恢复，新增消息或来源变化会重新进入进行中。原始采集策略后续禁止读取时，相关报告内容和建议在读取时隐藏。

## 后台与失败恢复

应用以 resident 后台运行，关闭浏览器后继续；主服务或机器离线不保证准点，恢复后按日期串行补跑。空日不调用模型。每次业务运行及 AI 请求先保存稳定编号；重启和本机桥断开后接续原任务，不更换键重复提交。

已审阅版本不覆写，新证据形成补充版。手动“重新核对此日”使用独立操作编号生成新版本，复用未变化的提取结果。AI 的 reconciling 保留原任务待核对；只对已确认失败的任务提供显式重试，不能借重试绕过未知结果。

源材料按批提取，必要时分层汇总；输入和输出仍受执行配置上限约束，无法处理的部分保留缺口或失败，不静默截断并伪称完整。后台只读取明确关联的目标及原文明确引用的工作区路径，当前目标正文节选带版本并标明范围。

## 数据与接口

采集原件继续位于原 `档案/对话/Codex/`。应用 user 范围的 `reviews.sqlite` 保存报告版本、建议、审阅回执和归档状态；runtime 范围的 `review-runs.sqlite` 保存请求、执行编号、提取结果与恢复状态。SQLite user_version=1，未知版本拒绝读取，不自动降级。运行数据也含恢复证据，不能作为可随意清空的缓存。

SQLite 属于应用自行维护的数据，不由固定 JSON 的 dataStores 迁移器检查。备份用 SQLite backup，或正常停止应用后复制完整文件；不得直接覆盖正在使用的数据库。回退程序不等于回退数据。

Core 公共证据读取见 [SDK 接口](app-development/api.md#回顾证据读取core-031)。应用 CLI 的命令与调用边界见 [包内说明](../applications/conversations/docs/cli.md)。API/CLI 调用经过 AI 任务服务；Desktop 经 codex-conversations 创建独立对话，应用校验结构化信封与引用后采用。报告记录执行路径与结果回执，不保存凭据。Desktop 的已接收/空闲不能替代结果校验，原请求未知时只核对与恢复，不切换执行端。
