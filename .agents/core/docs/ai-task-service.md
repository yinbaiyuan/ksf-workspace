## 1. 目标与职责边界

工作台应用通过公共 AI 服务提交一项有明确输入、目标和输出要求的任务。服务直接调用 API 或 Codex CLI，保存执行状态与结果。应用取得结果后，由自己的代码继续业务流程。

| 单元 | 持有的责任 |
| --- | --- |
| 应用代码 | 业务顺序、并行、条件、循环、定时规则、业务进度、结果验收、发布发送和业务恢复 |
| 统一 AI 服务 | 请求接收、输入与配置快照、并发排队、执行尝试、进度、输出校验、取消、结果保存及执行对账 |
| 执行适配器 | 供应商协议或 CLI 进程的转换、认证引用、执行身份、事件解码和错误映射 |
| KSF 能力对象中的 Cooperation | 指导对话 Agent 协调搭档、交换结果、推进交互；与应用代码流程分别存在 |

应用可明确选用能力定义作为 AI 任务的方法材料，也可只提供指令。调用 AI 服务不要求创建能力协同，不自动装载整个 KSF 入口、聊天历史、知识库或宿主插件。

首版包括应用主动触发的文本 API、Codex CLI，以及早会所需的专用转写 API 扩展。暂不设计宿主领取任务、通用业务流程引擎、业务 DAG、跨设备同步或无人值守桌面点击。其他 Agent 的可调用接口作为后续适配方向。

## 3. 应用提交契约

契约版本命名为 ai-task-v1。aiTaskId 与现有聊天档案 taskId、原生 turnId、能力聊天 runId 分别管理。应用自己的 businessRunId 和 stepId 仅作关联。

| 字段 | 要求 | 约定 |
| --- | --- | --- |
| contractVersion | 必填 | ai-task-v1；未知版本明确拒绝 |
| idempotencyKey | 必填 | 同应用内稳定的本次请求标识 |
| profileId | 必填 | 本次使用的执行配置 |
| instruction | 必填 | 目标、处理要求和边界，作为任务指令保存 |
| inputs | 必填 | 文本或已登记材料引用组成的列表；允许显式空列表 |
| outputSpec | 必填 | text 或 json；JSON 附结构约束，文本可声明 text/markdown |
| context | 建议填写 | 应用业务运行编号、步骤编号和必要标签；服务不解释业务顺序 |
| requirements | 按需 | 现行适配器支持的额外能力，例如audio-transcription；首版不支持web-retrieval，未知能力拒绝 |
| deadlineAt | 按需 | 带时区的绝对截止时间，覆盖排队、重试和执行 |
| limits | 按需 | 在执行配置允许范围内收紧尝试次数、时长和输出大小 |
| methodRefs | 可选 | 首版仅接受空数组；方法正文显式作为text输入。精确引用解析是后续扩展目标，当前不执行 |

调用 appId、应用版本和 release 身份由宿主根据受管运行实例绑定，应用提交值不作为身份依据。管理界面使用独立管理上下文，不把任意 appId 参数当授权。

### 3.1 输入材料

文本输入保存本次原文；文件输入通过材料登记获得 materialId、版本、SHA256、MIME、大小和显示名。引用普通可变工作区文件时，先按现有文件保护规则取得一致快照，再提交任务。

材料登记是辅助接口，不属于业务编排。普通应用 RPC 传引用而非大文件。录音已提供有界二进制/流式入口，复用工作台来源、令牌和路径校验；不把整段音频 Base64 塞入现有小型 RPC，也不静默放宽现有图片上传或普通 JSON 请求限制。

任务接收后保留不可变输入快照。文件后来修改、应用升级或能力版本变化，只影响新的提交。输入超过适配器限制时返回明确错误；分段、汇总和重新提交由应用代码决定。

网页 URL 是来源信息或待抓取输入，不能据此声称已读取正文。网页、录音转写和外来文档作为数据处理，与任务指令分开封装。联网权限和检索工具能力分别声明，不能用“允许联网”代替“已配置可工作的检索工具”。

### 3.2 接收与去重

1. 先按宿主身份检查调用来源、请求版本、执行配置、材料引用、输出约束和能力匹配。
2. 对规范化请求内容计算摘要；去重作用域为 KSF 根、appId、idempotencyKey。
3. 相同键及相同请求返回原 aiTaskId；相同键但请求不同返回 AI_IDEMPOTENCY_CONFLICT。
4. 新任务固定输入、指令、方法、输出约束、执行配置及其版本，持久保存后再确认接收。
5. 确认接收只代表任务已进入队列，执行结果通过后续读取获得。

去重先查已接收请求，因此重复提交不会因执行配置后来更新而创建新任务或替换旧快照。去重标识到期策略必须显式设计；首版不清理仍可重放的键后悄悄允许再次执行。

## 4. 执行端连接与执行配置

这两类配置是 AI 服务实例数据，不是新增 KSF 能力对象类型，也不占用聊天动态变量空间。

| 配置 | 公共字段 | API 专属字段 | Codex CLI 专属字段 |
| --- | --- | --- | --- |
| 执行端连接 | id、revision、kind、enabled、能力清单、并发额度、credentialRef | 明确的 protocolId、baseURL、网络请求设置 | executablePath、兼容版本范围、运行账号与认证来源 |
| 执行配置 | id、revision、executorId、model、允许的模型选项、超时与重试规则、输入输出限制 | 该协议和模型支持的原生输出约束、上传策略 | 工作目录、只读输入与输出目录、工具清单、网络与权限配置 |

应用按 profileId 选择已配置路线。首版不自动跨 API 与 CLI 改换执行端；应用可明确提交替代任务，并关联原 aiTaskId。原配置内的技术重试保留原任务编号。

原配置快照固定模型请求、协议、工具及限制；秘密值只通过 credentialRef 在执行时读取，不进入请求快照、结果、进度事件或前端。凭据轮换与模型配置变更分别处理。

凭据后端先支持明确配置的服务环境引用；系统凭据库接入可另增解析器。后台服务环境需实际具备该引用，不假设继承交互终端的环境。Codex 使用当前运行账号的明确认证来源，业务适配器不从当前桌面聊天中提取凭据。

配置变更使用 revision/etag 校验；展示可用性、能力、最后检查结果和凭据是否存在，不回显凭据。配置能力声明需经过相应适配器检查；不兼容模型选项在执行前拒绝。

## 5. API 接入

### 5.1 文本 API

首版文本适配器已支持 `deepseek-responses-v1` 与 `openai-responses-v1`。用户已选 DeepSeek，确认默认 `deepseek-flash`、`env:DEEPSEEK_API_KEY`；真实账户凭据及调用仍待验收。DeepSeek 按自己的无状态 Responses 协议映射，不添加 OpenAI 专有字段。不同协议通过独立 protocolId 接入，不能仅更换 baseURL 就宣称完全兼容。

适配器负责：

1. 把指令、文本与材料转换为该协议支持的输入，保存请求身份与模型请求信息。
2. 根据 outputSpec 映射原生结构化输出。供应商只支持部分 JSON Schema 时，检查可映射范围；不能映射时返回错误或采用配置明确允许的生成后校验方式。
3. 区分实际完成、拒答、输出被长度限制截断、工具调用未完成、请求被拒绝及结果未知。
4. 流式分片仅作为进度；完整响应经统一校验、落盘后才能成功。
5. 仅在确定可安全重试的瞬时错误下按配置重试。响应结果未知时，若有可查询的上游身份先对账，否则进入 reconciling。

第一版文本 API 不隐含通用 Agent 工具循环。应用可先取得材料再请求整理；若以后支持模型自行调用工具，需要单独的工具执行协议、权限和验收。

### 5.2 转写 API

录音转写采用专用适配器和执行配置。输出统一成转写文本、分段以及确实可取得的时间戳/说话人信息。执行端未提供的信息保留未知；不从文本猜造精确时间戳或说话人身份。

适配器检查真实音频格式、大小、时长及供应商能力。超限分段和多段合并由早会应用安排。模型和接口的可用性、弃用及限制在实施时按当前官方资料复核，不固定沿用旧教程中的模型或能力假设。

## 6. Codex CLI 接入

本机 codex-cli 0.163.0 已完成非交互真实任务及安装早会应用的真实调用，使用虚构转写稿验证结构与关键事实。取消/恢复另有受管进程故障测试；它们不替代真实录音和长期使用验收。首版适配限定 0.163.x，升级仍须重查。

每个执行尝试准备独立工作目录，包含只读输入快照、任务指令、必要方法材料和输出位置。CLI 路径、模型与认证来源取自配置；参数由适配器结构化生成，任务指令经标准输入传递。

进程由后台服务持有，记录 attemptId、PID 及进程身份校验信息、原生会话身份和版本。超时或取消仅操作该尝试确实拥有的进程组；重启后不能仅凭一个可复用 PID 判断所有权或杀进程。

JSONL 事件用于识别开始、工具执行、失败和完成；隐藏推理及 reasoning 事件不进入服务执行记录。stdout、stderr 和工具事件需脱敏、有界保留。解析失败、输出超限和进程异常退出有独立错误原因。

CLI 退出成功、最终输出可读取及统一输出校验通过，三者共同构成适配器成功条件。会话可以归属于某次执行尝试，但不得使用“最近会话”推断恢复目标，也不自动接续当前桌面聊天。

权限和工具限制必须落实到当前 CLI 支持的配置与实际运行约束。无法无人交互完成的登录、工具授权或必要补充输入，以明确错误交回应用；不伪造已经完成。

## 7. 应用调用、进度和管理入口

下表描述调用分层；当前接口的精确方法名及首版限制见接入说明：

| 接口层 | 操作 | 约定 |
| --- | --- | --- |
| 应用后端公共服务 ai | describe、submit、get、cancel、events、register、readResult | 使用宿主绑定的 appId；submit 返回 aiTaskId 与当前快照 |
| 材料辅助入口 | register、二进制material-upload、readResult | 大文件走有界材料入口，校验引用与读取范围 |
| 管理入口 | 连接/配置 read、write、check；任务 list/read | 经工作台来源、会话令牌及管理上下文校验 |
| SDK 辅助 | submit/read/cancel；基于游标的事件订阅 | 初版通过有界短轮询实现订阅；保留未来流式传输替换空间 |

应用前端先调用自己的后端，由应用后端提交 AI 请求。通用管理接口不接受应用自行声称的 appId 作为任务所有权依据。现有宿主服务桥需向 AI 服务传入不可被参数覆盖的调用上下文。

首版 get/events 返回状态快照和单调递增 seq，events 接受 afterSeq并返回hasMore；观察者先排空分页再处理终态。事件按至少一次交付处理；应用按 seq 去重，断线后从游标继续。查询是结果事实源，不因 UI 订阅中断而取消任务。

普通应用服务调用的超时不等于 AI 任务执行时限；submit 完成接收即返回，不把数分钟模型任务挂在普通 RPC 上。会话能力增加 ai-tasks-v1，旧应用继续运行，未提供服务时返回明确的能力不可用错误。

当前应用体系面向受信任代码，应用后端拥有用户系统权限。appId 绑定用于正确归属和服务校验，不将其宣称为对恶意同用户代码的完整操作系统隔离。

## 8. 统一结果与错误

| 字段 | 约定 |
| --- | --- |
| aiTaskId / status / revision | 独立任务身份、状态及当前聚合版本 |
| context | 原请求的业务关联信息 |
| output | format、value 及生成文件引用；只包含通过输出契约的结果 |
| warnings | 输入缺口、能力限制、可确认的质量限制；不制造置信度分数 |
| execution | profileRevision、executorId、模型请求与可取得的上游模型信息、各次尝试摘要 |
| timestamps | 接收、开始、完成、取消请求时间；统一存储时间，按应用时区展示 |
| usage | 可取得的 Token、用时及费用来源；未知为 null，估算与实计分开 |
| error | 稳定 code、可读 message、执行结果是否未知及下一步建议 |

服务校验格式、Schema、文件引用完整性及约定的基本限制。业务正确性、是否发布及是否需要人工修订由应用自己的验收逻辑决定。JSON Schema 通过不证明纪要事实或新闻判断正确。

大结果先发布为不可变结果文件，再原子提交任务中的成功引用；之后才发成功事件。失败的校验候选不能出现在成功 output 中。失败及取消后的候选结果可保留为受控诊断材料，业务代码不能把它当成功结果推进。

建议错误族包括：AI_REQUEST_INVALID、AI_PROFILE_UNAVAILABLE、AI_CAPABILITY_UNSUPPORTED、AI_AUTH_REQUIRED、AI_INPUT_TOO_LARGE、AI_OUTPUT_INVALID、AI_PROVIDER_REFUSED、AI_EXECUTION_TIMEOUT、AI_DEADLINE_EXCEEDED、AI_EXECUTION_UNKNOWN、AI_IDEMPOTENCY_CONFLICT。上游错误经脱敏映射，不直接把原始异常或密钥返回前端。

## 9. 生命周期和一致性

### 9.1 任务与尝试

任务是应用提交的工作单元；尝试是一次向执行适配器的实际派发。API 的新一次生成/修复请求或 CLI 的新一次启动计为新尝试。CLI 内部模型/工具步骤属于该尝试，能够取得的用量要避免重复累计。

| 任务状态 | 含义 | 终态 |
| --- | --- | --- |
| queued | 已持久接收，等待服务按并发额度派发 | 否 |
| running | 正在准备、执行或校验；phase 表明实际阶段 | 否 |
| retry_wait | 已确定可重试，等待受限退避 | 否 |
| reconciling | 原执行结果未知，暂停再次派发并核对 | 否 |
| succeeded | 有符合输出约束且已保存的结果 | 是 |
| failed | 策略或确定错误已结束任务，没有可供应用采用的结果 | 是 |
| cancelled | 取消已提交，后续结果不再推进本次应用步骤 | 是 |

~~~mermaid
stateDiagram-v2
  [*] --> queued
  queued --> running
  running --> succeeded
  running --> retry_wait
  retry_wait --> queued
  running --> reconciling
  reconciling --> succeeded
  reconciling --> failed
  queued --> failed
  running --> failed
  queued --> cancelled
  running --> cancelled
  retry_wait --> cancelled
  reconciling --> cancelled
~~~

reconciling 只有取得有效且未被截止/取消策略拒收的结果，才可以成功。截止后取得的候选作为诊断证据保存，不能自动恢复发布。

### 9.2 重试、取消、截止和恢复

- 重试次数、退避和单次执行时限来自已固定配置；deadlineAt 是额外的总截止限制。新尝试开始前再次检查截止与额度。
- 格式修复属于新尝试，受相同次数、时长和用量记录约束。认证、能力不匹配、拒答等错误不作无意义重试。
- 结果未知不等于可以重试。可查询上游身份、可核验 CLI 进程或已保存结果时先对账；无法核验时保留未知并交应用选择取消或另发新任务。
- 取消在任务聚合中原子提交。若成功先提交，取消返回已完成；若取消先提交，晚到结果不能改为成功。尝试另行记录 stopConfirmed 与 executionOutcome，取消不表示远端计算或收费必然停止。
- 终态不可回流。改输入、改输出契约或选择替代执行端均创建新任务，并可通过 context 关联原任务。
- 派发与回交使用 attemptId、执行租约和版本检查；旧尝试、旧进程或重复回调不能覆盖新状态。
- 并发额度按实际尚未结束的执行尝试计算。任务已取消但尚未确认执行停止时，不能仅因任务进入终态就释放名额并继续超额派发。
- 服务关闭时先停止接单与新派发，保存运行身份并终止/脱离受管执行的结果核对信息。启动时先恢复现场，再派发可确认未执行的队列项；不将全部 running 批量改成 queued。

应用应把 aiTaskId 与已采用的最终 revision 和业务步骤状态一起保存，以便重复事件不会重复推进。群消息、文档发布等外部动作仍需要应用自己的操作身份与回执；本服务不承诺这些跨系统动作“恰好一次”。

## 10. 数据保存与版本演进

拟议实例位置：

| 位置 | 内容 |
| --- | --- |
| .agents/user-data/ai/connections.json、profiles.json | 连接、执行配置及 revision；只有凭据引用 |
| .agents/user-data/ai/tasks/ | 任务聚合：请求摘要、快照、状态、尝试和可重放的关键事件 |
| .agents/user-data/ai/materials/、results/ | 已接收的不可变材料、结果及其摘要 |
| .agents/runtime-data/ai/ | 可重建索引、执行锁、受管进程记录及临时工作目录 |
| 应用 dataDirectory 或已选项目位置 | 会议、日报、业务流程进度、发布记录及正式产物 |

首版建议沿用文件存储：单任务的权威状态、尝试、关键事件在同一聚合中更新；结果文件先准备并 fsync，再原子发布聚合引用。去重标识记录在权威任务内，查询索引可重建；接收、去重与派发须受同一根的跨进程协调保护。

实施时需核对文件及父目录的持久提交能力。临时文件加 rename 只能直接说明替换方式，不能单凭它宣称真实断电情况下的数据持久性已经验证。

关键事件保留状态与可解释里程碑，不持久记录每个生成 token。记录、材料和输出均有大小上限；超限明确失败，不能截断权威状态或把损坏文件当空任务重建。

凭据不保存到上述普通文件。断电留下的未引用结果、临时目录和损坏记录需保留可核对信息，清理采用显式策略。正式业务产物和运行证据不能只放在可清理缓存。

Core 发行携带源码与虚构示例，保留实例数据。未知存储版本拒绝修改；旧程序不能覆盖新 schema。回退程序不等于回退任务数据，需要版本检查及关闭新任务入口的恢复方式。

## 12. 两个应用的使用与验收目标

### 12.1 早会纪要

应用代码接收录音，提交转写任务；转写完成后提交纪要任务；应用验收结果、发布文档和发送群消息。

纪要任务示例：profileId 为 text-default 或 text-codex；输入为同一份固定版本转写稿、日期和已知参会人；输出为 summary、decisions、actions、openQuestions。行动项允许 owner、dueAt 为 null，并引用确实存在的转写段落。决定与提议应区分，缺失负责人不能猜填。

验收重点：相同转写稿分别经 API/CLI 后保留一致的关键事实和未决项；输出格式一致但不要求逐字相同。转写、整理与发布各自有任务或操作身份。发送失败只恢复应用的发送步骤，不重做已经完成的转写和纪要。

### 12.2 每日早读

应用按自己的时区与出刊规则取得材料、维护已报道事件，再提交筛选整理任务；结果完成后由应用核对来源、排版与发布。

任务输入包含材料编号、真实读取的正文、来源链接、发布时间、事件时间、采集时间和历史事件清单。输出包括导语、事件条目、摘要、sourceIds、关注理由与待核实事项。sourceIds 只能引用本批允许材料；引用存在不等于事实已经被验证，应用仍应核对原文支持。

验收重点：同一事件的转载合并、旧闻识别、空新闻日、来源部分失败、跨日去重、截止后晚到结果不自动发布。固定测试材料与真实联网采集分别记录证据。

无窗口的准点出刊还依赖应用后台启动机制和机器在线条件。现有任务保活不是长期计划恢复；应用后台入口、定时及跨日补跑是业务配套阶段的独立交付，不能用单次 AI 调用成功代替。

## 13. 决策状态、代价与重评条件

| 决定 | 状态与依据 | 代价 / 重评条件 |
| --- | --- | --- |
| 应用代码控制业务流程，能力 Cooperation 指导对话 Agent | 已确认；用户明确纠正并要求沿此边界设计 | 应用需要自己维护业务状态；出现跨应用真实复用需求时再评估公共业务设施 |
| 首版应用主动调用 API 和 Codex CLI | 已确认；用户明确暂不考虑宿主领取 | 没有主动调用接口的宿主不进入首版执行端 |
| 异步任务、输入/配置快照、统一结果、任务/尝试分离 | 按已讨论方案实现首版，已有契约与故障测试 | 需继续维护持久状态和兼容，并用真实业务核对质量 |
| 单根后台协调、文件聚合与可重建索引 | 首版已实现单写者与原子保存，故障测试已运行 | 多写者、长事件历史或查询规模使文件方式不适用时重评存储 |
| 原配置内技术重试，替代执行端由应用明确提交 | 首版已实现；未知执行暂停重派 | 牺牲自动切换便利；未来增加切换需明确费用、能力和结果未知语义 |
| 文本 API 首选 DeepSeek Responses，保留 OpenAI 协议适配器 | 用户已确认 DeepSeek、默认模型与凭据变量名；不表示账户密钥已具备 | 实际供应商协议和模型兼容性需真实调用验收 |

尚需在对应实施阶段配置：DeepSeek 后台凭据、转写能力及认证来源、真实早读时间/来源清单及部署。用户已明确早会当前仅本地导出，团队渠道后续接；早读来源与时间由用户提供。业务应用已在项目关联的独立工程中实现首版；这些未决项不被伪造为已配置。
