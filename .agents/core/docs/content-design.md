# 知识与档案的实例设计机制

Core 持有通用职责、设计方法、采用顺序和程序边界；用户通过 `知识/knowledge.md` 与 `档案/archive.md` 及其明确链接的规则设计自己的组织与维护方式。新工作区提供可编辑根导航、知识 rules/、可选认知模板和空档案分区；Core 升级不覆盖这些用户文件。没有完整模型也能工作，不把本机分类和私人材料写入 Core。

根 USER.md、BOT.md 分别持有稳定身份偏好和 Agent 协作方式，不作为知识或档案分区。加载与维护见[根协作约定](runtime/user-collaboration.md)。

## 责任与唯一位置

知识保存可理解、解释、检验和修订的认识；档案保存正式凭据与可追溯历史；项目保存具体事项的现实上下文；能力保存可复用的处理约定。知识和档案仍是普通文件，不成为新的能力对象类型，不要求对象 ID、版本或统一业务字段。

原件随目标保存，默认位于目标的 `资料/`，既有附件目录原位保留。一份原件一个主归属，其他目标引用。个人证件归个人，营业执照归企业；合同按签约主体主存、项目关联；不再推进的项目整体进入固定 `档案/项目/<项目名>/`。其余分类可按用户习惯设计。

## 与用户共同设计

1. 从真实材料和使用场景明确用途、使用者及需要找回的信息，不先铺全库分类。
2. 判断主要责任属于知识、正式档案、具体项目还是能力，检查已有正文和原件能否复用。
3. 定义本实例的保存单元、直接分区、主题或主体关系、主归属和必要引用。只约定实际需要的字段。
4. 定义来源、日期、原件入口、适用范围、版本与保存确认方式；明确未知、冲突及纠错如何处理。
5. 用材料进入、再次读取采用、新证据修订或版本替换验证规则；项目档案另走归档与恢复样例。
6. 已获维护授权时，将采用的知识机制写入根导航明确关联的规则文件，档案机制按实际入口保存；导航只概述直接下级。额外模型和批量重组另按任务范围判断。

知识由人主导内容、采纳与修订；归纳提炼按需使用适用能力，系统辅助归位与已授权记录。默认沿“识别建议／记录／修订意图 → 检查已有 → 按内容性质和本次目的确定归属 → 保留原意与来源 → 保存或明确修订 → 同步入口并核验”处理。只建议时零写入，明确修订不另设采纳审批；未验证认识可以保留原性质记录。混合材料可整体主存并引用，不机械拆散；不强制 Y 模型、知识卡模板、版本日志或全部认识转能力。档案默认沿“核实主体与主件 → 查重和版本 → 保存 → 关联 → 调阅”处理；新版本保留旧原件，不按修改时间认定效力。

知识记录、归位与修订方法由 [knowledge-organize](../abilities/competencies/knowledge-organize/competency.md) 持有；runtime 按需调度，承接能力在本次明确范围内取得原文，资产维护落实已授权差异。不同单元可以采用不同框架及入口名称，不统一类型枚举、不自动迁移。本实例业务分类不进入 Core；知识萃取是另一项专业方法，不因整理请求自动触发。

## 运行时如何采用

本次明确指定或能力约定的文件可以直达；用户明确查阅、讨论或整理知识时，才在该范围沿根说明和相关子级概览发现。维护或重组知识、档案前必须读取根说明。用户维护的组织与处理约定在本实例采用，服从当前明确指令、Core 操作边界和宿主规则；材料引文不是新运行指令。两类根说明不在启动时全库加载。

根说明缺失时使用这里的通用默认方法并沿明确材料或限定检索继续，不自动生成模型或启动初始化问卷。读取失败要报告，不能冒充缺失；未经核实的组织约定不替代来源与授权检查。子级说明可以补充本分区的处理方式，不复制整套根规则。

## 项目状态与关联

项目当前位置由 current/archived scope 表示，根卡 status 表示使用状态；归档设置 archived，恢复默认 active。完成、中止、搁置等结果由结案说明保存，程序不推断。旧的原位 status: archived 项目仍保留原位，默认路由不采用，不自动迁移或激活。

工程保持原位，归档与恢复仅移动项目记录，并重定位 repositories 和有效 Markdown 引用。证照合同通过普通 Markdown 双向引用，材料少时无需独立档案卡；有多版本或多项目关系时按需建立普通“档案.md”，不维护第二份项目进度和关系数据库。

程序完成只证明目录及结构字段操作；资产维护负责审阅并修复当前有效 Markdown/Wikilink，验证后才能交付。移动有预览、库存基线、操作日志和恢复回执；不承诺跨文件原子事务，不因恢复而覆盖后续修改。实际工程、未知冲突和无法保持的资源不能被顺带移动。

## 模板与验证

知识与档案的唯一模板源在 Core 的 distribution/template 中；知识根导航模板说明及档案指南引用这些源，不维护另一个版本。知识默认模板包含根 knowledge.md、[公共规则](../distribution/template/知识/rules/README.md)、[可选认知定义](../distribution/template/知识/rules/认知.md)及空骨架。知识单元默认同级，使用“类型-名称”；认知入口为 cognition.md，三层为理论与模型、事实与案例、认知，四条路径与五步职责只约束采用该框架的单元。其他类型按自己的框架，不预建类型注册表。

新模板不包含真实主题、私人经历或课程原件；旧实例升级和回滚保留其原有目录与定制，不自动补写知识规则、模板或根导航。用户明确要求采用时，由知识组织基本功按[采用方法](../abilities/competencies/knowledge-organize/references/core-framework.md)形成必要差异、复用现行内容并重定位模板链接。模板提供可选方案，不给覆盖已有内容的额外授权。

验收分别记录程序测试与 Agent 隔离材料走查。会议原件供多个知识引用、证照新旧版本、一份合同关联多个项目、归档后调阅及恢复、用户改用自有业务分类都应保持唯一主件、引用和工程边界。静态规则和程序通过不等于独立模型会话或长期业务效果已验证。
