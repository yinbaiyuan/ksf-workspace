# 备份、迁移与恢复边界

目标：保留能够恢复真实工作的内容与必要身份，同时避免把本机锁、活进程控制和凭据无差别复制到另一设备。当前没有通用的一键完整备份/导入/恢复命令。

## 先区分四种操作

| 操作 | 覆盖范围 | 主要限制 |
| --- | --- | --- |
| config export | 已声明可导出的配置 | 不含完整正文、信任、密钥和队列 |
| Core升级备份/回滚 | 系统管理文件及相应事务 | 不自动回退业务数据 |
| 应用迁移原件副本 | 某受管数据文件的转换前原件 | 不等于跨文件业务事务或允许降级 |
| 用户完整备份 | 用户正文、工程、设置和必要身份 | 由用户备份流程组织并实际恢复验证 |

## 备份前清点

阅读[数据地图](../reference/data-map.md)，列出用户根目录、项目/知识/能力/档案、独立工程及其Git历史、应用数据、AI/通信记录和必要身份。外部关联工程及能力源可能不在实例根内，外层Git也默认忽略repositories。

确认是否还存在在途应用、AI、通信或文件写入。需要一致快照时先在有效授权内排空并停止相应写入者；APP_BUSY时保留现场，不能强杀来伪造一致备份。

## 同设备恢复快照

1. 选定独立备份目的地，记录来源根、时间、系统/应用版本、文件清单和摘要。
2. 保存用户正文、独立工程、user-data，以及经清点确认必要的本机持久状态和身份。使用受控备份工具保留权限和原始字节。
3. 另记录当前OS自启动、环境变量凭据引用和外部目录，密钥使用合适的私密保存方式，不进入公开仓库或普通日志。
4. 恢复前停写，先恢复到隔离目录核对完整性和格式，再恢复实际入口。锁、PID和控制令牌不按快照直接复活。
5. 核对原件、项目入口、应用版本/数据、历史关联与关键业务；恢复工具退出成功不能代替实际可用性。

## 迁往另一设备

设备范围设置、进程控制、运行时安装和路径分别重建，不能把整个runtime-data直接复制后启动。通信节点私钥决定设备身份；通常新设备建立自己的节点，涉及保留旧身份时先明确迁移意图与旧设备停用条件，避免克隆身份并发在线。

聊天匿名身份依赖routing/v1/identity.key，不能与已有档案关联随意分离删除。应用runtime存储也可能是持久业务状态，不能因Git忽略就视作缓存。确需迁移这些内容时按所属模块核对身份、路径、版本和恢复依赖。

重新登记外部工程/能力源路径、配置本机程序及凭据引用、核对自启动，再检查真实业务。没有跨设备自动同步或通用合并服务，两个副本各自写入不能用目录覆盖解决。

## 数据格式与回退

Core更新回退核验兼容声明与已安装应用要求；受管JSON由应用显式prepareData转换，读取不迁移。不同schema回退可被拒绝；原件副本不会自动覆盖新数据。SQLite、外部数据库和跨文件业务事务由应用另行设计。

## 验收

至少做一次隔离恢复：核对摘要、来源、入口和实际使用；记录恢复时间、缺失材料、密钥/路径处理及未验证范围。在未完成恢复演练前，准确表述为“已备份”，不表述为“恢复已验证”。
