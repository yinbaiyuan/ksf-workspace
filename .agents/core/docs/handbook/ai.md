# AI交互：三条路径与结果采用

KSF中的AI交互有三条不同路径。上下文、身份和状态分别管理，不能以一次模型成功推定整个任务完成。

## 选择合适路径

| 路径 | 主要用途 | 上下文和状态 |
| --- | --- | --- |
| 宿主Agent | 持续对话、工具操作、分析和交付 | 宿主会话及按KSF规则读取的实际材料 |
| 应用AI任务服务 | 应用提交有界文本或转写任务 | 显式输入、执行配置快照、任务/尝试/结果 |
| Desktop原生会话桥 | 工作台项目与原生聊天接续 | Desktop持有线程，Core持有关联和操作回执 |

应用AI任务不自动运行KSF入口或加载当前聊天。能力方法需要显式作为材料提供；首版methodRefs仅接受空数组。原生Desktop的持久对话、工具和审批也不能用隔离CLI单任务替代。

## 配置前提

系统设置中先配置连接，再检查本地执行条件，最后配置profile。凭据只保存引用，服务进程必须实际获得对应环境。连接检查可能只证明格式、程序版本或登录状态，不等于真实付费请求成功。

没有可用profile时，应用报告缺配置，不伪造密钥或静默换供应商。模型名称和供应商兼容按具体协议及当前配置核对，不写死到业务流程。

## 应用任务的完整顺序

1. 应用保存业务运行、输入版本和稳定幂等键。
2. 提交明确instruction、inputs、profile及outputSpec；身份由宿主绑定。
3. 保存返回的aiTaskId，退出短RPC，再观察事件和快照。
4. succeeded后读取经过校验的结果，核对业务质量与来源。
5. 将已采用的结果revision与业务步骤一起保存，幂等推进。

提交后、保存编号前中断时，用同键同请求恢复原任务；同键不同内容报冲突。UI订阅结束不取消任务。生成失败候选不能作为成功结果采用。

## 状态与未知结果

| 状态 | 用户或应用应做什么 |
| --- | --- |
| queued/running/retry_wait | 展示真实进度，观察原任务 |
| succeeded | 读取成功结果，再做业务验收 |
| failed | 显示错误及下一步，保留业务编号 |
| cancelled | 请求取消；未确认远端停止时仍可能占额度或产生费用 |
| reconciling | 原执行结果未知，保留编号等待核对 |

API发送后断线、5xx或响应不完整可能进入未知状态。没有可查询上游结果时，当前没有自动API对账或人工回填通道。CLI监督回执可支持原尝试恢复；不能手改文件释放额度或用新任务绕过未知结果。

## 材料和输出

小文本可以内联，大材料先登记，使用materialId与摘要。上传限制、适配器限制和供应商实际接受范围分别核对；上传成功不等于转写完成。

JSON输出使用服务支持的有界结构子集。结构校验只能确认输出契约，不能证明事实正确。用量和费用只记录可取得的数据，未知为null，不宣称完整账单。

## Desktop会话

创建、发送、补充、停止和回答均使用稳定operationId。派发后断线不能重发，先查询原操作和原生历史。普通问题及计划可由工作台支持，权限审批仍在原生宿主处理。

Desktop接入包含按版本验证的私有协议适配，平台可用不代表任意客户端版本兼容。缺少可靠Hook时显示轮次未确认。[兼容表](../reference/compatibility.md)与[会话协议](../codex-conversations.md)分别持有边界。

## 验收

分别核对接口、真实供应商、业务采用和用户目标。虚构材料模拟测试不等于真实账户通过；原生会话创建成功不等于重启恢复和全部工具都已验证。开发接口见[统一AI](../app-development/ai.md)，实例配置见[接入说明](../ai-task-service-usage.md)。
