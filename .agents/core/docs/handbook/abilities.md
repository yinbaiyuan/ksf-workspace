# AI能力：定义、采用、维护与验证

能力保存可复用的工作方式。Agent实际履责，定义提供责任和方法，程序提供工具与确定性约束；三者协作但不能相互冒充。

## 四类对象

| 类型 | 主要问题 | 最小内容 |
| --- | --- | --- |
| 协同Cooperation | 多项独立责任怎样配合完成结果？ | 分工、依赖、交接、返工及整体完成条件 |
| 搭档Partner | 谁承担这一类业务责任？ | 使命、职责、协作方式、基本功配置 |
| 基本功Competency | 专业处理和操作怎样做好？ | 输入、方法、操作、判断标准、案例及支持 |
| 数据包DataPackage | 当前情境需要哪些成组依据？ | 内容、来源、用途和读取条件 |

单个搭档有多个步骤，不必创建协同；已有基本功能承载新方法时优先完善。项目保存具体事实，知识保存可独立理解的认识，二者不是第五、第六类机器能力对象。[对象详解](../objects/overview.md)提供判断例子。

## 从发现到采用

```sh
.agents/ksf context capabilities --json
.agents/ksf partner --help
.agents/ksf competency --help
```

context返回完整性、错误及有效协同/搭档摘要，程序不做语义选择。Agent先核对明确要求和有效旧安排，再按项目预设及全局规则选择候选；读取正文与必要依赖，实际采用时读取该能力设置及聊天状态。

发现、阅读、选择、采用和有效果是不同事实。references只是引用，未实际读取不能说已加载。继续任务复用有效安排，目标、范围、来源或依赖变化时重审受影响部分。

## 来源与版本

能力可以来自Core、个人区或关联的独立Git能力源。默认有效解析按个人、匹配源、系统处理；多个源匹配同ID可能产生歧义，不能按顺序或最高版本猜选。固定入口保护不受个人同名对象替代。

ID表示稳定身份，版本表示定义及契约变化，个人user_revision跟踪个人修订，definition_digest核对实际正文。精确引用需要实际可解析的id@version。来源对象的依赖遵守源绑定规则，不能随意拿其他源或个人覆盖补齐。

关联能力源读取其当前工作树，包含未提交修改；它不是安装副本或提交锁定。拉取、提交、分享和公开PR有各自授权，见[能力源协议](../sources.md)。

## 创建或改进能力

1. 从真实重复任务和质量缺口提出需求，检查现有对象能否复用或完善。
2. 明确责任、输入、方法、失败处理、结果标准与依赖，形成可审阅定义。
3. 按明确授权保存，检查元数据、精确引用和附属资源。
4. 用正例、反例、缺资料及中断情境验证，再在真实任务采用。
5. 人依据反馈决定修订，保留失败和适用范围。

程序check证明结构、身份和引用，不能证明专业方法有效。自动评测、当前Agent走查、独立会话和真实业务验收分别报告。

## 设置、状态与沉淀

对象user-data按稳定ID保存长期普通设置；chat状态按聊天与能力空间保存当前工作所需值。两者都不保存凭据或替代项目成果，也不产生新的授权。缺设置可以使用已声明默认，不为采用能力强制初始化。

一次工作成果可以促使能力修订，但要有具体定义变化和后续采用证据。不能把程序修复、模型参数变化或一次成功笼统称为能力已进化。
