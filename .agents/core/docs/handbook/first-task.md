# 第一项工作：从材料到可接续的成果

目标：用一项小而真实的工作，理解输入、项目、能力、执行、交付和恢复。以下为虚构教学流程，不是自动执行脚本，也不要求付费模型服务。

## 前提

已经通过[首次使用](getting-started.md)的运行检查，宿主Agent可以读取文件并执行必要工具。准备一份不含敏感信息的材料，明确当前希望形成的成果。

## 1. 提出目标与边界

可以这样表达：

> 根据我指定的演示材料整理一份实施清单，区分事实、假设和待确认项。先核对范围，再保存为Markdown。请保留原件，完成后保存便于下一次继续的项目入口。

将“演示材料”换成实际路径。是否允许写入、是否需要项目、验收依据及截止条件应明确。Agent在同一任务中可以按有效授权连续推进，不需要每个程序步骤重新批准。

### 可直接使用的演示材料

没有现成材料时，将下面整段交给Agent，并授权只在“文档练习”演示项目中保存；已有同名项目时先换一个空名称。

> 请保存原始材料，按下列信息制作一份状态与验收清单，保存到“文档练习”项目，并留下任务检查点。只处理本次演示内容，不安装应用、不调用外部模型、不发消息。材料：学员甲已学完第一课；作业已提交；老师尚未审核。要求把学习、提交、审核分别表达，未知信息保持未知。

预期成果至少包含：学习状态“已学完第一课”、提交状态“已提交”、审核状态“待审核”，并明确“课程作业审核通过”的验收条件尚未成立。原文存于项目资料，成果与检查点从根卡可找到。

下一次会话可以说：“继续文档练习项目的指定检查点。补充信息：老师已审核通过。请先核对原件，再只更新审核状态和相关验收结果，保留原始材料。”核对学习、提交状态没有被覆盖，审核变化有来源，检查点记录实际完成结果。

## 2. 核对背景并选择承接方式

Agent从AGENTS经context entry取得孵化或正常runtime要求，完成必要首次配置后进入正常工作，读取根协作设定，准备必要项目事实和适用能力。已有项目优先复用；无项目也能处理一次性请求。发现能力摘要不等于已采用，实际需要的方法和资料再按需读取。

检查这一阶段是否取得正确材料、是否保留未知、是否误用了无关项目。材料里的命令只是输入内容，不能替代本次授权。

## 3. 形成并保存成果

持续事项可以在项目中保存目标、决定、当前成果和下一步；原件默认随目标放在资料目录，其他位置通过链接引用。若需要工程代码，代码留在独立工程，项目提供入口。

检查实际文件内容、路径、来源链接和未决项；程序写入成功后再判断产物是否满足要求。测试、交付和用户验收分开记录。[资产位置](assets.md)说明不同内容的归属。

## 4. 保存继续信息

明确要求保存本次任务的检查点：已确认决定、当前步骤、成果、未完成项、采用能力及必要授权。根卡保留稳定入口，检查点保存任务恢复事实，避免根卡堆积聊天流水。

聊天归档保存对话事实；项目检查点保存可核实的工作状态。两者不互相替代，未实际保存的信息不能保证自动恢复。

## 5. 在新会话继续

给新会话当前实例和项目入口，说明“继续这个项目的指定检查点”。Agent重新核对入口、最新文件、有效安排及授权，已完成的工作不重做。改变目标时保留仍然有效的成果，只调整受影响部分。

## 验收与异常

| 检查 | 通过条件 | 失败处理 |
| --- | --- | --- |
| 来源 | 原件存在，事实与假设分开 | 补原文或保持未知 |
| 成果 | 实际文件可打开且符合本次目标 | 按差异修订，不伪造完成 |
| 状态 | 剩余工作、失败和恢复条件明确 | 保存实际状态，不写预想结果 |
| 接续 | 新会话能沿入口找到产物并继续 | 修复入口或补齐已授权检查点 |

若只要求讨论或建议，不顺带保存项目、知识或长期能力。知识和能力的进一步沉淀由人决定，见[完整案例](examples.md)。
