# 完整案例：工作产物、能力与反馈怎样连接

以下为可在隔离材料中演练的教学案例，采用虚构项目和内容。它们示范检查方法，不作为历史交付或长期效果证据。

## 案例一：把资料整理成可继续的项目

### 初始材料与人的决定

准备三条演示需求：记录课程学习、保存作业、追踪审核。人确认“学完”“已提交”和“审核通过”分别成立，不能只用一个完成勾选。

要求Agent保留原件，先做状态定义与实施清单，保存为演示项目的成果，并留下恢复入口。项目根卡保存目标和当前决定；材料主件随项目保存；若开发应用，源代码进入独立工程。

### 实际工作与验收

Agent选择可用设计方法，检查输入、给出状态与操作，再按授权保存。检查产物是否分别表达三种事实、是否保留未知、是否能从项目找到材料和下一步。

新会话沿指定检查点继续，重新核对文件和授权。故意删除一个导航链接，再恢复并验证入口，检查系统是否诚实报告缺口；不要修改真实用户项目来演示。

### 哪些内容进入积累

本项目的课程状态留在项目或应用。关于“完成条件应独立识别”的解释可以形成知识；若希望反复用于设计，再明确设计一项方法。后者需要真实能力定义变化及后续采用，不能只写“已沉淀”。

## 案例二：开发一个按需应用

### 目标与实现

从SDK模板创建演示窗口，显示计数并原子保存。界面展示和后台业务分开；用两个窗口更新同一记录，验证并发条件或锁防止丢失。

需要持续业务时再声明后台策略；只是读取系统文档时不需要应用后台。模板构建、包检查、隔离安装与真实窗口操作分别核验。

### 失败与修复

引入虚构损坏数据或旧schema，确认保留原件并显示诊断，不自动清空。修正准备逻辑后重试，再核对历史数据与在途操作。把错误输入、修复差异和实际复测保留为证据。

## 案例三：两个实例合作

### 准备与送达

双方在隔离应用中明确配对和通道授权。A发送一份虚构需求及附件，保存原操作编号，B核对材料并持久接管。

B可以忽略，也可以接受后在本地形成成果。需要回传时显式发送另一条结果消息。A按最初要求验收，不能把delivered当作委托完成。

### 恢复演练

在已受理后断开观察连接，查询原编号；重复交付由应用去重。应用显式停止时不能被消息恢复；重新start后再按原状态继续。不要用真实外部动作来试验未知结果重复执行。

## 怎样评价飞轮

| 问题 | 应保留的证据 |
| --- | --- |
| 保存了什么 | 实际原件、决定、成果及入口 |
| 改变了什么 | 知识、能力或程序的具体差异 |
| 后来用在哪里 | 另一项真实工作中的明确采用 |
| 效果怎样 | 验收结果、反例、代价和剩余问题 |

程序测试、同一Agent走查、独立会话、真实用户使用和长期对照分别表达。只有教学演练时，不能声称已取得真实业务或长期量化收益。
