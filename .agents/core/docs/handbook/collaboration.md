# 跨实例协作：可靠送达与接收方自主处理

人机共同体以人为主体，人与AI持续协作、积累，并作为整体参与外部合作。技术节点提供寻址和通信，业务责任仍需双方明确。

## 前提与身份

默认每设备一个实例。双方主服务在线、网络可互访，并启用所需通信入口。mDNS发现仅提供局域网候选，不等于已经信任；名称不证明人员身份。

通过用户明确请求和同意建立配对，核对双方提示及必要指纹。便捷配对只授予此次应用通道的消息与激活授权，不开放其他应用、Agent或本机AI/工具执行。

## 一次合作的顺序

1. 发送方表达任务目标、背景、材料、要求和期望交付；不把仅发送文本当成已委托成功。
2. 公共通信核对来源、目标、通道、容量和材料摘要，取得持久接收回执。
3. 接收应用可以被授权激活以保存待处理记录并确认接管。
4. 接收方自主决定继续、忽略、只在本地完成或按业务流程回传。
5. 需要合作承诺时，双方明确责任、变更、完成条件和验收，再核对实际结果。

普通内网消息由消息应用查看、下载和回复；应用任务由对应应用组织。当前不建设统一收件中心、公共委托协议、强制答复或跨节点任务状态机。

## 不能混同的状态

| 事实 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 发现 | 有一个候选节点地址 | 人员身份可信 |
| 配对 | 相应节点身份与通道获得确认 | 任意本机执行授权 |
| delivered | 对端完整校验并持久收到消息材料 | 人已读或答应处理 |
| acknowledged | 应用已持久接管 | 业务执行完成 |
| 本地接受/完成 | 接收方业务状态 | 已回传或被发送方验收 |
| 结果回传 | 另一条消息已发送 | 成果已达到要求 |

## 消息、材料和编号

发送地址由nodeId、端点和通道组成。端点可以是应用或持久Agent收件箱；原生宿主聊天ID不是公开地址。Agent收件原件可以等待查询，但无宿主适配器时不能承诺远程自动唤醒任意会话。

长文本和附件使用不可变清单、部件和流式传输。稳定messageId表示一次逻辑消息，operationId表示一次发送操作；重试或对账复用原内容和材料引用。业务taskId、requestId与本地appRunId分别关联目标、请求和运行，Core不解释业务步骤。

## 失败和恢复

未取得回执时可能failed或unconfirmed。连接失败可明确未发送；提交后响应丢失不能推定未收到，先reconcile原操作。cancelled只有在确认提交之前终止时成立，不能撤回对方已收消息。

接管确认按至少一次设计，应用需持久去重。等待反馈要保存允许来源、请求编号和处理游标，反馈先到时可补查。暂停、停用、显式停止和本地授权不能被远程文本绕过。

双方离线时不提供网络代存转发或自动补发。平台的本地投递重试是处理已收到事件，不是离线网络队列；机器停机期间不继续收信。

## 核验

先验证收发、附件摘要及回执，再验证应用接管、接收方决定和业务成果。模拟通信或SSH回环不能代替双设备真实网络验收。完整接口、容量和权限见[通信与工作流](../app-development/communication.md)、[通信CLI](../cli/communication.md)。
