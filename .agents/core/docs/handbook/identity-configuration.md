# 身份与配置：人、实例和设备

目标：知道每个名称与身份的用途，找到正确设置入口，并在并发编辑时保留已确认内容。

## 身份地图

| 名称 | 作用 | 主要位置与限制 |
| --- | --- | --- |
| 用户与协作偏好 | 称呼、语言、时区、稳定要求 | USER.md；普通原文，不自动抽取双写 |
| Agent协作定位 | 如何推进、沟通和接续 | BOT.md；不是宿主登录或权限 |
| 本地技术身份 | 名称、邮箱、能力命名空间 | identity配置；不验证远程账号，不改已有对象ID |
| 实例名称 | 当前KSF的显示名称 | instance配置；不改变目录、版本或通信身份 |
| 设备名称 | 内网显示与配对提示 | 本机device配置；允许重名，不是身份凭据 |
| 通信节点身份 | 密钥、证书、nodeId及指纹 | 通信服务持有；改显示名称不更换身份 |
| 人机共同体 | 人与AI组织成整体参与合作 | 协作概念，不等同于一个显示名称或证书 |

默认一设备一实例。多个窗口、CLI和Agent复用当前实例，不能依据窗口名称识别另一套用户数据。

## 配置入口与作用范围

工作台“系统设置”和ksf config共用配置服务。各领域仍由所属模块保存与校验。系统设置展示能力独立设置；应用业务设置由应用菜单的“设置…”进入，只有应用注册后显示。

读取时区分保存值、默认值、有效值、作用范围、版本和生效结果。AI配置供新任务使用，已接受任务保留快照；USER/BOT在下次读取时采用；自启动开关不等于当前服务已停止。

## 安全地修改实例名称

先读取当前版本：

```sh
.agents/ksf config read instance --json
.agents/ksf config check instance --data '{"name":"演示工作区"}' --json
.agents/ksf config write instance --data '{"name":"演示工作区"}' --if-match missing --dry-run --json
```

最后一条仅适用于read确认为missing的初次创建。已有值必须把missing换成实际etag。核对预览后去掉--dry-run保存，再read核验。Windows建议将JSON保存在文件，通过--from传入，避免命令行引号差异。

## 并发、重置和应用失败

etag标识读取时的完整文件内容，revision表达相应记录的修改序号。支持CAS的接口在锁内重新核对版本；别的窗口保存后，旧etag应报冲突。保留自己的草稿，比较当前值，再基于新版本形成最小修改，不能盲换etag重放旧内容。

JSON写入更新提供的顶层字段，嵌套值整体替换；reset移除覆盖，null仍是一个保存值。USER/BOT没有reset。不同配置领域没有整体事务，部分成功要逐项读回。

保存成功但应用失败时，保留新保存值和错误，再用最新版本重试apply；apply只应用已保存值，不接收另一份内容或擅自重启主服务。

## 导出与核验

config export默认排除设备信息、密钥、通信信任与授权、正文、队列及不明敏感性的能力数据。显式选项可包含USER/BOT或设备信息。导出不是完整备份，恢复按[备份与迁移](../operations/backup-migration.md)分别处理。

核验应同时检查保存值和实际生效状态；后台不可用时不能把磁盘值说成运行中有效值。完整领域表、HTTP与错误语义见[统一配置中心](../configuration-center.md)和[config CLI](../cli/config.md)。
