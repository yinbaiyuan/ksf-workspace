# 工作台与应用：界面、后台和生命周期

工作台提供人的操作入口，主服务承载公共能力，应用持有业务流程。关闭窗口、退出应用、停用应用和停止主服务有不同后果。

## 打开与日常导航

通过ksf open启动或复用主服务并打开工作台。桌面提供分组、应用启动图标和功能卡片；同一应用可以有多个窗口，每个窗口有自己的导航、滚动和临时状态。顶部活动应用菜单提供关于、可选设置和退出。

提供窗口的应用安装后自动在主页添加一个1×1启动图标，首次启用此机制时将已有应用补到当前桌面。启动图标可拖动，进入桌面编辑后可移除，再从Dock“所有应用”阵列的右键菜单选择“添加到桌面”恢复；同一分组每个应用最多一个启动图标，不限制该应用的功能卡片数量。删除图标不会卸载或停止应用，刷新和应用升级不会补回；卸载会移除各分组的启动图标，重装则按新安装添加。主页改名后保留原定位，删除主页后重新建立。

桌面图标和卡片的名称采用白字、细描边和柔和投影，长名称省略显示，悬停可查看全名。名称区域仍可拖动。“添加卡片”只列功能卡片，应用图标通过“所有应用”的右键菜单添加到当前分组；已有图标时显示“已添加到桌面”。

Dock常驻“所有应用”和“显示桌面”按钮。“所有应用”在按钮正上方展开已安装应用图标阵列，只有图标与应用名称，较多时在框内上下滚动；再次点击按钮、点击外部或按Escape收起。删除桌面图标后仍可从这里打开应用，已停用或无窗口的应用可进入商店管理。运行图标只显示当前页面仍有窗口的应用，多个窗口合并一个图标，最小化时保留，最后一窗关闭后移除。窄窗中间的运行图标可横向滚动，常驻入口保持可见。

时间左侧按实际后台运行状态显示应用小图标，窗口关闭后后台仍运行则继续显示；点击可查看状态、打开应用或进入活动监视器。窄窗通过“更多”菜单收纳图标，断连时标记状态未知；活动监视器未安装时进入“运行与后台”设置。

“系统设置”管理实例与公共能力；应用菜单的“设置…”由应用实现。桌面布局和外观由实例配置保存，焦点和临时导航属于页面会话。旧浏览器偏好需明确迁移，不自动覆盖实例设置。

系统设置以居中窗口显示，左侧选择分类，右侧查看分组表单；窄窗通过分类列表、页面和详情逐级返回。长原文、连接、能力及运行信息通过详情打开，技术数据默认折叠。手动表单离开前会保护未保存的修改；保存和生效状态分别显示，外观参数继续即时预览并自动保存。

## 两个维度理解应用

| 维度 | 选择 | 行为 |
| --- | --- | --- |
| 界面 | 窗口、卡片、没有界面 | 界面是访问方式，不决定是否需要后台 |
| 后台 | 无、on-demand、resident | 无后台只加载前端；按需启动或随主服务常驻 |

KSF手册阅读器没有应用后台。终端按窗口租约管理资源；需要持续执行的业务由应用后端承接，不能只放在前端定时器。纯后台应用也能有CLI和管理入口。

## 启动和停止

| 动作 | 结果 |
| --- | --- |
| 关闭浏览器 | 结束观察及界面租约，不停止有持续需求的后台 |
| 关闭一个窗口 | 清理该窗口资源，不影响其他窗口 |
| 退出应用菜单 | 关闭该应用窗口；后台仍按自身租约和策略决定 |
| app runtime stop | 保存本机显式停止意图，新界面/CLI/消息不自动撤销 |
| 停用或卸载 | 应用入口和激活受限；数据按应用规则保留 |
| service stop | 主服务排空后停止，期间不能继续接收网络消息 |

on-demand后台在没有界面租约、调用、任务、保活或手动运行需求时退出。tasks.run保护本进程在途任务；持久retain表达重启后仍需运行；业务恢复和幂等回执由应用负责。

显式停止后使用start或restart恢复；应用商店停用还需先启用。停止或升级遇到在途工作会等待或报APP_BUSY，不能把强制终止当作业务已取消。

## 安装、升级和版本

应用商店展示随附及已配置来源，可导入受信任安装包。安装前核对ID、版本、来源、能力、最低Core及数据要求。摘要校验内容，不证明发布者可信；当前应用代码运行于同一系统用户边界。

应用包不可变，同版本不能覆盖不同执行内容。运行中升级保留旧窗口和操作，排空后切换；数据准备发生在新业务激活之前。不兼容的schema或宿主要求会阻止安装、启动或回退，不自动拿迁移备份覆盖新数据。

## 常用应用与缺口

KSF项目现为 Core 内置默认应用，维护源位于 applications/projects；随附安装包可离线安装，旧独立包沿用 com.ksf.projects 身份升级，项目原文和应用设置保留。

KSF项目负责定位项目事实；KSF文档负责原位浏览编辑；KSF仓库负责工程协作；终端提供真实Shell；KSF手册负责只读阅读。其他业务应用按各自使用说明工作，不推定它们提供全部Agent命令。

KSF知识与KSF能力目前为 Core 内置占位应用，只提供图标和空白窗口，尚无业务功能。

KSF飞轮提供工作回顾、待处理建议与原始对话。启用每日回顾后按配置生成报告，用户审阅后归档已结束且覆盖完整的对话；正式资产修改仍由用户决定。采集完整、已回顾和已归档分别展示，见[每日工作回顾](../daily-work-review.md)。

Agent调用应用前需有用户对具体应用的明确选择，读取当前包CLI文档和摘要后再调用。主动业务CLI可以启动主服务；运行状态和离线数据检查保持只读。完整规则见[应用CLI](../app-development/cli.md)。

## 核验和故障

先看主服务，再看应用是否安装启用、显式停止、数据停放及租约，最后核对业务回执。界面资源损坏不应停止管理API和应用后台。见[后台服务](../runtime/service.md)及[故障处理](../operations/troubleshooting.md)。
