# 认知与资产：保存位置、来源和修订

KSF按内容承担的责任组织资产。知识与能力都供人和AI使用，不能简单按读者划分。原件、事实、假设、认识、决定和成果需要保留各自性质。

## 内容放在哪里

| 内容 | 主位置 | 使用方式 |
| --- | --- | --- |
| 待处理输入 | 收件箱 | 先核对用途、主体和来源，再按明确要求处理 |
| 可独立理解的认识及依据 | 知识 | 保存适用条件、来源、反例和未知 |
| 具体工作的目标和当前事实 | 项目 | 根卡连接决定、任务检查点和成果 |
| 正式资料与历史 | 档案 | 核对主体、效力、版本与引用 |
| 工程代码及工程产品文档 | 独立仓库 | 工程自行管理Git与备份，项目关联入口 |
| 可复用责任、方法和操作 | 能力 | 按四类对象及专业设计规则维护 |

原始材料默认随目标保存在资料子目录。一份原件有一个主归属，其他目标链接引用。已有原件位置和附属资料目录保持原位，不因为介绍新模型就自动搬迁。

## 记录与修订的流程

1. 明确用户表达：只建议位置、直接记录、修订，还是处理后保存。
2. 读取目标与来源，核对当前实例的知识或档案组织约定。
3. 找到唯一现行正文，比较重复、冲突和已有有效内容。
4. 在授权内保存最小差异，保留来源与历史性质，同步必要导航。
5. 重读内容及入口，说明实际保存与尚未验证部分。

“放哪里合适”只提供建议；“记录下来”授权明确内容的保存；“提炼后保存”包含相应内容处理。保存认识不等于证明认识正确；文件存在也不代表未来任务已自动采用。

## 知识框架可以定制

新模板提供可编辑知识根说明、公共规则和可选认知骨架；现有实例可以使用自己的分类和模型。Core不强制本实例的Y模型成为所有用户的目录结构。维护前读取根说明，普通工作不加载整库知识，也不自动扫描背景。

知识无需全部转换为能力。对方法的解释和证据可以独立成为知识；当希望反复运用它完成处理时，再设计相应基本功。完整边界见[对象综述](../objects/overview.md)及[知识设计机制](../content-design.md)。

## 三种记忆与接续位置

| 位置 | 保存什么 | 不保证什么 |
| --- | --- | --- |
| 项目任务检查点 | 本任务当前步骤、产物、决定及恢复条件 | 外部动作必然完成或授权永久有效 |
| 对话档案 | 实际采集的消息及路由事实 | 新会话会自动读完全部历史 |

用户要求只读、只讨论或不保存时，不写业务资产和检查点；对话归档按其独立隐私规则处理，见[任务推进](task-execution.md)。

## 归档、恢复与备份

项目归档移动项目记录，不移动其独立工程；恢复要重新核对最新事实和链接。正式证照、合同的旧版按规则保留，不按修改时间猜效力。跨文件移动和入口修复各自核验，不能声称任意文件的原子事务。

外层KSF Git通常忽略repositories容器，工程历史须另备份。程序设置与业务正文分开，实际类别见[数据地图](../reference/data-map.md)。
