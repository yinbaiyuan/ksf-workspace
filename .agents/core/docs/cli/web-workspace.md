# 文档与 Git 应用

本地工作台包含对话、文档与 Git 仓库三个应用。文档直接编辑当前 KSF 原文件；Git 应用管理当前实例和 `repositories/` 内已存在的仓库。界面操作不经过 Agent，不自动代表 Agent 执行、提交或对外发布。

## 标准应用窗口

本章是共享窗口框架承载的现有及新增应用的唯一窗口规范。系统设置弹层和模态对话框沿用各自结构。

标题栏无应用操作单元时默认高 **40px**；共享工具栏位置有按钮、链接、输入框或其他交互单元时，高度为 **68px**，承接现有的上图标、下文字布局。红黄绿窗口按钮、应用名、普通上下文文字和空工具栏容器不触发增高；操作单元挂载或移除时自动切换，不按应用名称写例外。从左至右为：**红黄绿窗口按钮 → 应用名 → 当前对象与导航 → 弹性空白 → 应用快捷操作**。应用名紧邻红绿灯且位置稳定；仓库名、文件名和聊天归属属于后续上下文。采用 [Apple 统一工具栏的组织逻辑](https://developer.apple.com/tutorials/app-dev-training/working-with-toolbars)，应用名位置按 KSF 的明确约定固定。

快捷操作与红绿灯同一行；应用内容不再重复窗口级工具栏，文件筛选、提交筛选和编辑区局部工具保留。快捷按钮默认采用**上图标、下文字**的纵向结构，提供悬停提示、数量角标和执行状态；这是现有及后续应用的默认设计。窄窗保留可见按钮文字，按优先级将放不下的动作放入**双箭头溢出菜单**；菜单保持原动作顺序，支持方向键、Home／End、Escape 和焦点返回。

标题栏不显示左半屏、右半屏和窗口管理三点菜单，也不显示“当前窗口／对照窗口”。红绿灯保持关闭、最小化、最大化／还原；窗口排列、新开对照窗口、移动与调整大小从 Dock 右键菜单访问，键盘可用 Shift＋F10 打开。标题栏空白和应用名可拖动、双击最大化；按钮、菜单、链接、输入及编辑区域不触发窗口拖动或双击最大化。

应用内对象使用共享右键菜单，并支持 Shift＋F10／菜单键、方向键、Home／End、Escape、边缘避让及焦点返回。同一时刻仅打开一个对象菜单，菜单随所属窗口隐藏或失焦关闭。Git 仓库、文件、工作区节点、提交、分支、标签、远端引用和贮藏提供对应操作；文档目录、标签和局部工具区以及对话列表同样接入。右键操作复用原队列、版本核验和确认流程，批量文件操作明确数量；原有按钮入口和文本编辑区域的系统菜单保留。

共享 `WindowToolbar` 由应用提供对象与导航内容、动作列表，动作支持图标、名称、快捷键、数量、禁用、按下和执行中状态。窗口框架持有工具栏挂载位置，每个窗口独立接收自己的应用操作；隐藏、最小化和关闭不会串用其他窗口的操作。新增应用复用该接口及现有 React／Radix／Lucide／react-rnd，不另建标题栏。

Git 默认保留最左侧**仓库列表**，包含搜索、收藏和状态摘要，选中仓库后仍显示。条目固定为紧凑两行：名称，以及分支与状态摘要；搜索框后提供带选中态的“只看有变更”按钮。发现、更新进度及读取问题入口放在固定高度的底栏，与显示／总仓库数共用一行，不在列表顶部插入提示。顶部侧栏按钮只控制仓库列表的显隐；标题栏仓库名为普通上下文文字，当前分支紧随其后，以轻量分隔和次级文字区分，不提供下拉选择。窗口不足 900px 时仓库列表通过该按钮打开抽屉，选择仓库后收起。列表右侧的当前仓库工作区采用**仓库导航｜提交图｜节点详情**。仓库列表默认 220px、仓库导航默认 200px；两列的右侧分隔线支持独立拖动、方向键微调（Shift 加速）、Home／End 触达边界、双击恢复默认，拖动中 Escape 取消。完成调整后按实例保存列表宽度，按实例和仓库保存导航宽度；窄窗临时收紧显示宽度，恢复窗口后沿用用户偏好。仓库导航显示文件状态、历史、分支、标签、远端分支、已贮藏；它与仓库列表独立，应用窗口不足 1000px 时由内容区“仓库导航”按钮打开抽屉；拖宽仓库列表不会单独触发导航折叠。动作顺序为提交、拉取、推送、抓取、分支、合并、贮藏、设置、刷新。提交动作选中工作区并聚焦说明，实际提交仍经过核对。

提交图默认占导航外区域约 40%，分隔线可拖动或键盘调整。右侧宽度达到 680px 时文件列表和差异左右排列，否则上下排列；应用窗口小于 1000px 时导航进入抽屉，扣除两列侧栏后的内容区小于 720px 时提交图和详情切换，保持选择与滚动。无 SHA 的工作区节点置于提交图顶部，仅当实际 HEAD 在当前图中出现时绘制连接；有修改默认选择工作区，否则选择 HEAD，首次提交前选择工作区。文件状态选择工作区，历史恢复上次真实提交，单击引用浏览相应历史，检出等写操作通过明确菜单进入核对。贮藏从左侧选择并在右侧预览和恢复，其内部提交不混入普通提交图。仓库列表继续渐进加载，只请求所选节点与文件的详情。

## 应用和文件

`/?app=markdown&path=项目/示例/说明.md` 打开文件；`/?app=git&repo=<id>` 打开仓库。旧 target/task/turn/project 与 `?view=routes` 链接保留。Dock 按应用显示窗口，多窗口共享同一文档缓冲区，目录和大纲按窗口宽度收起。

文档树根层只按顺序显示 `.agents/`、`@收件箱/`、`档案/`、`能力/`、`项目/`、`知识/`、`repositories/`、`AGENTS.md`、`BOT.md`、`README.md`、`USER.md`，缺失条目直接省略，名称沿用磁盘原名。名单集中维护在 `workspace-files.js` 的 `ROOT_ENTRIES`，没有虚拟目录或设置入口。此规则只整理根层显示，子目录、搜索、最近打开、原链接与文件读写仍按现有规则工作；新增非白名单根条目默认不显示。

Markdown 使用 CodeMirror 6，提供即时预览、源码、分栏和阅读。支持 GFM、代码高亮、本地图片、相对链接、KaTeX 与 Mermaid。即时预览中的链接可 Cmd/Ctrl+单击打开；阅读和分栏预览直接点击链接。HTML 不执行，远程图片不自动加载。图片粘贴、拖放和文件选择写入文档同级 assets，返回相对链接。

停笔 800 毫秒后保存，输入法组字期间暂停；Cmd/Ctrl+S 立即保存。文本编辑按字符变更更新原文，保留 BOM、原有换行和未修改部分。超过 1 MiB 的文档降级源码模式，UTF-8 文本读取及保存上限 8 MiB，图片上限 20 MiB。只读文件不触发保存。

普通用户文件可以编辑。`.agents` 系统源码、根 AGENTS.md/README.md/.gitignore 和 .github 默认只读，普通文件可显式解锁，解锁仅在当前服务会话有效。`.git`（含大小写别名）、凭据（包括 .git-credentials/.npmrc/.netrc、私钥及 .ssh/.aws 等目录）、`.agents/runtime-data` 不开放内容；自动生成的 Codex 对话档案只读。文件服务拒绝符号链接、绝对路径和越界。目录树与搜索跳过依赖、构建和缓存目录；repositories 不因父 KSF 的 Git 忽略规则而被隐藏。

自动保存是乐观并发控制：读取内容摘要，写入前重新核对，并通过同目录临时文件、fsync 和原子替换发布。多窗口与本服务的 Git 操作共享写入协调器；不声称能锁住不遵循本服务锁的外部编辑器。检测到磁盘变化时返回 409，保留草稿并暂停保存，界面提供基线、磁盘与合并结果。恢复草稿放浏览器 IndexedDB，按实例隔离；数据库不可用或配额不足时明确显示，不能当作已安全保存。

支持新建目录/文件、重命名及移动普通文件和目录。移动采用独占目标发布，不覆盖同名目标，不批量改写引用；目录移动先保存相关缓冲区、核对目录版本并检查整个子树，不移动根分区、仓库、系统或含受保护内容的目录，不跨磁盘复制目录。打开的文件窗口同步更新路径。首版没有永久删除入口。

## HTTP 契约

全部响应不缓存，仍只监听 127.0.0.1。Host/Origin 必须匹配本服务；POST 还必须使用 application/json、当前会话的 `X-KSF-Token`，浏览器跨站请求拒绝。不提供 CORS、任意路径静态托管或通用 shell 执行。

本地服务重启会更换会话令牌。页面收到写入前的会话失效拒绝时，重新获取会话；确认仍是同一实例且令牌已变化后，用原正文与版本自动重试一次。并发请求共享会话刷新。网络中断、文件冲突和其他操作失败不自动重放；切换到其他实例时停止写入并保留原实例草稿。

JSON 成功为 `{ok:true,data}`；失败为 `{ok:false,error:{code,message},data?}`。文件版本和仓库版本是 opaque 字符串，不由客户端构造。查询仅 GET/HEAD，变更仅 POST；原 task/route API 继续只读。

## 仓库设置

提交姓名和邮箱分别保存、分别恢复继承；只写当前仓库配置，已启用 `extensions.worktreeConfig` 时身份沿用当前工作树范围。界面显示当前生效值和来源，恢复继承删除该范围的覆盖值。不会修改全局配置或自动启用工作树配置。

远端支持新增、改名、修改／添加／移除抓取和推送地址及删除。多地址按原顺序保留，重复地址也独立处理；移除最后一个显式推送地址恢复沿用抓取地址，最后一个抓取地址不能单独移除。用户名／密码和敏感查询参数脱敏，原始地址只在服务内部用于精确匹配；修改其他字段不会把脱敏文字写回 Git。删除前明确核对配置、跟踪引用和上游关联影响。

配置动作 `config-set/config-unset`（field:name/email）、`remote-add/remote-rename/remote-remove`、`remote-set-url/remote-url-add/remote-url-remove` 复用 operations 队列和 requestId 去重，使用独立的 `settingsVersion`，文件变更不会使配置表单失效。并发配置变化返回 409 并保留输入；Git 内容动作仍校验原仓库状态版本。配置文件使用 Git 原生锁；重复地址的单项修改在持锁的同目录副本中生成，再原子替换配置，保留其他配置项，不清理外部锁。

显示偏好按实例与仓库保存在浏览器，包括默认差异方式、换行与提交图比例。保存失败显示提示；配置写入失败保留输入，成功后读取当前仓库数据。

## Git 操作和恢复

自动发现当前实例及 repositories 下的仓库，识别工作树指针、子模块和路径别名。普通文件夹实例也有目录入口，明确显示未初始化，不自动 git init。普通文件和 .DS_Store 不当作仓库；扫描及仓库状态分批查询，单项错误不阻断其他仓库。总览只返回仓库摘要，选择仓库后查询变更明细；文件树与变更列表分批显示。打开应用不联网，远程操作只在用户点击后执行。

目录查询不等待仓库状态：已发现的名称立即返回，状态最多四个并发在后台补齐；一个慢仓库不会阻断其余条目。状态首次读取显示“正在读取”，过期摘要保留并显示“更新中”，失败逐项显示，不将未知状态当成干净。后台摘要复用 30 秒，深层目录发现复用 60 秒；点击刷新目录立即重新发现与刷新。扫描或状态更新时每 500ms 取得进度，稳定后每 10 秒查询；稳定查询只读内存摘要，过期时排队更新，不再次等待全部 Git 命令。缓存仅在当前服务内保存，不新增磁盘仓库注册表。

文档写入仅使原路径与新路径所属仓库的摘要失效；总览读取省去索引、逐文件属性、合并状态和远程名，只在 HEAD 变化时重读最近提交。变更计数仍展开未跟踪文件并保留子模块检查。选中仓库的详细状态和每次写操作仍实时读取、验证索引与文件版本，不使用总览缓存授权 Git 写入；晚到的后台结果不能覆盖已更新状态。

所有 Git 动作调用本机 Git，无 shell 命令拼接，参数、路径和动作受控。继承本机凭据助手、SSH agent、hooks 和签名设置；不修改全局身份或关闭签名。缺少 Git、身份或认证时显示实际错误。

action 为 stage/unstage（paths）、hunk（snapshotId/hunkId）、commit（message）、branch-create/branch-switch/branch-delete/merge（name）、merge-abort/merge-complete、fetch（remote）、pull/push（remote/branch）、stash-create（message/includeUntracked）、stash-apply/stash-pop/stash-drop（stash/stashOid）、resolve（path/text/fileVersion）。

仓库版本绑定 HEAD、索引、工作区状态和文件时间/身份。执行前重新核对；修改块绑定服务端生成的 diff，不接受任意客户端 patch。按文件操作保留其他暂存内容，分块只修改索引。确认界面绑定打开时的版本，仓库变化后要求重新检查。

pull 仅快进，分叉后先 fetch 再明确选择 merge；push 明确远程和目标分支，不强推。删除分支只使用安全的 -d。Stash 使用引用和 OID 双重核对。冲突结果含标记时不能标记解决；保存后暂存，全部解决后才能完成合并。

每个仓库串行执行；文件保存和改变工作区的 Git 操作共用协调器。界面先处理相关未保存文档，再发起 Git 动作。操作 ID 和 requestId 在当前服务会话内去重，最近结果有界保留；浏览器保留最后操作 ID。重连查询结果，不自动重发动作。服务重启、记录已失效、超时或输出超限时，先刷新实际仓库核对，不推断失败等于未发生。操作错误与输出过滤 URL 中的凭据。

首版管理已有仓库；不提供交互式 rebase、强推、PR/Issue 或全局 Git 配置管理。Windows 和其他浏览器的实际验证范围以当次验收记录为准。

## Git 日常交互细化（2026-10-26）

工作区详情按冲突、已暂存、未暂存分组。文件名单击查看差异、双击暂存／取消暂存，方向键浏览相邻文件；复选框支持多选与 Shift 连选。搜索同时匹配现路径和重命名前路径，支持状态筛选。组内“全部”只作用于当前筛选结果，每批最多 1000 个文件，超过时应继续筛选或分批选择；不截断后静默执行。取消暂存重命名会同时处理原路径及新路径，保留磁盘内容。

提交区固定在文件列表下方。说明草稿按本实例与仓库隔离保存在当前浏览器，切换仓库或刷新后恢复；存储失败明确提示。提交前展示完整说明和已暂存文件清单，支持返回继续检查；只在本次提交成功且说明尚未再次修改时清空草稿。`⌘/Ctrl+Enter` 打开提交检查，`⌘/Ctrl+1` 选择工作区，`⌘/Ctrl+2` 恢复历史，`⌘/Ctrl+3` 浏览当前 HEAD 文件，`⌘/Ctrl+4…5` 打开引用／贮藏导航，非输入区域的 `⌘/Ctrl+R` 刷新仓库。

差异支持就地修改块操作、行号、统一／并排比较、换行、语法高亮、查找与修改位置跳转。文本差异随仓库版本变化更新，不沿用旧内容；按块写入仍使用服务端完整快照与仓库版本校验。历史文件浏览默认只读原文，可切换比较方式或输入比较基线。左右分栏支持拖动、方向键、Home 重置和双击恢复默认宽度；详情内部的适配边界以“标准应用窗口”章节为准。

历史搜索在服务端对完整历史过滤后分页，支持提交说明、作者、文件路径、指定分支和 SHA 定位。文件历史跟随重命名；默认“所有分支”包括本地／远程分支、标签和当前 HEAD，不把贮藏内部提交铺入普通历史。每页 100 条，以额外一条探测下一页。提交详情返回作者、日期、父提交、文件状态与增删行数；合并提交的文件清单及差异都比较第一父提交。工作区文件修改不会重置已经选中的历史提交。

左侧本地分支、远端分支和标签可搜索、查看历史／文件、指定起点新建、选择创建后是否切换、检出远程跟踪分支、重命名、安全删除与合并。引用操作可带 `expectedOid`，服务端核对所选引用仍指向已检查的对象；修改新建起点后重新解析。同步对话框默认采用实际上游的远程与分支名，明确显示源→目标；推送可选择建立上游，拒绝非法目标名称。最近获取时间只在获取／拉取成功后更新。

贮藏可先预览文件及差异，包括第三父提交中保存的未跟踪文件；恢复可选择同时恢复暂存状态。应用保留、应用后删除、直接删除各说明后果，写入仍核对 ref 与 OID。封装对贮藏命令不传 `--literal-pathspecs`：该全局选项会传给 Git 的内部清理命令，在本机 Git 导致包含中文等特殊名字的未跟踪文件未被收起。贮藏接口不接收用户路径表达式，其他文件命令继续使用字面路径。

冲突编辑支持普通冲突及删除／修改冲突，明确区分“空内容”与“删除文件”；磁盘文件缺失时可重建结果。后台刷新不替换当前编辑结果，磁盘发生变化时暂停保存并提供明确重新载入入口。受保护文件仍遵循文件服务的写入／解锁策略。

常规暂存操作使用就地状态反馈，失败或结果不确定时显示详细输出。操作结果中的 `state` 为仓库摘要，不包含可能很大的 `entries`；当前明细从 status 重新读取。服务重启后失效的操作指针只提示一次并清理，不重复执行原动作。

新增／扩展查询：

- `history` 增加 `q`（说明文字）、`author`、返回 `offset`；过滤值按固定字符串匹配。
- `commit` 增加 `author/email/at/committedAt/parents/files`；`files` 含状态、增删行数，二进制行数为 null；保留 paths。
- `refs` 增加分支完整引用、最近说明和日期；贮藏增加日期。
- `GET /api/git/repositories/:id/stash?rev=<stashOid>` 返回仍在列表中的贮藏详情，文件分别携带实际预览 rev 与 untracked 标识。
- `conflict` 增加 `oursExists/theirsExists/fileVersion`（缺失为 missing）。
- 操作增加 `branch-track`（source/name）、`branch-rename`（name/newName）；`branch-create` 支持 startPoint/checkout，push 支持 setUpstream，贮藏恢复支持 restoreIndex，resolve 支持 remove。旧参数保持有效。

交互参考 [SourceTree 文件状态说明](https://support.atlassian.com/sourcetree/kb/viewing-file-status-of-a-repository/)及[提交与推送流程](https://confluence.atlassian.com/get-started-with-sourcetree/commit-and-push-a-change-git-847359114.html)。实现复用现有开源 CodeMirror 6（merge/search/language-data）、Radix Dialog、Lucide、React 与本机 Git；没有嵌入 SourceTree、复制其专有代码或引入另一套桌面 Git 客户端。依赖精确版本、离线资源和第三方许可继续由现有构建维护。

## 桌面卡片操作

普通状态下可直接拖动卡片空白处或卡片名称移动位置，松手吸附网格并保存到当前分组；不需要先进入编辑。拖动时显示无边框的浅色圆角网格，吸附目标为卡片后方的柔和底色，无描边或文字标签。辅助网格不撑高桌面；桌面不显示滚动条，超出可见区域的卡片仍可使用滚轮访问。普通状态松手后网格和目标提示收起，编辑状态保留背景网格。卡片内按钮、链接和输入控件保留各自操作，名称区仍可使用滚轮滚动。窄窗口拖动仅保存位置，不把响应式临时显示尺寸覆盖为卡片设定尺寸。

左侧边栏底部铅笔按钮“编辑卡片”直接进入编辑状态，可缩放、添加、移除卡片，也可使用方向键移动、Shift＋方向键缩放。编辑中的修改在“完成”后保存，“取消”恢复进入编辑前的布局。系统设置仍从左上角 KSF 入口打开。

## 工作统计卡片

工作统计是当前唯一正式卡片，首次打开默认显示一张 4×2 工作统计。继续阅读、最近对话、归属概览三张测试卡片已删除，包括卡片库注册与专用组件、样式和最近对话卡片请求；旧布局加载时过滤其记录，不移动保留的正式卡片，不向用户主动清空的桌面补卡。

“工作统计”可从桌面卡片库添加，默认 4×2 格，任务、对话轮次、项目、知识、能力五项横向排列，今日／本周各一行。下方直接列出今日曾作为主归属的项目、知识和能力名称；点击名称可查看该对象的关联任务，名称较多时在名称区域内滚动。点击数字展开对应明细，每页 30 条；对象可以进一步查看本期任务，打开任务时在新对照窗口定位本期匹配轮次。明细保留打开时的数据，后台刷新不重置正在查看的页码或对象。已有正式卡片的位置和尺寸保持，主动移除后不会反复插回。

一个任务为一个本期有已记录用户轮次的聊天，轮次按开始时间归日；进行中、完成和中断都可计入。未记录、策略待确认、没有用户输入的占位不计入。项目／知识／能力复用历史主归属与稳定身份去重，同轮切换归属分别计入，重复主归属只计一次；仅关联对象和采用能力不计入。无具体归属的轮次仍计入任务与轮次。今日从当地零点起，本周从当地周一零点起，时区跟随浏览器，服务端验证 IANA 时区并处理夏令时边界。

`GET /api/work-stats?timeZone=Asia%2FShanghai` 返回 `{ok,data,errors}`。data 包含 generatedAt、timeZone、today/week（startAt/endAt 为 UTC 半开区间、startDate/endDate 为当地日期、counts 为 tasks/turns/projects/knowledge/abilities），activity 为本周符合口径的轻量轮次，另含 capture（enabled/activatedAt）与 errors。每行仅包含 taskId、turnId、taskTitle、title、startedAt、navigationTarget、primaryTargets（key/kind/label/lifecycle）；不返回 messages、声明原件或工具输出。重复或无效参数返回 400；接口沿用同源、Host、GET/HEAD 与 CSP 保护。

统计只读已有任务档案，内存缓存每个文件的轻量投影，按文件身份、大小、修改时间和变更时间检测变化，分批让出事件循环；共享一次进行中的计算，统计快照缓存 15 秒。未变化文件不重复解析，不新建持久统计数据库、不改写原件。卡片显示时每 15 秒读取，页面恢复可见、跨日或跨周自动更新；桌面隐藏或卡片未添加时不轮询。手动刷新传 refresh=1，绕过快照缓存但仍复用未变化的文件投影。读取失败保留上次数字并提示；部分损坏仅展示可核对记录，采集未启用时说明只统计既有资料。
