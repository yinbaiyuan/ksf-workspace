# 基本功 Competency

基本功是 KSF 统一的可复用能力单元，承载专业判断、处理方法和具体执行操作。它规定在什么条件下，如何把一类输入处理成可检查的结果，并说明判断依据、质量要求和失败时的修正方式。

## 解决的问题

“分析一下”“整理得更好”只表达意图，没有提供可靠方法。基本功把专业经验转成能指导判断和行动的约定，使不同搭档处理同类问题时能够复用方法、比较结果并持续修订。

基本功既可以侧重专业判断，也可以侧重稳定操作。即使没有任何工具和数据包，只要有清楚的结果、方法与标准，也可以成立；只有资源清单而没有处理逻辑，则不足以构成基本功。

## 持有的内容

- 独立结果、适用条件、不适用情境和相邻能力边界。
- 必要输入、可选上下文、缺失信息的处理方式。
- 专业概念、分析维度、判断依据、方法及条件分支。
- 输出要求、质量标准、失败信号与修正办法。
- 正例、反例、边界例，以及真实或模拟的来源性质。
- 所需数据包、知识、模板、脚本与 CLI 支持及其使用条件。
- 验证方式、已有证据和仍未证明的部分。

方法可以包含追问、操作、反复验证和修订。它们服务于这一专业结果，不接管搭档的整体责任或协同的跨搭档协调。

## 与其他对象的边界

**与知识**：知识可以解释一个方法为何有价值、依据是什么；基本功约定采用这个方法时怎样判断和处理。完整的操作性方法可直接进入基本功，独立有价值的背景解释通过引用保留，不要求双份正文。

**与搭档**：基本功不承担一整类业务的持续推进责任。同一需求分析基本功，可以被产品搭档和方案咨询搭档复用；搭档持有责任—基本功配置，基本功不维护一份使用者反向清单。

**与程序和资源**：基本功直接说明操作方法、调用条件和结果检查；脚本、CLI、模板与资料提供实现或执行支持。确定性的细节可以由程序完成，情境判断可以由 Agent 完成，两者都服务同一能力，不按执行方式再建立一类平行能力对象。共享程序或资源可以独立维护，由多个基本功引用。

**与数据包**：基本功决定如何使用和评价材料；数据包提供有组织的信息依据。把案例放进包里，不代表已经给出了判定案例好坏的方法。

## 粒度与创建判断

一项基本功应有可以独立解释的结果及连贯的方法和质量标准。具体操作具有独立复用价值时也可以形成基本功；只是其他处理中的单个动作时，保留为方法步骤或程序支持，不强行建对象。包含多类明显不同的结果时，再判断是否需要拆分。

先检查现有基本功。增加案例、条件分支或执行工具，不必新建一个名称接近的基本功。专业标准的现行版本只在其主要归属处维护，搭档和协同引用它。

**示例情境**：把访谈材料转成有来源、能区分目标与方案、标明关键缺口的需求分析结果，适合基本功承载。

**操作示例**：反复将指定输入转换为规定格式的文件，定义输入、调用方式、失败处理与输出检查，也可以形成基本功，直接使用已有转换程序。

**反例情境**：收藏十篇需求分析文章，只说明拥有资料，尚不能证明已有一项专业能力；它们可进入知识或作为数据包资料。

## 定义与运行

入口文件为 `competency.md`，以承载目录整体管理。已实现 list/read/write/remove/check，公共管理规则见[对象命令](../cli/objects.md)。

系统区为 `.agents/core/abilities/competencies/`，用户区为 `能力/基本功/`。初始能力发现提供协同、搭档摘要；基本功正文按任务安排与责任需要渐进式读取。

定义方法见[基本功设计](../../abilities/competencies/competency-design/competency.md)，公共字段见[对象元数据规范](../对象元数据规范.md)。结构完整、案例走查通过与真实任务有效是不同证据，不能相互替代。

对象依赖通过公共 `references` 声明，普通支持资源的路径和使用方式在正文说明；脚本和 CLI 不因被引用就注册为对象。渐进读取先取得基本功的必要定义，再按当前步骤读取其支持资源。
