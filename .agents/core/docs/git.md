# Git 协作规则

系统与个人数据以独立仓库和发行清单区分。`ksf-core` 承接 KSF 系统，是唯一系统开发源；`ksf-workspace` 承接用户模板，由发行程序生成；真正的用户实例叫 `ksf` 或用户自定义名称，可以是私有仓库或普通文件夹。机制见[发行说明](distribution.md)。

## 仓库与分支

- Core 主分支为 main，功能和修复分支按用途命名，无需 ksf- 前缀。新系统分支必须来自已核实的纯系统历史。
- 官方 ksf-workspace 用户模板仓库由发行程序生成；其默认 main 是模板发行结果，常规系统源码贡献统一进入 ksf-core。
- 个人工作区使用自己的 main 和个人远程。升级按 Release 版本及基线执行，不整体合并 Core 分支，也不依赖个人 Git 历史。

## 内容归属

Core 承载 .agents 下的系统定义、程序、文档、测试和模板源，以及根 AGENTS.md、README.md、.gitignore 和 .github 工作流。系统示例使用虚构数据。

项目、知识、用户能力、收件箱、源档和归档属于用户实例，Core 不跟踪这些根目录或占位文件。ksf-workspace 模板的空目录由发行程序生成，测试数据在临时目录创建。Core 的忽略列表采用系统源码白名单，防止本机用户内容误入库；用户实例使用模板自带的另一份忽略列表，允许正式个人数据入库，仅排除本机缓存等。两个列表各自维护，不按分支切换本机 Git 配置。

发行和升级不修改个人 Git 配置、远程或 .gitignore。复制文件夹无需 Git。创建远程备份时优先从模板创建自己的私有仓库；公开上游的 fork 也会公开。

## 系统提交和推送

任何 Git 写操作前检查当前分支、工作区和已有暂存差异。混合工作区只定向暂存授权的系统文件，不使用 git add .、git add -A 或 git commit -a。提交前审查暂存内容；用户目录及其占位文件不能进入系统提交。

推送前核对实际远程、源/目标分支和全部待发送提交，不只检查最后一个提交。不得向 Core 整体推送个人分支或混合历史。忽略列表不是权限隔离，已跟踪、强制添加和旧提交仍需审查。

用户要求普通项目、知识或能力维护，不自动授予提交和推送权限。明确的系统发行任务需要纯系统提交时，按该任务的实际授权实施并检查来源；本规则不引入另一轮无依据的确认。

## 用户贡献

普通能力定制保存在用户能力区。明确修改 Core 并希望贡献时，使用 contribute prepare 整理选定系统差异，向用户展示公开内容，再用 submit 的 reviewed 摘要提交。

贡献工具从发行来源建立新的纯系统提交和 contrib-<ID> 分支，不复制个人文件、提交说明、作者配置或 Git 历史。首次公开提交需要账户授权；准备和预览无需 Git 或账户。个人 main 的 origin 不能被默认当成系统发布目标。

本规则不声称已安装全局 Git 钩子或配置服务器保护。强制检查范围以实际发行、贡献程序和验证结果为准。
