# KSF 开发与测试规范

本文是本地开发、CI 和发行的唯一现行测试规范。命令参数见 [test 命令](cli/test.md)，覆盖范围以[统一清单](../runtime/testing/catalog.json)和本次回执为准。旧验收记录保留当时事实，不作为当前操作要求。

## 选择验证范围

| 阶段 | 必要动作 | 扩大范围的条件 |
| --- | --- | --- |
| 小步修改 | 精确文件或变更快速验证，检查问题及邻近边界 | 出现新的影响证据；简单文案、样式无需强制新增测试 |
| 功能完成 | 受影响组件、公共契约及必要集成；相关类型检查、构建和界面检查 | 跨组件调用、持久化或原生差异 |
| 提交或 PR 前 | 补齐快速与相关集成证据，核对选测计划中的全量需求 | 风险规则要求全量；不因每次提交机械重跑全量 |
| 交付候选 | 对稳定输入补齐 Mac、Windows 必需全量和专项验收 | 缺少匹配的可信证明，或来源、锁、工具链、平台变化 |

默认 `ksf test` 实际执行快速档。全量必须显式使用 `--suite full`；快速结果不能替代全量证明。真实模型、付费请求、GUI、跨设备和长期运行单独验收，记录真实环境和缺口。

```sh
.agents/ksf test --changed --plan --json
.agents/ksf test --changed
.agents/ksf test --component sdk
.agents/ksf test --suite full --component core
```

变更计划报告 `requiredFullComponents` 和扩大原因，不暗中把快速升级为全量。存储、迁移、锁、启动器、升级发行、公共协议、依赖工具链和选测机制变化必须补齐相应全量。无法精确映射的第一方变更保守扩大；Git 失败必须修复基准或显式选范围，不能声称没有变更。

## 依赖、构建与隔离

开发命令使用 `ksf hello --json` 返回的随包 Node。首次准备、锁文件改变或环境失效时才安装锁定依赖；测试命令不会安装依赖。Core 集成使用 SDK、web 和 Projects 的开发依赖，各目录分别 `npm ci`（SDK、Projects 使用 `--ignore-scripts`）。缺少依赖会在计划中列出，实际运行返回失败。

前端或应用构建输入变化时构建对应产物；服务端测试要求当前前端产物有效。完成一批系统修改后运行 `ksf build --json` 刷新 Core 清单，再 `ksf runtime verify --json`。发行预演只用于发行相关修改及交付候选，运行 `ksf release build --dry-run --json`；它要求干净源码提交，不通过临时提交或覆盖日常实例绕过。

测试在临时根操作，并负责关闭进程、服务和文件句柄，清理目录。不得写业务数据、重启日常后台、修改受管构建产物来让测试通过。生命周期种子仅用于复制，场景目录和 Git 历史独立，不共享可变目录或可被覆盖的硬链接。运行器为每个文件提供本轮专用临时目录，超时或取消时停止拥有的进程树（包括脱离父进程组的子进程），并清理这些目录。Windows 测试 PATH 同时包含所选归档工具目录，避免找到 tar 却找不到 gzip。

## 清单与新增测试

清单记录每个文件的 owner、covers、quick/full、输入、平台、超时、依赖、可缓存性及平台耗时估计。owner 是维护者，covers 是保护的组件；应用可引用 Core 的公共集成覆盖，执行时按文件去重。每个第一方测试恰好登记一次；漏登、重复或失效路径阻断全部计划。独立工程、第三方依赖和已安装应用包不自动扫描。

新增测试先明确能阻止哪种有效行为退化，再登记。异步链路分别等待目标阶段的明确状态或受控屏障，不能用接收方业务完成推断发送方已持久确认。子进程超时与整组超时分别设定；耗时场景拆组并保留故障断言。轻量规则和格式组合放快速档，真实进程、CLI、故障恢复、发行与原生差异放全量专属文件；全量同时包括快速。文件混合昂贵链路时拆分，保留有效断言和仍支持的兼容覆盖。清单中的输入必须包含测试、夹具、实现、相关契约和锁；无法完整确定输入的测试不得缓存。新增公共装置或输入关系必须验证选测、分片和失败传播。

应用 `check` 可独立调用，不先加载打包器。测试目录允许使用宿主测试装置；生产源码仍拒绝私有导入，生产入口闭包和实际构建图均拒绝导入测试代码。直接构建与 CLI 构建采用同一必要检查。warning 仍需人工判断，不等于完整安全证明。

## 结果与复用

回执在忽略目录 `.agents/runtime-data/tests/`，区分实际执行、复用、平台不适用、未执行、失败、超时、取消和输入变化。`complete` 只说明所选范围，不代表整个产品。空变更或平台不适用明确返回不适用；空分片不算独立完整证明。

只有本地快速档显式 `--reuse` 才读取成功缓存。指纹包括实际输入字节、夹具、清单、锁、安装工具链字节、Node 和平台环境。失败、取消及执行期间输入改变不产生当前有效证明；输入无法确定的测试不缓存。缓存不是发行门槛凭据。父进程的 Node 测试选择、预加载、覆盖率等参数不传入子运行器，分片只能通过命令显式指定。

失败先复跑失败文件，再验证相关组件；只有新的证据显示影响扩大时才追加范围。不要为了收集更好看的耗时反复跑全部测试。耗时分开记录依赖准备、构建、夹具、Git、打包、断言、清理和队列；平台耗时基线用于分片，不作为删减必要覆盖的理由。

## CI 与发行证明

`check.yml` 使用同一计划器决定快速或风险全量；手动运行支持全量。`verification.yml` 每平台准备一次依赖及前端，全量分片恢复准备产物并重建声明的本地 SDK 目录链接，再按确定清单运行；不在每个 Windows 分片重复 SDK、前端、冒烟和发行预检。固定 `required` 汇总全部适用作业，避免路径过滤留下 Pending。仓库分支保护需将该固定作业配置为必需检查；工作流文件本身不能改变远端规则。

全量汇总核对每个平台的完整文件集合、去重、成功、源码摘要、清单和随包运行时。发布只接受官方仓库 main 的成功 Verify Core 运行、对应 Actions 产物和相同最终提交的完整双平台回执；重新查询运行和产物身份，不能信任本地缓存或 PR 分支自报的成功。证明缺失、过期或不匹配时补跑原生全量。最终包仍独立检查来源、摘要及冻结交接；验证复用不允许替换发行产物。

远端工作流必须在授权推送后记录真实结果。Mac 和 Windows 原生执行分别留证；模拟平台适配器、配置存在或单平台通过都不能写成双平台验收完成。目标快速约 3—5 分钟、全量约 15—20 分钟；未达到时报告实测瓶颈和保留的必要覆盖。
