# 发布、升级与兼容

## 应用源与版本

KSF 固定启用[公共默认应用源](https://yinbaiyuan.github.io/ksf-apps/index.json)，由 [ksf-apps 仓库](https://github.com/yinbaiyuan/ksf-apps)通过 GitHub Pages 发布。此源不能通过界面或公共 API 改名、改地址、停用或移除；服务端返回 `APP_SOURCE_LOCKED`（403）。这是宿主配置规则，不是操作系统级文件保护。

随附应用源继续支持离线安装官方应用，自建源仍可添加和管理。旧工作区自动补入固定源，保留既有源设置、安装身份和应用数据。相同版本优先公共默认源，已安装应用继续跟随原源；公共源暂不可用时显示错误，随附源和已安装应用继续可用。公共源首版目录为空，应用贡献见仓库的 CONTRIBUTING.md。

用户可在应用商店直接导入 `.ksfapp`，无需索引或联网。手动安装与应用源安装共用包校验、不可变版本、数据目录、任务租约和延迟切换；操作方式见[快速开始](quickstart.md#分享应用包并手动安装)。手动来源不检查远程更新，升级由用户导入新版包；源安装与手动安装之间不自动换源。离线包只能与本机已知兼容版本比较，不能据此确认开发者全球最新版本。

构建输出 .ksfapp 与ksf-app-registry-v1的index.json。索引每项包含manifest和package.url/size/sha256；包URL相对索引解析。HTTP(S)源由本机宿主下载，不需要浏览器CORS；首版不支持URL内凭据和自动跟随重定向。

必须在执行包或Manifest变更时递增版本；仅商店展示资料变化可以独立发布，见[商店资料](store-listing.md)。打包器及安装器拒绝同版本换内容（包含pending、可回退及卸载后保留的历史包）；不可通过覆盖同名包让用户绕过版本核对。自建源的并发构建通过写锁合并索引，先完成包和校验再原子发布索引。

应用ID稳定，卡片类型ID稳定；改名不改ID。官方ID由随包源占用。第三方包不得冒用官方ID，也不能宣称SHA256等价于签名认证。

## 运行中升级

窗口固定启动时的release；旧窗口/实际执行中的操作会使升级pending。最后窗口关闭且操作完成后，宿主统一释放旧卡片/后台、切换版本并恢复卡片配置。仅有卡片或空闲后台不会永久阻挡升级。

应用后端不要用永不结束的tasks.run来实现定时。后台定时器由startBackground和dispose管理；安装、启用及版本切换由管理器协调，不依赖浏览器继续开着。业务需在后台开始前核对持久进度，避免升级补跑重复发布。

RPC调用方超时不代表执行完成，仍在执行的动作继续阻挡不安全切换。结果未知时先查询原操作。

## 停用、卸载及回退

停用/卸载先通过当前窗口关闭保护，其他页面窗口或在途操作明确报错。卡片停止运行，保留配置、分组和几何占位；业务数据保留。重装同ID后按原记录恢复，不凭同名应用转移数据。

首次安装没有可回退版本。回退必须确有不同的previous release，并核对当前业务数据schema与旧代码兼容。回退不删除AI任务、不撤回已发布结果，也不恢复旧数据快照。

## v1 与 SDK 2.0 兼容

v1保留frontend、顶层尺寸及multiInstance，每窗口独立后端；不要求迁移Terminal或项目应用。v2使用window/cards，同版本后端共享。SDK 2.1增加接口与检查，旧v2包继续按原产物运行。

旧页面公共客户端、历史SDK导出和包格式继续保留。新开发只用手册列出的公共入口；未列的兼容内部模块不作为新应用的稳定依赖。SDK变化属于宿主升级时，先完成一次宿主切换；后续应用安装/升级不重启主服务。

发布前声明支持的平台和已实测平台。不得用macOS ARM64构建成功推断Windows、Safari或长期运行已通过。

平台/ABI变体使用同一版本时，需通过专门打包步骤生成不同文件名；通用build默认文件名仅适合单一变体源。每个变体分别核对target/nodeAbi和实际硬件，不能在索引中写重复版本/平台/ABI组合。

普通商店仅安装最新兼容版，更新跟随原源；历史版本不提供常规安装入口，故障回退单独保留。SDK2.2新增可选listing及素材工具，不改变宿主协议整数2。

## SDK v3 的交付门槛

应用包内 CLI 及消息激活等新机制见[CLI 契约](cli.md)和[通信契约](communication.md)。只有实现、宿主版本/SDK 兼容检查、打包校验和[对应验收](validation.md#cli-与通信验收)完成后，才能作为可用能力发行；当前为开发实现，未正式发行 SDK 3.0.0。

CLI 实现、命令描述、文档及依赖同包交付和切换；既有执行先排空，版本条件不符时重新核对。消息消费者和持久需求的交接不得使新旧版本双消费；回退仍需核对业务数据，不因旧包存在就承诺恢复旧业务状态。已经发行的同版本包不能为补充新 CLI 或文档而覆盖。
