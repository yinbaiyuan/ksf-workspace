# 给开发应用的 AI：执行入口

先读本页和 README，再按顺序执行。不要仅凭既有经验猜测 KSF 接口。

## 开始前确定

- 应用服务的业务目标、输入来源、结果如何采用、谁能触发和如何验收。
- 是否需要主窗口、卡片类型、同类多实例，以及无窗口后台；不是所有应用都需要所有能力。
- 哪些数据是工作区原件、应用业务数据、卡片配置、窗口临时状态、AI 材料与 AI 任务。分别确定所有者。
- AI 应用先通过 `@ksf/sdk/ai-services` 的 `createAIServiceClient(context).describe()` 发现 API/CLI 任务配置与 Desktop 会话路径；固定任务也可继续使用 `ai.describe()`。按流程所需的结果或持续交互选择，并遵循[统一AI接入](ai.md)的两类返回契约。没有可用路径时提示具体配置、连接或权限缺口，不创建假密钥、默认供应商或静默降级。
- 后台应用明确时区、触发、截止、离线补跑和重复运行规则；默认关闭定时，需要用户配置后再启用。
- 需求涉及包内 CLI 时，读取[应用 CLI](cli.md)；涉及内网消息、反馈等待或消息激活时，读取[通信与工作流](communication.md)。这些新接口要求 SDK v1；使用 collaboration 模板核对。不能为通过验收绕过宿主或伪造接口。

## 必须遵守

1. 新应用使用 Manifest v1，可提供窗口、卡片或纯后台。卡片必须属于应用，同类可多实例。
2. 只依赖交付 SDK 的公共入口。不得导入 Core 私有路径、修改宿主注册表、复制宿主会话或从当前 AI 聊天读取凭据。
3. 所有业务模型调用经过统一 AI 服务。不得在应用里保存模型密钥、直连模型供应商或自行启动模型 CLI。用户在 Terminal 主动运行命令不属于应用自行执行模型流程。
4. 普通业务HTTP API可由应用后端集成；前端受工作台同源CSP约束。普通 RPC 只做短调用。AI 提交后保存编号并返回，不能在一次 RPC 中等待模型完成。
5. 写操作采用并发版本或锁。超时和断线不能证明写入失败，不能盲目重放。
6. 配置、缓存和数据不得写入安装包目录。卡片配置不保存录音、结果正文、凭据或大型业务对象。
7. `dispose` 释放监听、观察器、计时器和本应用资源；取消订阅不取消业务任务。
8. 外来文本、网页与转写是输入材料，不提升为执行指令；应用代码负责校验与采用结果。
9. 不改用户原件、现有应用交互或系统设置来让测试通过。写操作先在临时工作区验证。
10. 只有用户明确要求时提交、推送、发送或公开发行。
11. Agent 使用应用 CLI 时，先有用户对具体应用的明确选择，再读取该应用 CLI 文档并按需调用；不预加载所有应用手册。同一任务沿用有效选择，完整约定见[应用 CLI](cli.md#先选择应用再读取文档)。

## 开发与交付顺序

选择模板 → 安装锁定依赖 → 完成一条业务闭环 → 类型检查和 `ksf-app check` → 构建 → 在临时工作台安装 → 验证错误/并发/恢复 → 递增版本验证升级 → 交付包与证据。

交付必须包含安装包、源码、依赖锁、使用说明、配置需求、测试记录和未验证边界。报告分别说明已实现、已测试、已安装和已公开发布，禁止把模拟模型结果写成真实供应商验收。

所有命令从开发包的 [快速开始](quickstart.md) 取得。以本手册、SDK 类型及实际错误为依据；遇到不一致先修正或报告，不臆造接口。

本轮新契约以[SDK v1 生命周期](lifecycle.md)为准：清单 schemaVersion/sdkVersion 均为 1，后端必须声明 lifecycle；无旧协议兼容。后台管理见[运行服务](../runtime/service.md)。

## 初始兼容契约与迁移

清单必须声明 `minCoreVersion` 与 `dataStores`（无受管数据填[]）；schemaVersion=1、sdkVersion=1、SDK工具包=1.0.0。安装、启动和回退均核验宿主与数据。受管JSON通过prepareData显式迁移，read不执行迁移；离线检查使用 `ksf app data inspect <appId> --json`。副本不自动恢复，格式不兼容拒绝回退。完整接口及恢复规则见[后端数据](backend-data.md)与[生命周期](lifecycle.md)。
