# KSF 应用开发者手册

规范版本 **3.0.0 开发版**；清单 **Manifest schema 2**；宿主协议 **SDK v3（兼容 v1/v2）**；AI 契约 **ai-task-v1**。2026-10-28。

本地开发实现包含应用包内 CLI、公共通信、持久保活与消息激活，尚未正式发行。旧 SDK v1/v2 应用保持兼容。

这是应用开发的唯一现行入口，面向开发者和开发应用的 AI。KSF 是承载业务应用的工作台。应用定义业务行为，宿主提供窗口、卡片、安装、文件协作和统一 AI 执行。

## 阅读路线

1. AI 开发者先读 [AI-START](AI-START.md)，按清单确定需求与验收。
2. 运行 [快速开始](quickstart.md) 的完整闭环，再按应用能力查后续章节。
3. 交付前运行 [验证清单](validation.md)。构建成功只证明产物生成，不能替代业务验收。

## 规则等级与状态

**必须**是交付约束；**建议**允许开发者在说明理由后调整；**可选**按业务需求采用。每项能力必须以实际宿主及版本为准。

**已实现**：窗口与多卡片、独立实例配置、按版本共享后端、任务租约、显式后台、AI 服务、热安装升级、v3 桌面恢复。**兼容**：v1 包、既有 SDK v2 入口和旧客户端。**暂不支持**：不可信代码沙箱、公开签名认证、自动跨模型切换、API 结果未知自动对账、跨设备持续运行。

**SDK v3 开发实现**：包内应用 CLI 与 `ksf app` 网关、公共消息与 Agent 收件、持久运行需求、消息分发时激活。完整工作流由应用负责；支持范围以实际验收记录为准。

前端共享页面 JavaScript/DOM；后端以当前系统用户运行。声明能力用于来源核对与行为约定，不能宣称隔离保护。`background` 和 `environment` 声明确实影响后台启动及环境继承，但同样不构成安全沙箱。
