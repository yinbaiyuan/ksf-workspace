# 文档维护、生成与验收

文档主位置是Core的docs目录。总入口面向读者，专题持有唯一现行规则；能力定义持有Agent方法，源码与实际接口核实程序行为。私人项目、部署和历史记录保留原位置。

## 正文责任与风格

概念页说明定义、用途、边界和例子；操作页说明目标、前提、步骤、预期、核验和失败处理；接口页说明输入输出、副作用、身份、版本、并发、错误及幂等；排障页从症状回到实际证据。

事实、推断、建议和历史分开。每个数字注明所属契约或历史阶段，不能用文件数量、active状态或一次测试证明成熟度。专业表述优先具体动作与后果，首次使用术语链接解释。

文档和示例不得依赖私人路径、凭据、真实业务数据或未公开能力源。图片使用随包普通文件，标明示意、真实截图及日期；图的箭头说明含义。未经实际验证的流程明确标注。

## 导航与索引

navigation.json是唯一导航源，维护五条阅读路线、首选页顺序和额外配套说明。正文从docs自动发现，配套文件明确登记；目录和搜索索引由documentation.mjs生成，包含正文摘要和Core适用版本，不手工编辑catalog.json。

修改正文后，用开发环境Node24或hello返回的随包nodePath执行：

```sh
node .agents/core/runtime/tools/documentation.mjs --json
node .agents/core/runtime/tools/documentation.mjs --check --json
```

这里node指上述已核验执行文件，普通用户无需另外安装全局Node。--root可指定隔离实例；--check只检查，不修改文档或索引。生成失败保留原索引并列具体路径和原因。

## 每次改动的检查

1. 修订唯一正文，清理同页失效说明，保留历史记录的当时语义。
2. 更新导航和相关入口，检查Markdown文件、章节锚点、中文路径及引用式链接。
3. 更新目录与搜索索引，核对摘要、版本、全量覆盖和CLI索引。
4. 验证命令/配置/Manifest示例，不在真实业务数据上测试写入。
5. 预览长文、表格、代码、数学、图表和窄窗；有界面改动做真实滚轮和多窗口验收。
6. 通过相应构建与回归，记录实际环境及未验证项；本地通过不等于远程CI或发行。

## 变更关联

| 变化 | 必须复核 |
| --- | --- |
| CLI或配置 | 参数、索引、输出、作用范围、副作用和示例 |
| 应用SDK | 类型、模板、生命周期、错误和开发指南 |
| 主服务或平台 | 启动、停止、进程、端口、权限和原生验收 |
| 数据格式 | 所有者、兼容声明、迁移、备份与回退限制 |
| Agent运行定义 | 能力版本、精确引用、任务顺序和行为说明 |
| 文档结构 | 旧链接、导航、章节、生成索引和阅读器 |

现有CLI没有通用文档编辑或自动知识采纳接口；本工具只生成系统文档的派生目录与索引，不改用户知识和长期认知。

## 发布检查与历史

冻结最终源码后检查生成物及链接，再执行相应程序、构建和实际使用验收。Core构建核对文档索引，过时内容必须先显式生成。历史设计和验收页在导航标明性质，当前支持表引用现行证据，不将私人实施日志整份搬进Core。

实际回归和浏览器证据保存在本次项目验收记录；通用文档说明方法和范围，不硬编码本次测试计数。提交、推送、远程部署及发行仍需具体授权。
