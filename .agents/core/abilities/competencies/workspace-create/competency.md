# 创建用户工作区

## 输入、结果与适用范围

输入为可核对来源的 workspace 模板目录或发行包、目标绝对路径、文件夹或私有仓库方式及用户授权。结果是独立命名、可进入且没有其他用户内容的实例。更新已有实例使用版本维护；历史资料导入不属于创建动作。

## 方法

1. 核对来源的版本、平台、Core 提交及摘要。发行包须与可信索引一致；本地构建模板需核对构建结果，development 来源只用于明确的本地试验，不冒称正式发行。来源不能只是一个名称相近的个人目录。
2. 核对目标路径与父目录，目标必须不存在或为空；非空目录、链接或可能覆盖已有工作区时停止并明确冲突。名称可用 ksf 或用户指定名称，不改变系统产品身份。不因用户要求创建而自行删除旧目录。
3. 文件夹方式通过宿主文件工具复制生成的完整模板目录，或在校验后使用受限归档读取实现解包，保留入口权限和隐藏文件，不执行未验证归档。该步骤使用现有文件能力，没有 `workspace create` CLI，不能编造命令。复制不需要 Git、全局 Node 或包管理器。
4. 仓库方式从官方模板创建用户自己的私有仓库，再克隆到目标；这是外部写操作，须在本次明确范围内。不得将公开 fork 当作私有资料空间，不继承 Core Git 历史，也不把官方模板的远程当成个人备份远程。仅要求本地创建时不创建远程。
5. 核对 AGENTS.md 指向 runtime、发行清单和初始模板出处一致、用户目录为空或只有生成的占位、启动器权限正确。用该实例入口执行 `runtime verify --json`、`context capabilities --json`，检查固定 runtime 与可发现维护搭档及必要引用。启动只准备本地运行时，不检查或安装新版。
6. 区分“程序入口可用”与“独立 Agent 会话已使用”。没有真实新会话证据时只报告前者。创建失败保留原有内容；只清理本次产生且能确认归属的临时文件，不自动删除整个目标。

## 输出、案例与验证

交付实例绝对路径、来源及版本、创建方式、用户目录检查、首次程序调用证据和限制。初始 `.ksf-template.json` 不冒充后续升级后的当前版本，当前版本以 release.json 为准。支持见[发行说明](../../../docs/distribution.md)与[归档程序](../../../runtime/src/distribution/archive.js)。

模拟正例：经校验模板复制到空目录，跨 cwd 通过固定入口启动，用户区无私人预置。反例：把现有个人 ksf 整体复制给其他人。边界例：目标非空、平台不支持或仅要求介绍创建方法，分别报告冲突、支持缺口或只交付说明。隔离测试覆盖创建与首次入口；真实远程创建及新会话证据单独记录。
