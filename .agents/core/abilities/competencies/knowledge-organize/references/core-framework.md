# 采用 Core 知识组织与认知模板

Core 提供可编辑的默认组织约定和可选认知框架。唯一模板源位于 [distribution/template/知识](../../../../distribution/template/知识/knowledge.md)，不依赖某实例的知识目录、私人能力或课程仓库。新工作区由发行程序从这些源生成；生成后的文件属于用户，后续升级或回滚不覆盖，也不补写缺失文件。

## 先判断是否需要采用

已有实例先读实际根导航、关联规则和目标单元。它们与 Core 模板不同不表示错误；本次只整理既有框架时按既有框架执行。普通读取、原文分析及入口缺失不触发初始化。

用户明确要求建立知识组织规则、采用 Core 默认方案或建立认知主题时，读取[公共约定](../../../../distribution/template/知识/rules/README.md)及[认知定义](../../../../distribution/template/知识/rules/认知.md)，形成必要差异。用户已指定其他框架时采用其框架；尚未选择且会影响实际结构时，只澄清这一选择，不默认把全部知识改为认知。

## 新实例与已有实例

- 新实例自带根导航、rules/ 及空认知模板；不创建真实主题，不填入个人经历，不初始化默认 user-data。
- 已有实例按本次授权采用：缺失的相关文件可以建立；现有文件逐项比较并按需合并。存在同名不同内容、不可读、符号链接或并发变化时保留现状，报告具体冲突。不能将模板树整体复制覆盖实例。
- 根 knowledge.md 只作分层概览；规则正文归 rules/，业务正文归知识单元。已有规则目录或入口名不同，可以沿实际落点使用并调整引用，无须仅为采用模板改名全库。
- 规则采用与真实主题创建分别核对；只要求规则时不创建主题。已有材料、其他类型单元和用户定制不因 Core 更新自动迁移。

## 创建认知单元

1. 核对主题范围及现有单元，优先复用；用户已明确建立认知主题时无需重复询问框架。用户要求把内容记录到一个尚不存在的认知主题，且当前采用的类型规则已明确时，可以建立本次所需最小骨架；只问位置、未要求记录时不创建。
2. 读取当前实例已采用的认知定义及模板；实例尚无约定且本次选择 Core 方案时，从上述唯一模板源取得最小文件。形成明确的来源—目标和授权差异。
3. 将 cognition/ 骨架实例化到 `知识/认知-<主题>/`，替换主题与简短定义占位，保留四条路径的目录。没有材料时分区保持空，五步详细认识保持“待形成”，不复制课程或编造认识。
4. 按最终落点重算链接。默认落点的 `3认知/认知说明.md` 链接应为 `../../rules/认知.md`；模板位置的 `../../../认知.md` 不能原样带到主题。采用自定义规则位置时按实际相对路径计算。正文中的示例路径不是待批量替换的来源事实。
5. 按当前类型规则把用户原文或其指定结果放入必要正文，保留尚未验证、来源未知等性质，不为填模板自动生成模型或个人认识。根导航仅补一项该单元的综述与 cognition.md 入口；主题入口链接三个分区和详细认知，只同步本次涉及的概述或占位，不列出全库文件。资料唯一主存并保留来源，混合来源包不机械拆散。
6. 由资产维护核对基线后落实已授权差异，再运行只读路径与链接检查并重读入口。重复执行应复用已创建内容；不同内容保留差异，不覆盖为模板默认值。

## 验收

分别验证：新实例模板可达、无真实主题；已有定制与其他框架保留；新建认知主题能从根逐层到原文；模板链接完成重定位；未填写的认识仍待形成；明确要求记录的未验证想法保留原性质；重复采用不产生副本；只建议位置时零写入。程序检查只验证文件事实，当前 Agent 与独立会话的实际采用另记。模板和归位操作不替代人作出认识与采纳决定。
