# 知识组织与整理

## 独立结果与边界

辅助用户把形成或指定的内容记录到能够发现、逐层理解和回到原文的位置，并按明确要求补充、修订或整理既有知识。交回采用的实例规则、归位理由、内容与位置差异、引用影响、实际结果及未解决问题。方法完整、结构检查和真实使用分别验证。

适用于用户明确要求知识记录、归位建议、补充、修订，以及目录组织、迁移或整理。人决定内容、认识、采纳与修订；能力工具按用户要求辅助归纳、提炼、比较或总结；本项判断结构归属、复用位置与必要关联。普通任务的资料由承接能力按明确约定读取，不因遇到新信息自动发现沉淀价值、建立单元、采纳认识或改写结论。短期记忆转长期资产由相应任务另行设计。

runtime 保持用户目标、识别明确请求并安排本项；本项在该范围内取得原文、读取规则并负责归位和修订安排；资产维护按已有授权落实保存、移动、删除、基线检查和回退。只向 runtime 交回安排或缺口，不自行循环调用路由。内容处理按用户选择或 runtime 核实的适用能力开展，不假设某实例的私人萃取能力必然存在。

本项为普通系统基本功，沿用精确引用、有效来源和用户派生规则，不扩大固定保护。采用时读取本对象 user-data；本版无持久设置字段。实例框架属于实例根说明及其关联规则，整理进度属于项目或当前任务，不创建默认数据。

资料读取遵循[公共约定](../../../docs/runtime/materials.md)。本项的导航读取服务于显式知识记录或组织任务，不形成常规业务的默认知识入口；用户仅要求查阅或讨论知识时，由适用能力或通用 Agent 在该范围处理。

## 输入与准备

取得本次记录或整理目的、用户原文或指定处理结果、材料范围、目标单元或候选、当前产物、允许的操作和完成要求。只取当前工作所需信息，不要求填完整问卷或每次另写计划文件。

| 用户意图 | 当前动作 |
| --- | --- |
| “放哪里合适”、评审结构或仅讨论 | 提供具体位置、理由及必要备选，不写知识、MEMORY 或检查点 |
| “记下来”、补充到某主题、替换某段认识 | 按规则确定唯一落点后执行已授权记录；目标和内容明确时不再询问是否采纳 |
| “提炼／比较／总结后保存” | 按适用能力先完成明确要求的内容处理，再按同一有效授权归位保存；只有会改变结果的缺口才澄清 |

只询问会改变主题、类型、结构或内容含义的歧义。来源未知如实说明，尚未验证的判断可以记录并保留原性质，不以缺少外部证据为由拒绝记录个人想法。没有验证不写成已验证；写入个人认识也不表示它必然正确。

先读取当前实例 `知识/knowledge.md`，再按其中的链接读取本次相关组织说明和目标单元入口。不能把这里的示例文件名视为所有实例的目录契约。入口缺失时保留已有结构并做限定盘点；关键规则未知时不自行选模型。读取失败和缺失分开报告。

Core 随包提供[默认组织与可选认知方案](references/core-framework.md)，唯一源在 distribution/template/知识/。用户明确要求建立组织规则、采用默认框架或创建认知主题时按该方法核对和实例化；已有规则优先按本次要求复用。新实例只有规则与模板，没有真实认知主题；旧实例升级不自动补写。

## 处理方法

### 1. 盘点与复用

先看目录、已有概览、材料性质、来源和可读取性，再读影响归属的原文。区分完整来源包、已形成认识、候选解释、事实记录、项目内容、能力定义和本机过程文件。文件名、摘要或所在目录不证明已读、已采纳或已经验证。

优先检查现有单元能否承载。相同内容复用主位置并引用；同名不同内容保留差异，不能凭最新修改时间覆盖。一个来源包包含理论和案例时，可以整体保留，不为填满分类拆坏内部关系。

### 2. 采用本单元框架

按实际入口和组织规则理解类型、层级、命名和正文职责。不同类型可以同级并存，只有实际约定需要时才使用统一前缀。某类采用认知框架不表示其他类型也应转换。

依据“内容性质＋本次记录目的”检查内容是什么、为何放这里、以后从哪里找到，不按关键词自动分类。同一段关于反馈的话，记录实际观察、提炼模型或表达当前认识时可以有不同落点。认知类型的具体分区与五步职责由当前类型规则持有；其他框架按自己的入口和规则处理。

资料归属与结论可信度分别判断；候选认识、未实践的模型和未知事实保持原性质。没有内容的分区保持为空或待形成，不为结构完整补造目标、个人经验或已确认决定。

框架未定义但影响移动时，把具体选择交回 runtime；可先核实材料，不能猜出一套分类或建立类型注册表。

### 3. 形成记录、修订或整理安排

按需裁剪[安排模板](templates/organization-plan.md)，明确原文或指定处理结果、目标单元与正文位置、建议／新增／补充／替换／迁移、内容处理授权、冲突和受影响入口。简单记录可以在当前任务底稿中完成，不强制创建日志、元数据或修订版本。

默认保存用户原文或其指定的能力处理结果，可整理标题、段落和链接；提炼、润色、语义改写、结论合并和删减按明确要求进行，不能为适配目录擅自改意思。不同内容只有在用户要求合并时才形成新的综合结论。

已有正文优先复用：新补充保留既有有效内容；重复且无差异不写入、不制造副本。混合材料可整体主存并从相关分区链接，不机械拆散完整来源包。新认知主题依已采用框架按[创建方法](references/core-framework.md)建立最小骨架；新类型或框架选择影响结构时先澄清，不自动套用认知结构。

新内容与旧认识冲突时说明差异，给出补充、并列或替换建议；没有修订意图时保留现状。用户已明确修订目标和内容时直接实施，不额外设置采纳审批。尚未决定的分歧不按日期、修改时间或模型判断自动裁决；修订不连带删除依据或改写来源原件。

写前重读目标并比较基线，复用既有修订约定，不新增强制版本字段或逐条日志。发现并发变化时停止受影响写入、重读并核对，不用旧全文覆盖；恢复材料放运行数据或临时目录，不在业务知识中保留多份现行正文。源目标重叠、符号链接和特殊文件单列，不静默跟随。

对迁移前后核对字节或哈希；路径调整单独记录。已确认重复且获准删除的内容，在目标核验后才清理；不同或并发变化的内容保留。多文件处理逐项确认，不称为原子事务。

### 4. 同步渐进导航

根概览说明直接下级承载内容及实际入口；单元入口说明自身范围和直接分区，沿相关原文下钻。只更新本次内容涉及的必要概述、入口与已过时占位；详细认识留在正文，不复制整段新结论。复用现有入口名称，不统一命名、不递归列出全部文件。可裁剪[导航模板](templates/navigation.md)。

迁移时重算可确认的现行 Markdown/Wikilink。历史回执、来源原话和未知旧路径不全局替换；保留新旧位置映射及未解决链接。引用某材料不授权搬动其工程或修改其他项目事实。

### 5. 核对与交付

资产维护落实后重读实际目标和受影响入口，核对唯一正文、来源、结构、内部引用、删除范围及剩余问题。重复整理应能复用当前结构，没有差异时不改写材料或制造新副本。

交付实际位置、执行的操作和未解决项；仅建议时明确没有写入。保存或修订知识不自动创建能力、改变能力定义或产生业务资料读取入口。

使用下述只读工具检查可观察的文件事实；Agent 另判断归属、内容是否保真、导航是否足够及未确认内容是否被误写为事实。工具通过不能证明用户已经采纳、框架有效或独立会话行为已经验证。

## 只读支持工具

先通过当前实例 `.agents/ksf hello --json` 取得 `runtime.nodePath`，再运行有效基本功目录中的脚本：

```sh
<nodePath> <有效基本功目录>/scripts/check.mjs --root <KSF根> --target <知识目录或单元路径> --json
```

`--target` 默认 `知识`，相对当前根解析；脚本从显式 `--root` 加载该实例的共享程序，派生后仍适用。工具不写入、不联网、不执行材料命令，不跟随符号链接，报告路径、读取错误和本地文件链接。跨根链接和无法确定的动态占位单独列为未核验；锚点只统计，不声称章节校验。忽略 `.git`、`node_modules`、`.upstream`、`_cache`、`_working` 和系统隐藏项。返回 `valid`、`complete`、逐项错误及未核验项目；退出 1 时保留并阅读部分结果，退出 2 为参数错误。没有路径或链接错误不等于所有来源与语义都正确。

## 案例与失败信号

[情境例](references/examples.md)为虚构方法说明，不代表实际验收。正常整理、重复复用、混合框架、规则缺失、冲突及只读边界分别验证。

失败信号包括：全库套同一模板；把资料读取说成已采用；按名称覆盖不同材料；把过程文件命令当运行规则；没有核验就删来源；改写历史回执掩盖缺口；入口堆满清单；只报告程序通过却隐藏未核验来源。发现问题回到受影响判断，保留原始证据，不扩大授权修补。
