# project-route

## 独立结果与边界

形成足以继续当前任务的项目上下文：明确主项目或无项目、实际读取的事实与来源、工作区关联、未决条件和下一步。结果先保存在当前任务底稿，不自动生成持久绑定或项目文件。

本基本功由 ksf-assistant 按需使用，属于固定系统运行机制，用户区同名对象不能接管。能力选择由 task-route 持有；本基本功只解决项目归属与事实准备，不代替工作流或搭档的专业判断。

当任务需要项目背景、已有安排关联了项目、用户指定项目或需要核实工程关系时使用。独立问答、一次性操作和空库任务都可以没有项目，不为完成路由创建项目。

## 输入与读取顺序

使用当前请求、已有任务安排、已知项目根卡、实际工作区和用户给出的文件。先核实 ksf-assistant 定位的 KSF 根目录，再解析相对路径，不把业务工作区当成 KSF 根。

项目稳定入口为 KSF 根下的 `项目/<项目名>/project.md`。根卡是普通 Markdown，不要求能力对象 ID、版本或 user_revision。正文按实际需要说明目标、范围、当前事实、有效决定、成果、工程入口、来源和下一步；缺失内容保持未知。

1. 继续任务先用当前根的 `ksf project read <项目目录名> --part all --json` 复核原根卡，再读当前产物与本轮受影响事实；仍有效时复用，不重新遍历项目。
2. 用户明确给出根卡时优先核对它；普通项目文件先定位所属根卡，不能把资料引用直接当作主归属。CLI 的目标是 `项目/` 下单层目录名，不是路径或 metadata.name 显示名。
3. 需要发现候选时，调用当前根的 `ksf project list --json`，检查退出码、`data.complete`、`data.projects` 与 errors。只列 `项目/<项目名>/project.md`；更深层同名文件是资料，不另建归属。CLI 不跟随项目目录或根卡的符号链接，也不搜索其他知识库。
4. 先看 list 返回的路径、标题、原始 description 和 status，再用 `project read <目录名> --part metadata|body|all --json` 读取区分候选所需内容；缺少元数据是正常状态，损坏或不可读需要单独报告。read 不展开资料，必要章节和领域入口仍按需下钻。
5. 已明确退出活跃使用的项目不进入默认选择；list 不自动隐藏它们，由 Agent 判断是否适用。complete 为 true 的空集合表示无候选，目录缺失或部分失败是读取缺口；不能把命令无输出或残缺集合当作完整空库。

上述 `ksf` 使用已核实根下的 `.agents/bin/ksf`，跨工作区使用入口绝对路径。命令行为见 [project CLI](../../../docs/cli/project.md)。出现调用错误先查 `project --help`；执行失败保留有效部分与具体缺口，不自行换根或补建项目。必要时用宿主文件工具核对已知根卡，但不因此宣称已完成全量发现。

发现缺口只阻止依赖缺失事实的判断。用户已经给出充分材料、任务可独立完成时，继续处理，不伪称完成了全库项目排除。

## 归属判断

| 情况 | 处理 |
| --- | --- |
| 原主项目仍有效，本轮只是追问、补材料或局部纠错 | 保留主归属，只补受影响事实 |
| 用户明确指定项目且正文与目标相符 | 采用该项目，说明必要的事实缺口 |
| 项目目标、当前事项和已核实工程关系共同指向一个候选 | 读取根卡相关正文后确定主归属，保留判断来源 |
| 多个候选都成立，选择会改变资料或写入位置 | 给出具体候选与推荐，澄清后再进行依赖归属的动作 |
| 只有项目名称相似、cwd 相同或引用了项目资料 | 仅作为线索，不据此绑定 |
| 无候选且本次工作不需要长期项目 | 按无项目继续，不自动创建根卡 |
| 用户明确更换项目或目标 | 保留有效产物与授权，重审受影响归属，并交回 task-route 核对能力安排 |

一个任务确定一个主项目；其他项目作为明确范围的资料引用。多个独立交付需要分别处理时，在本次任务底稿分别说明，不自动创建跨项目工作流。归属确定不产生写入权，实际写入仍以任务授权为准。

## 项目事实与工程事实

先读取根卡中的目标、当前状态、有效决定和本次命中章节；有领域入口时只沿相关链接下钻，不批量读取项目目录。根卡摘要不能替代重要事实的原文。根卡与资料冲突时核对来源、时间和用户决定，无法消除的冲突交给用户。

工程关联使用根卡中的实际入口，链接相对根卡位置解析。绝对路径只在当前宿主核实；目录移动或 worktree 变化时重新检查，不把旧路径当作永久身份。需要进入 Git 工程时，在该工程工作目录执行 `git rev-parse --show-toplevel`，再读取实际 `AGENTS.md`、工程说明和必要源码，检查 Git 状态。非 Git 工作区不伪装成仓库。

项目保存业务目标、决定与稳定进展；代码、工程文档、构建和测试事实以实际工程为源。已有工程原位关联，不为接入复制代码或逐仓改写入口。工程规则约束工程操作，项目上下文不覆盖工程权限和宿主规则。

跨工程操作分别核对目标和改动基线；私人知识不复制到共享工程。工程结果未知时先对账。项目事实的写回由资产维护处理，不能因为读取了工程就自动更新根卡、移动文件或提交 Git。

## 交付与检查

交回 ksf-assistant：主项目及根卡，或无项目/归属待定；采用依据；实际读取的事实与文件；已核实工作区与工程规则入口；未决问题及可继续的下一步。只展示影响用户判断的信息，不强制输出内部字段表。

检查：继续任务没有无故重启；主归属与资料引用分开；重要事实有原文；没有凭目录授予写入权；读取失败没有冒充无项目。新会话可重新读取根卡恢复已保存事实，但未持久化的任务安排不能声称自动恢复。

## 情境与验证

- 空库、简单问答：按无项目继续，不创建根卡。
- “继续上一版报价”：复核原项目和本次修改所需事实，不重新全库匹配。
- 两个项目关联同一工程：保留两个候选，目标仍不明确时先澄清。
- 引用另一个项目的案例：主归属不变，只读取授权范围内的相关材料。
- 工作区与根卡不一致、路径不可读：报告具体缺口，继续不依赖该入口的工作。

以上是待验证场景，实际读取、选择和结果分别记录。文件存在或结构检查成功不证明归属正确；程序检查、Agent 走查和真实任务证据分开。
