# 系统贡献

## 输入与结果

输入为实例根、已提交到该实例 Git HEAD 的系统改动、明确选择的系统路径、标题说明及准备或公开提交授权。结果是可审阅的冻结贡献，或经远程复核的 PR 状态。用户能力定制仍在用户区；本地修复、本地 Git 提交和公开贡献分别依据用户要求执行。贡献命令不自动暂存、提交或推送个人仓库。

## 方法与分支

1. 读取[Git 规则](../../../docs/git.md)，核实当前实例的 Git 根和最新本地提交。只比较 HEAD 中的系统文件与同一提交保存的正式 Core 基线；暂存区、未暂存修改和未跟踪文件均不参与，也不要求工作区干净。没有 Git、没有 HEAD 或基线缺失、损坏、属于开发包时说明具体缺口，不退回工作目录凑出贡献；先有本地提交，才能准备贡献。新实例凭据不内嵌文件清单或原文，准备时联网取得该准确 Core 提交的系统树及必要原文并校验；不能使用最新 main 替代。
2. 按[提交信息规则](../../../docs/git-commit-message.md)从选定系统差异整理公开标题、原因、变更和实际验证，再按[PR 说明规则](../../../docs/pr-description.md)用同一事实生成背景与目的、主要变更、验证结果及影响与兼容，按需补迁移与审阅重点。两份正文分别做格式和内容核对。`contribute prepare --paths <明确系统路径...> --title <标题> --body-file <提交正文文件> --pr-body-file <PR正文文件> --json`（Git 正文也可用 --body，PR 正文也可用 --pr-body，各自二选一）从 HEAD 冻结具体差异。比较的是完整系统状态，包含之前多次本地提交的累积变化；只有确实要求全部系统差异时才用 `--all`。`--dry-run` 不保存计划。无差异时如实交付，不把未提交文件自动提交进去。检查返回的 warnings：同一本地提交或相同系统内容有既往发布记录时，展示原贡献 ID、已核实 PR 链接及 open／closed／merged；未知状态说明待核实。
3. 通过 `contribute read <ID> --json` 核对 sourceCommit、Core 原提交、版本、基线摘要、公开 diff、完整 commitMessage、含来源说明的完整 prBody、ID 和 digest，检查选定文字是否适合公开。仅要求本地修改或尚无公开授权时交付可审阅结果；已有针对该具体内容的有效提交授权时继续，不重复确认。首次公开前 HEAD 新增或切换提交须重新准备；继续编辑工作目录或暂存区不改变冻结内容。
4. `contribute submit <ID> --reviewed <digest> --dry-run --json` 仅检查本地条件，remoteVerified 为 false，不能据此宣称远程基线、权限或合并条件已验证。真实 submit 在公开授权下先核对选定路径的原版 Core 内容和权限，再从该 Core 提交建立独立贡献分支及草稿 PR。不上传个人历史、作者配置、个人提交说明或本地 sourceCommit；Core 提交使用冻结的完整 commitMessage，PR 使用独立冻结的 prBody，不在发布时临时添加内容，不自动变基或合并。不同计划的相同内容先只读核对既有 PR 并返回 duplicate，不重复创建；只有同一节点、选定内容不同则提示已有选择，不将其误判为完全重复。部分成功引导恢复原 ID，状态未知时停止新发布。
5. 响应不明时保留 ID、digest 与状态，重试同一计划先对账。缓存 URL 不代表 PR 仍有效；核对远程分支、提交、目标和 PR。已记录发布提交的重试可在本地 HEAD 前进后核对旧计划，不把新修改并入已有贡献。PR 说明可随评审由用户或按授权使用正常工具更新，重试不覆盖远程标题和正文，也不声称它们仍与初始审阅文本一致。提交内容、消息或目标变化及无法查明时不覆盖、不重复创建；已合并或关闭则交付真实状态。
6. 旧 schema 1／2／3 计划仅供读取和已有 PR 的只读核对，不能发起新发布，也不能补造本地提交来源或独立 PR 正文；schema 3 的冻结消息仍须核对。核对返回链接、提交、目标、draft、state、merged 及 reused；仍为草稿时说明 Ready for review，已送审、合并或关闭时报告实际状态。

## 质量与验证

交付选定路径、本地 sourceCommit、Core 基线、ID、审阅摘要、验证结果与实际 PR 状态；没有远程结果不声称已创建或合并。CLI 及协议见[contribute](../../../docs/cli/contribute.md)与[发行协议](../../../docs/distribution.md)。凭证仅按现有认证契约取得，错误不得回显秘密。

模拟正例：选定修复经审阅后提交，网络中断后找到同一 PR。反例：把个人 main 整体推给 Core，或只返回旧缓存 URL 就宣称远程未变。边界例：远程分支被改、PR 已关闭、预览后 HEAD 前进，分别停止覆盖、报告状态或重新准备；仅工作目录继续修改不影响冻结贡献。程序测试使用模拟 API；没有真实远程提交时明确标注。
