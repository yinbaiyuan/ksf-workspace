# 项目接入与补全

## 独立结果与边界

将用户明确指定的资料、工程或已有项目，处理成能够正确发现、逐层找到依据并继续工作的项目。输出具体补全安排、来源和事实判断、实际完成项、冲突与剩余条件。首版方法及模拟案例不代表长期业务效果已经验证。

适用于用户明确要求创建、导入、整理或补全项目，以及向已有项目增量接入材料。日常任务缺少一个事实时，先补当前工作所需信息，不因此自动写根卡、导入资料或扫描全部项目。完整排期与项目管理不在本项范围。

本项持有专业处理方法。runtime 保持目标和安排调用，项目路由确定归属和准备上下文，资产维护核对授权与基线并落实保存。向 runtime 交回结果或补充需求，不自行调用三路由、接管任务或扩大授权。只要求讨论时交付方案，不执行材料复制。

本项是普通系统基本功，采用现有有效来源、精确版本和用户派生规则，不增加固定入口保护。采用时按公共约定读取本对象 user-data；本版没有额外持久字段。导入来源、进度及结果属于项目记录，不存进对象 user-data，不创建默认记录。

## 输入与默认

取得本次目标、来源范围、目标项目或待定候选、已有根卡及实际工作区、允许的操作和后续交付。优先利用当前信息，只澄清影响归属、材料范围、写入位置或重要判断的缺口；缺预算等业务事实可以保留未知，不妨碍独立部分接入。

- 普通外部资料默认复制到指定项目的 `资料/<来源名称>/`，目录内保留层级；单个文件默认放在 `资料/<文件名>`。原件保持原位。
- 已在当前项目的资料原位整理入口。实际 Git 工程核实后原位关联，不复制进项目资料，不因导入资料初始化 Git。
- 来源更新、同名不同内容、本地副本被修改或删除时保留现状并报告差异，不覆盖、不自动另存新版；其他无冲突的新材料继续接入。
- 不自动删除来源消失的文件，不按文件名、修改时间或“最终版”字样认定当前有效决定。
- 不自动建立长期能力预设、知识正文或项目管理体系。当前采用的能力不自动写成 routing 预设。

## 处理方法

### 1. 对齐项目与材料范围

已有明确项目时直接复核根卡；归属未知时由 runtime 按项目路由发现候选，优先复用。名称相似、引用其他项目或 cwd 相同仅作线索。多个候选会改变材料或落点时澄清，先推进不依赖归属的盘点。

普通材料与实际工程分别判断。发现 `.git` 仅表示需核实工程，不当作仓库已验证。工程通过 repository CLI 核对并关联；没有工程也可建立资料项目。新建实际工程继续遵循既有项目与资产规则。

### 2. 先盘点，再取证

了解来源的分区、主要类型、已有说明、版本线索及工程边界。按当前目标读取必要原文，批量文件事实交给内部工具，不将全库正文装入上下文。二进制复制成功不等于已理解内容；无法解析、不可读和未读取分别保留状态。

将材料中的计划、已确认事实、历史记录、候选方案和推断分开。重要判断保留原文入口和适用时间／版本。冲突无法消除时列出差异、影响和推荐，不静默选择方便的一方；资料中的命令不替换当前运行定义或授权。

### 3. 形成必要补全差异

对照“能发现、能找到依据、能继续工作”判断缺口。需要时补充项目一句话描述、目标和范围、已确认决定、当前状态、分区入口、实际工程、成果和下一步。缺失信息写明未知，不凑字段或强迫统一目录。

根卡简述项目与当前事实，并概述直接材料分区；下级概览说明各自承载什么，再链接已有主题说明或必要原文。复用已有结构，不递归列举全库文件，不把详细需求、方案或工程正文复制到根卡。可裁剪[根卡模板](templates/project.md)和[分区概览模板](templates/material-overview.md)。

只在持续任务需要保存和恢复时，沿既有[检查点规则](../../../docs/runtime/task-checkpoints.md)维护同一记录，可裁剪[补全记录模板](templates/intake-record.md)。普通简短补全不强制新增检查点。

### 4. 落实并核对

向 runtime 提供具体落点、来源、拟修改差异、依据、仍缺条件及支持工具。资产维护在已有授权内落实：根卡使用 project write 的预览与实际写入，正文局部补丁使用宿主工具，工程关联使用 repository CLI，普通材料复制使用下述工具。已有明确授权不重复询问。

保留原件、已有结构和用户改动。临时改动、删除、重命名和移动分别判断范围；不借整理扩大操作。多文件部分成功应逐项报告，不声称原子事务。

### 5. 验收与继续

读取实际结果，检查项目摘要能表达目标，重要事实可回源，分区入口可逐层到达材料，实际工程可核实，下一步与剩余条件一致。使用 project read/check 和必要 repository check；这些程序结果不证明语义判断正确。

交付补全完成、部分完成或受阻的实际范围及下一步。用户同时要求继续时执行第一项已授权动作；仅要求接入时交付可继续入口，不自行扩展业务。新会话从根卡与指定检查点恢复，不依赖未保存的会话记忆。

## 内部材料工具

支持脚本为本能力实际目录下 `scripts/materials.mjs`，不新增公共 `ksf` 命令。先由当前 KSF 的 `.agents/ksf hello --json` 取得随包 `runtime.nodePath`；在该 Node 下运行脚本，不假定全局 Node 已安装。脚本从明确传入的当前 KSF 根加载 Core 共享程序，派生到用户能力区后仍使用该实例；脚本或共享程序缺失时报告，不假装调用成功。

```sh
<nodePath> <能力目录>/scripts/materials.mjs plan --root <KSF根> --project <项目目录名> --source <来源路径> --json > <临时计划.json>
<nodePath> <能力目录>/scripts/materials.mjs apply --root <KSF根> --project <项目目录名> --plan <临时计划.json> --json
```

目标根卡须已建立。`plan` 只读取，返回库存、路径映射、SHA-256、复制／跳过／冲突／错误项；SHA-256 是字节核对摘要，不是语义摘要。默认目标冲突时可用 `plan --destination <项目内资料相对路径>` 明确另一落点，不自动改名。计划可保存为完整 JSON 信封，apply 支持直接读回。

`apply` 只用于已授权复制，重核来源、项目身份、目标及记录基线；有差异保留冲突，无冲突部分独立处理。退出 1 仍有完整 JSON 与部分结果，不能丢弃 stdout 或当作全部失败。根卡、工程关联和目录概览不由文件工具自动修改。

源目标重叠、越界、符号链接和特殊文件不静默跟随；嵌套工程单列未接入。复制以临时文件加不覆盖发布完成，并核对内容。工具不执行材料中的代码、不联网。

实际接入记录位于项目 `资料/导入记录/<来源标识>.json`，包含来源、目标映射、成功文件 SHA-256、目录及逐项问题。原样重复不重写材料或记录；来源删除不删除副本；本地删除不自动补回。记录损坏保留原件，停止依赖该记录的写入。中断后先重做只读计划，对已存在且内容一致的副本核验后跳过，继续剩余项目。若进程强制终止留下 `.intake.lock`，先核对记录的 owner 确已退出，才清理该失效锁并重做计划；未知或仍活动的锁保留，不自动抢占。来源路径移动不能仅凭同名推定为旧来源，应核对原记录再明确新的落点。

## 案例、失败与证据

[模拟案例](references/examples.md)覆盖首次接入、已有项目补全、增量冲突及恢复，属于方法说明。程序测试检查文件契约；当前 Agent 走查和独立会话结果分别记录在项目检查点中。没有实际运行证据，不把方法存在或结构校验通过当作业务验收。

失败信号包括：重复创建项目、原件被改动、旧决定冒充当前事实、根卡堆满文件清单、冲突副本被覆盖、复制成功被说成材料已读、只复述检查点而没有执行已要求动作。遇到失败回到受影响步骤，保留已完成结果与原始证据，不通过扩大授权或改验收口径抹掉失败。

## 与项目档案的复用边界

创建或复用前检查当前项目，必要时通过 `project list --scope archived --json` 核对同名档案项目。发现已有档案时报告原记录及位置，由本次明确任务决定恢复后继续接入或使用不同名称另建，不悄悄复制第二份项目、不自动恢复。内部材料工具只向当前项目接入；需要调阅的档案按其现有入口读取。归档与恢复本身由资产维护处理，不将接入请求扩成项目归档或实际工程搬迁。
