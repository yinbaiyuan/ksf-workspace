# KSF 工作台前端

## 当前：PC Web OS 首版

工作台支持独立应用安装：内置“应用商店”管理默认源、多个 HTTP(S) 自建源、安装、启停、升级与回退。外部前端通过动态 import 加载预构建 ESM，后端按应用共享，终端等资源按窗口租约隔离；已打开的工作台无需刷新或重启即可安装应用。Terminal 是通过相同机制分发的真实本机 PTY 应用。协议、信任边界、SDK、打包及自建源发布方法见 [应用机制](../../docs/applications.md)。

入口为 http://ksf.ai:1313/，通过 hosts 解析；后台使用当前用户服务。根地址显示上次桌面分组。左侧64px窄图标栏仅在桌面出现，默认半屏高并垂直居中，图标增多时自动向上下延长，超过上限后列表滚动；座右铭回到页面左侧。支持分组切换，悬停和聚焦显示名称，底部有新增与设置。初始主页承接旧卡片布局，新组为空白；支持名称、图标、排序和确认删除，至少保留一组。卡片编辑支持拖动/缩放、方向键与Shift＋方向键，完成保存、取消回退，编辑未保存时切换分组可保存、放弃或继续。

Logo和侧栏设置按钮打开统一设置窗口，依次为桌面管理、外观设置、采集与诊断、后台运行、关于 KSF。面板紧贴左上角Logo下方，向右下展开，与侧栏统一距网页左边缘8px，Logo与侧栏图标中心对齐，目标860×620px，右侧和底部至少16px留白，小于640px改为顶部分类导航。无顶部标题栏和关闭叉号，直接呈现左侧分类与右侧内容，保留可读名称；顶部两角为直角，底部18px圆角；Escape和遮罩关闭，恢复入口焦点。标题区由142px缩至96px，卡片整体上移46px，座右铭高度不变，编辑工具换行后卡片滚动区自动填满剩余空间。

Dock保留对话、文档、Git和显示桌面。应用全局窗口不随分组关闭，侧栏隐藏时最大化仍贴齐原工作区四边。右键Dock可新开、切换和并排，支持Shift＋F10、方向键及Escape；顶栏右侧只有日期时间。采集状态卡已退役，旧版路由仍在对话应用内部。

应用统一标题栏及 Git 三栏布局以 [标准应用窗口](../../docs/cli/web-workspace.md#标准应用窗口) 为唯一规范。应用使用 `WindowToolbar` 接入框架持有的每窗口工具栏位置。

编译期扩展点：`src/desktop/registry.tsx` 的 AppDefinition / WidgetDefinition。`desktop.tsx` 统一启动、聚焦和管理实例；`desktop-model.ts` 持有边界与持久化；`window-context.tsx` 隔离搜索、分栏及阅读；`remote-cache.ts` 按 URL 去重；`overlay-coordinator.ts` 管理模态抽屉归属。新增应用只需定义并注册，不复制全屏入口；新卡片组件、名称及尺寸同样在注册表声明。

窗口采用 react-rnd@10.5.3，卡片采用 react-grid-layout@2.3.0。react-draggable 的选择样式已预置本地 CSS，生产 stylesheet link 带 `react-draggable-style-el` 标记，避免拖动时注入 inline style；脚本 CSP 保持同源；编辑器动态样式使用服务端 nonce，字体随包提供。UI 样式只通过现有 CSSOM 属性更新。依赖许可随生产资源重新收集。

应用窗口现为实色界面：窗框、内部导航、选中态、章节和来源抽屉均不再挂载玻璃效果。雪山与桌面卡片、Dock、状态栏、桌面按钮和系统抽屉材质保留，设置中只显示有效对象；旧窗口光学参数作为兼容数据保留。

ksf.workbench.desktop.v2 保存分组列表、每组布局、当前分组ID与普通窗口尺寸，不自动重开窗口。优先读取v2，缺失/损坏时读取v1并迁移为主页；首次保存写v2，v1不删除。空组保持空白，退役/未知卡片过滤，其余合法位置尺寸和窗口偏好保留。保存失败显示“仅本次生效”。旧位置、分栏和材质键继续可读。活动窗口URL关联浏览器历史，兼容旧project/tab/view=routes链接；隐藏页暂停轮询，最小化停止专属请求，无变化数据共享，失败保留已有内容。

显示性能已完成首轮优化：缩放复用折射贴图、按区域合并布局读写、实色应用窗口、隔离 Markdown 更新、轮询结构共享及时钟独立更新。相同连续缩放动作的主线程耗时从 4.83s 降为最终实色窗口的 0.208–0.226s；具体方法、三轮结果和限制见 [PERFORMANCE.md](PERFORMANCE.md)。

第二轮已复核打开应用、拖动、切换与长对话滚动，并优化日期格式器复用、收起记录延迟渲染、可中断切换、布局隔离及多余请求。普通四路径最终无超过50ms任务；4倍CPU/DPR2压力条件仍有约59–65ms渲染峰值，详见性能记录。

当前实现与验证见 [WEB-OS-REVIEW.md](WEB-OS-REVIEW.md)。下文保留的历史版本结论不作为本轮验收。

React + TypeScript + Vite + Tailwind CSS。`src/components/ui/` 使用 shadcn/ui 的源码组件方式，在 Radix primitives 上定制按钮与 Sheet；图标使用 Lucide。组件随源码维护，不依赖远程组件服务。Markdown 使用 react-markdown / remark-gfm / rehype-sanitize，不解释原始 HTML，不加载远程图片。

桌面卡片区宽屏两侧均留72px，取消宽度上限和叠加内边距。正方形基础格以96px为最小目标，选择1–12列后将剩余宽度均分，整行铺满可用宽度，横纵24px间距；尺寸为正整数n×m，默认2×2/4×3/2×2，名称位于卡片底部。编辑显示网格和尺寸，支持吸附拖动、缩放及方向键；1×1等窄卡片使用紧凑入口。可见列数随视口变化，窄窗排布不直接覆盖保存数据。旧v1/v2布局换算到正方格单位，保留分组与窗口偏好；grid: square-v1标识避免重复换算。卡片编辑全程使用轻量实时预览，暂停该网格的折射更新，点击完成或取消后恢复最终材质；拖动、缩放和松手均不重建材质，编辑时取消过渡动画。仅容器宽度变化重新计算网格，保持保存/取消与整数占格逻辑。`CardGrid`为react-grid-layout 2.3.0补齐格内像素位置刷新：每帧最多刷新当前卡片，保留其他卡片内容引用；移动与缩放连续跟手，占位和松手结果按整数格吸附。布局草稿仍只在操作结束时更新，退出或卸载取消排队刷新。

## 文档与 Git 应用

文档提供 CodeMirror 6 即时预览、源码、分栏和阅读，支持本地图片、GFM、公式、Mermaid、全文搜索和大纲。直接保存 KSF 原文件，800ms 自动保存、IndexedDB 恢复草稿、内容版本冲突保护；系统源码按文件显式解锁。Git 支持实例与多仓库概览、diff 和按块暂存、提交、分支、远程同步、stash、历史树和冲突处理。接口、文件边界和失败恢复见 [文档与 Git 应用](../../docs/cli/web-workspace.md)。

`src/apps/` 持有客户端、文档缓冲区、CodeMirror 编辑器、受限预览及 Git 应用；`src/services/workspace-files.js`、`workbench-git.js`、`workbench-http.js` 在 runtime 后端提供分离服务。应用通过 `openApp` 联动，关闭保护按窗口注册。新入口为 `?app=markdown&path=...` 和 `?app=git&repo=...`，旧对话链接保持兼容。

## 开发与构建

遵循[统一测试规范](../../docs/testing.md)。首次准备、锁文件变化或环境失效时执行 `npm ci`；定向修改按需执行类型检查、`ksf test --component web` 和前端构建。依赖版本固定在 package.json 和 package-lock.json。构建必须使用 KSF 已安装的随包 Node：将 `ksf hello --json` 的 `runtime.nodePath` 所在目录放到开发命令 PATH 最前，npm 可使用开发机已有安装。发行用户不需要 npm。

`npm run dev` 仅供开发，监听本机并将 `/api` 代理到 127.0.0.1:80 的现有 KSF 服务。日常使用从 KSF 根运行 `.agents/ksf web`，它只提供 `dist/` 中校验过的预构建资源。

`npm run build` 执行类型检查、Vite 生产构建、运行依赖许可整理，并生成 `dist/build.json`：源码/锁文件摘要与构建资源的逐文件 SHA256。构建不依赖用户的项目、对话或个人信息。输出的 `dist/THIRD_PARTY_NOTICES.txt` 随包保留。Vite 清单用于收集所有入口、分块和样式，不把 dist 整个目录开放为静态目录。

Core 的 `.agents/ksf build --json` 以及 Web 启动核对构建新鲜度与资源校验和；失败时提示前端重建，不自动联网安装。开发依赖、Vite 缓存、覆盖率、测试输出及界面验收截图从系统摘要、贡献和发行中排除。源码、锁文件与 `dist` 都属于正式 Core 资产。

## 行为约定

- 地址通过 target、task、原生 turn（旧 project 映射兼容） 保存选择，section=request/route/result 保存章节定位；旧 tab=conversation 定位请求，tab=route/routes 定位路由，旧版入口保留 view=routes 与 session。
- 归属目录来自全部历史事件的主归属，分项目、知识、能力、档案四组，标题不增加导航层级。聊天只出现在曾明确作为主归属的对象下；关联对象不收录聊天。默认打开最近以当前对象为主归属的轮次，不复制原件；知识按精确入口路径区分。
- 轮次栏自动读取全部摘要页供筛选和前后轮浏览，正文按所选轮次懒加载；保留完整聊天上下文，标出本项目、本知识单元、仅关联、其他归属、无归属、待确定、未上报、未记录；轮内主归属切换显示顺序及最终归属。
- 本轮同页按请求、路由、结果三段展示。用户原话约八行预览，可展开全文；复制与原文始终使用完整内容。路由使用默认展开的纵向演进线，首节点完整呈现主归属、关联项目／知识和四类能力，后续节点显示前后差异；节点及来源详情绑定当时事件。最终答复默认展开，过程说明、交互问题、用户选择与其他可见回复统一折叠并保持原始顺序。每条消息只进入一个分区，未知阶段不丢弃，缺少最终答复不根据完成状态补造。固定入口不展示，原始记录保留。
- 路由演进按档案顺序计算，仅主归属、关联对象、能力选择/读取/采用、增减与精确定义差异产生节点；同次多项变化为一个节点，跳过的能力阶段不补造。排列顺序、固定入口、来源查询装饰、摘要、说明及 Agent 处理状态不产生节点。原始上报与 Agent 状态从记录信息进入，主路由不显示上报次数或状态更新分组。
- 新轮次与新路由在一个更新区域提供准确跳转；新路由提示比较实质安排，纯状态上报不触发提示。正常主归属不重复提醒，仅关联、其他归属关系在路由区标注，归属切换沿演进线呈现。读取错误及采集缺口集中在记录信息，其入口提示数量。
- 可见页面每 3 秒刷新；隐藏时不发新查询。解除已离开的查询订阅，在途共享请求不影响其他窗口；失败保留上次成功数据；分页按 ID 去重。历史轮次、展开状态、滚动和抽屉不随轮询重置。
- React 负责文本转义，Markdown 另行清洗。只允许显式 http/https 链接，原始附件及本地引用显示为文本。Radix Sheet 的遮罩不启用会注入内联 style 标签的滚动锁，保留生产 CSP。

## 验证

后端使用 KSF 随包 Node 的 node:test。前端 `npm test` 验证消息分区与去重、原件不变、多最终答复、未知阶段、章节及旧链接定位、默认轮次、路由差异与链接处理。浏览器检查按具体迭代记录在下文，自动化测试、人工走查和用户验收分别表述。模拟示例始终在临时根创建并标明，真实工作区不插入演示任务。

## 归属与聊天导航

主工作台采用项目／知识／能力／档案分组的归属聊天树、完整轮次栏、同页证据阅读。`/api/task-targets` 只聚合历史主归属，没有归属记录的知识单元不预铺菜单。虚拟入口区分无归属、待确定、未上报、未记录。计数、默认轮次与最近上报使用 targetContext，不复用聊天整体 latestReported 冒充归属事实。

接口：/api/task-targets；/api/tasks?target=...；/api/tasks/:taskId?target=...；轮次正文按需加载。旧 /api/task-projects 和 project 查询继续兼容。URL target/task/turn 可刷新与前进后退，旧 project 链接解析后保留轮次。查询不写历史原件，来源不可用不自动改绑，只讨论知识不自动编辑正文。

待创建目标以稳定 targetId 聚合，目标落成前显示“待创建”；绑定后主身份不变，演进投影新增目标建立事件，不伪造成主归属切换。目标详情与采用能力分开，技术信息显示身份版本和精确定位。历史目标使用当时快照，currentBinding 只作后续信息；目录生命周期可显示当前绑定状态。绑定别名用于兼容没有独立旧历史的物理键，旧项目链接保留指定轮次。

## PC 视觉与阅读偏好

[DESIGN.md](DESIGN.md) 与 [.impeccable/design.json](.impeccable/design.json) 记录当前高峰晨光背景与原始Liquid Glass配方：导航和当前项采用对齐背景副本，按钮使用透镜几何与弹簧反馈，章节只复制已知UI标签作装饰，正文保持白色文稿。用户指定材质与意象，视觉仍待用户查看。目录和轮次默认各264px，分隔线支持拖动、方向键（8px，Shift为32px）、Home/End；轮次可收起，应用窗口1099px以下目录进入抽屉，759px以下轮次也进入抽屉。

搜索汇总各归属的服务端命中，非标题命中明确标注历史记录匹配；不会推测片段。仅已知完整问答格式呈现问题、选项与回答，原文／复制保留完整文本，损坏或未知格式回退原文。

localStorage 的 ksf.workbench.display.v1 和 ksf.workbench.position.v1 只保存显示偏好与最近阅读定位；显式 URL 优先；根地址显示桌面，继续阅读打开最近位置，失效记录提供错误提示与其他聊天入口。存储异常正常回退。浏览器历史中的已浏览轮次在当前页面会话中保留滚动位置，轮询不重置选择、展开或抽屉。手机端不在本轮验收范围。

## 关于 KSF

系统设置中的“关于 KSF”分类展示现有Logo、产品名、座右铭和真实Core版本，不加省略号。GET /api/about读取执行代码所在Core的build.json，不使用安装回执或前端包版本；失败保留产品信息并可重试。健康检查只在“采集与诊断”分类可见时订阅。
## 外观设置

系统设置“外观设置”复用原有表单，默认桌面卡片。可调整雪山背景的遮罩、亮度、饱和度与构图，以及桌面材质的染色、不透明度、折射、模糊、圆角、高光和阴影等参数；更多参数继续保留。抽屉材质预览放在设置内容内，设置本身保持实色，各分类独立滚动。

ksf.workbench.material.v1 仅在当前浏览器保存材质偏好。调整即时生效，250ms合并保存并在离页前补存；读取损坏或拒绝访问时回退默认，保存失败明确提示。保留当前对象和全部重置；系统减少透明度、高对比度和减少动态效果优先。应用内容保持实色，旧光学参数作为兼容数据保留。
