# 知识组织与导航

本文件定义本实例的知识组织、维护约定和分区入口，可按实际材料修改。未设计完整模型也能开始使用，不要求统一分类、对象 ID 或元数据模板。设计步骤与边界见 [Core 知识与档案机制](../.agents/core/docs/content-design.md)。

## 定位与保存

知识保存可理解、讨论和修订的事实、概念、解释与经验认识；具体项目进度留在项目，正式证照、合同与收口项目进入档案。方法论可以保留为知识，只有明确建立可复用处理约定时才设计为能力。

原件随所支撑的目标保存，默认在目标目录的 `资料/`，已有附属资料目录保持原位。一份原件一个主归属，其他目标引用；正文保留来源、来源日期、原件入口和适用范围，区分事实、来源观点、推断和待验证认识。

## 维护与复用

先核对已有正文能否承载，再选择无需保存、合并、修订或新建。保存后只同步直接受影响入口；有新证据时回到同一正文修订，保留分歧、限制和重要纠正依据，不整篇复制到多个主题。

读取明确文件可直达；需要扩展发现时沿分区概述逐层进入。维护或重组本目录前读取本说明。每层导航只说明当前及直接下级分区，不递归枚举全库文件，不展开业务知识正文。

## 按自己的材料设计

需要调整时，从几份真实材料开始：明确用途和使用者，确定知识单元、分类和关联，约定来源与原件位置、保存确认及修订方式，再用保存、复用和纠错样例核对。只采用本实例需要的约定，不因模板存在预建业务目录或启动问卷。

## 分区导航

尚无业务分区。形成真实内容后，在这里概述直接分区并链接下一层已有入口；复杂分区可使用子级 `knowledge.md`，已有综述可以直接复用。
