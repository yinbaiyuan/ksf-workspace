# 档案规则与导航

本文件定义本实例的档案结构、入档、版本、项目关联、归档与恢复方式，可按实际材料修改。通用设计方法和操作边界见 [Core 知识与档案机制](../.agents/core/docs/content-design.md)。

## 收录与归属

档案保存个人、企业、项目需要长期保留、查证或取用的正式资料与历史记录，既包括仍有效的证照合同，也包括不再推进的项目。会议、研究过程原件继续随其支撑的知识、方法论或项目保存。

| 分区 | 默认归属 | 入口 |
| --- | --- | --- |
| 个人 | 按人保存证件、资质及个人签署的合同 | [个人](个人/) |
| 企业 | 按企业保存营业执照、资质及该主体签署的合同 | [企业](企业/) |
| 项目 | 整体收纳不再推进的项目记录；工具位置固定为 `档案/项目/<项目名>/project.md` | [项目](项目/) |

个人、企业及其内部分类可自行设计。项目档案位置固定，以支持项目发现、归档、恢复和工程关联。复杂分区可增加子级 `archive.md`，已有说明可复用，不要求每层新建。

## 入档、原件与版本

先核对材料、主体、现有档案和唯一主归属。外来材料默认复制入档，保留外部原件；移动或删除按具体授权处理。同名同内容复用，同名不同内容保留现状并报告，不覆盖。默认用目标的 `资料/` 保存原件，已有附件目录原位保留。

证照和合同更新保留旧版本，记录来源、日期、版本与现用原件入口；未知效力明确未知，不按文件修改时间判断。材料少时直接保存文件；版本或关联需要解释时，可建立普通 `档案.md`。本说明及导航只保存必要概述，具体原件按需读取。

## 项目关联

合同按签约主体主存，项目根卡通过 Markdown 链接引用同一主件；合同的 `档案.md` 可链接一个或多个关联项目。营业执照供多个项目使用时同样引用主件。项目事实、进度和决定仍由唯一项目根卡持有，不在档案说明中重复维护。

## 项目归档、恢复与调阅

短期暂停可留在当前项目；明确结束、中止或决定收起时，先在根卡保存结果、原因、成果、未结事项及必要入口，再预览项目归档。程序整体移动项目记录、重算结构化关联并设置 `status: archived`；业务结果保留在结案说明，不由程序推断。

实际操作依次为：读取本说明与根卡 → `project archive --dry-run` → 复核目标、库存和链接清单 → 实际归档 → 审阅并修复当前有效 Markdown/Wikilink → 检查文件和关联。未验证入口前不能报告整项完成。历史 JSON 与原始来源表述保持原文，必要时用迁移说明解释旧位置。

调阅档案使用 `project list/read/check --scope archived`，不自动恢复。恢复预览和实际操作使用 `project restore`，默认恢复为 active，可指定状态；随后核实最新事实、未结事项和下一步。工程及 Git 历史始终保持原位。

归档、恢复不覆盖或合并已有目标。遇到并发变化、嵌入工程、无法保持的链接或跨文件系统移动时停止并保留原位。中断时按回执的操作 ID 使用 `project recover` 核对和回退；后续用户修改保留，不能强制覆盖。命令细节见 [project CLI](../.agents/core/docs/cli/project.md)。

## 采用与调整

维护、入档或重组前读取本说明；查找范围需要扩展时按导航逐层进入，明确文件可直接读取。根说明缺失时沿 Core 默认约定继续，不自动改名、迁移旧实例或创建个人模型。本说明指导已授权操作，不产生额外删除、对外发送、Git 或发布授权。

设计自己的机制时，从实际证照、合同和历史项目样本确定用途、归属、分区、版本和引用方式，再走查入档、调阅、项目收起与恢复。保留一份主件和可访问引用，不要求数据库或能力对象注册。
