# 团队协作示例

独立 SDK v1 应用：发送任务说明与材料，接收方决定处理，本地完成与结果回传分开。工作流由本应用定义，Core 只承担可靠传递、收件和激活。

## 使用

1. 运行 `ksf-app create <目录> --template collaboration`，检查、构建并在两端安装生成的开发包。
2. 选择节点，点击“请求允许本应用通信”，由对方在工作台确认。已有普通消息配对不会自动授予 `team.workflow.v1` 通道。
3. 发送方填写标题、任务背景和要求，选择附件后显式发送；目标是对端同应用。
4. 接收方打开本应用，查看待处理正文、来源及附件，再选择“继续处理”或“忽略”。这两个动作均不自动回复。
5. 继续后填写成果，点击“保存成果并在本地完成”。成果文本保存在本机；无需回传即可结束。
6. 需要回传时，在完成记录下准备结果附件，再点击“发送结果给原发送方”。发送方收到回复后自行处理，无强制审批步骤。

普通消息仍在“内网通信”应用中查看和回复；本应用收件只在本应用展示。没有统一任务中心、跨节点任务控制、强制答复或自动 Agent/AI/工具执行。

## 数据、附件与恢复

- `workflow.json` 沿用 schemaVersion 1，兼容已有任务、等待和旧审批记录。新增 result、attachments 和发送尝试标记均为可选字段。
- 正文最多 128 KiB，任务标题最多 1000 字符。更长上下文作为附件；一次最多 20 个附件，总量受通信层限制。
- 收件附件引用公共消息原件，按需流式下载，不将文件字节写进业务 JSON。正文和附件均作为材料，不执行其中的指令。
- 本地完成持久保存成果文本。结果附件在显式回传前上传，上传材料是有时效的暂存引用，不作为本地成果档案。
- 关闭前端后应用可休眠；授权来信使应用保存待处理记录。重启不会自动接受、执行、催办或回传。
- 重试查询原 operationId；一旦尝试发送，即使原记录暂不可确认，也不会自动重发。输入及发送意图保留在本机，按原操作核对后由用户决定后续动作。
- taskId/requestId 是本应用自己的关联字段。waiting 仅表示发件方可匹配后续回复，不表示对方承诺处理。

[CLI 文档](docs/cli.md)给出应用命令及授权边界；旧 `task.approve` 只保留给已有审批记录使用。

## 标准 CLI 入口

本模板声明 manifest.cli。宿主自动在商店显示“支持 CLI”，在顶部应用名称菜单“关于”后增加固定“CLI 文档”；无需自行注册。商店详情可阅读已安装版本，即使应用停用。docs/cli.md 与可选包内 schema 一并交付；主文档须非空、有效 UTF-8、≤256 KiB。阅读只显示包内内容，不启动后台或执行命令，文档与执行均绑定相同包摘要。
