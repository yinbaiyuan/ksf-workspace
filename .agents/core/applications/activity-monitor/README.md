# 活动监视器

用于当前 KSF 实例的运行管理。应用 ID 为 `com.ksf.activity-monitor`，Manifest/SDK v1，要求 Core 0.3.0 及 `runtime-monitor-v1` 宿主能力。应用自身没有后端或受管数据。

## 使用

从 Dock／应用列表打开「活动监视器」，或进入系统设置 → 运行与后台 → 打开活动监视器。

- **任务**：查看应用后台工作、AI 队列、已关联的活跃对话轮次和终端会话。搜索、按类型筛选、排序及多选停止；切换「当前与近期记录」可查看最多 100 条结束记录。
- **应用**：查看运行原因、窗口、保活、任务、PID 与异常重启；按 CPU、内存或名称排序。选中应用后可启动、停止、重启后台或读取日志。
- **资源**：查看主服务及受管进程的 CPU／内存、最近十分钟已采集趋势、日志和诊断。

默认每两秒刷新；暂停刷新不暂停任务，关闭窗口不停止其他应用。监视器关闭后不继续采集资源。曲线只缓存在内存中，不提供跨天历史。

## 停止含义

AI 取消请求与底层执行停止确认分别展示；结果未知时保留待核对状态。对话停止只中断准确的当前轮次。终端停止会结束整个会话及其命令。后台任务需要应用声明支持取消；其他任务可停止所属应用。

应用后台停止与统一 AI／Codex Desktop 独立任务分别管理。普通停止等待在途工作；遇到忙碌提示后可明确选择强制停止。主服务退出后控制台断开连接，重启后点击「重新连接」刷新工作台并重建窗口租约；停止后使用设备上的 KSF 启动入口恢复。重启沿用原端口。

## 统计口径

CPU 一个逻辑核心占满为 100%，多核可超过 100%；内存为 macOS RSS／Windows 工作集合计，可能包含共享内存。按 PID 和启动身份匹配，并对主服务、应用、AI 和终端子进程去重。首次样本、采集中断后的首个样本和采集失败显示未知。共享 Codex Desktop 和远端 API 的资源不分摊给单个任务。

后台任务近期记录保留在本次主服务内存中；AI 记录沿用 AI 服务原件；对话仅列现有已关联活跃轮次；终端来自现存受管会话。数量按类型分别统计，任务、调用与进程不相互替代。

## 构建与检查

在 Core 已准备构建依赖后，使用随包 Node 执行：

```sh
node ../sdk/scripts/ksf-app.mjs check . --json
node ../../runtime/web/node_modules/typescript/bin/tsc --noEmit -p tsconfig.json
node --test tests/*.test.ts
node build.mjs
```

`build.mjs` 生成 `.build/` 与随附应用源中的 `.ksfapp`，源代码、清单和依赖锁一并交付。同版本内容不可覆盖；修改后递增应用版本再构建。

权限：`runtime.read` 允许读取受管运行摘要、日志和诊断；`runtime.manage` 允许执行停止与启动操作。新接口同时核对工作台会话、存活窗口租约和应用声明；现有受信任应用执行环境不因此成为 OS 沙箱。
