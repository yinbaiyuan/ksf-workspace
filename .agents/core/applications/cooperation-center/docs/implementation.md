# 实施与验收

2026-10-30。本目录为开发源码，当前不表示已提交、发布、安装或完成线上升级接管。

统一源在 `runtime/src/applications/registry.js` 解析远程目录、已验证缓存和随包基线，公开 `directories[sourceId]` 的 kind、checkedAt、latestConfirmed。只在实时检查成功时确认最新目录；离线界面明确提示。相同 ID/版本/平台摘要冲突停止安装。来源迁移保留安装身份、启用状态和自定义来源，并备份原安装索引。Core 配套切换保留较新且兼容的独立应用。

KSF合作两种旧 ID 直接映射最终 ID。切换先迁移数据和宿主引用，再启动 Core 默认应用补齐；旧身份仍安装时禁止生成第二套KSF合作。只重写宿主所有者字段，原始消息、签名回执、历史包和业务操作编号不变。

承接声明及其本机处理规则通过KSF合作窗口传入宿主确认的来源。公开目录按字段白名单投影；发任务选择声明，收件按编号和版本匹配，替代按发送实例匹配。默认手动入口常驻。旧规则备份后转为未发布草稿，不扩大授权。Core 保存本机授权及规则版本，AI 请求只能引用它。原生 Codex 执行隔离本实例和认证目录，只写任务目录或用户明确授权的项目；派发前验证目录内写入、目录外读写、认证目录读取及禁网探针。权限变化撤回既有运行，扩大权限不自动拾取旧请求。拟方案阶段会进一步关闭项目工具写入及网络权限。

程序测试入口：应用 `tests/*.test.mjs`；Core `application-registry`、`application-default-source`、`application-store`、`applications`、`application-identities`、`matched-switch`、`ai-execution-grants` 及现有 AI 测试。测试与实机结果分开记录，Windows 未通过原生探针时必须转 B 处理，不能降级成无沙箱执行。

公用源发布前需通过仓库 SDK v1 校验，索引和随包文件摘要一致。正式发布后再回读索引、包与图片，并用真实工作台完成升级；未发布时仅报告“发布内容已准备”。

## 0.4.0 工作流与执行选择

Core 0.3.5 扩展固定的应用工作流服务。处理路径可为人工、API、CLI、独立 Desktop 会话或提供应用自己的新流程；成果统一登记后才进入待提交或自动交付。CLI 不提供人工确认来源。

A 发起应用先保存原运行等待点，再经宿主创建任务；KSF合作本地事务绑定真实应用、固定包摘要、运行、等待点与任务，并持久保存出站事件。B 成果返回后保存成果和回调事件；宿主至少一次通知原应用 workflow.signal，提供应用事务去重与推进原节点。暂停、停用、失效等待点或版本变化保留结果，不另开流程。

SDK workflow-provider 示例使用自己的 SQLite 节点/事件状态，支持独立承接、内部人工复核、并行等待、乱序结果、暂停恢复与终态去重。公开目录不带私有固定值、包绑定或模型配置；旧协议只收到兼容声明。

升级前停应用并备份整个应用数据目录和 runtime 授权目录。SQLite v1 由 VACUUM INTO 保存包含 WAL 的备份，再迁到 v2；messages 标记迁到 schema 3，宿主保留旧标记；授权 schema 2 按摘要备份后迁到 3，声明版本和操作回执保留。回退不能只换旧包：旧包拒读新格式，需恢复同一备份中的数据库、材料、标记、授权与安装状态，并核对未知操作。复制到另一实例不重放队列和执行。

隔离与实机证据分别记录。无真实模型的 Desktop 权限探针只能证明权限边界和配置重启保留；合成适配器测试只能证明 API/CLI 分发与结果处理，不表示实际供应方调用或 Windows 原生边界已验收。日常实例切换和正式源发布须使用既有授权与切换流程。
